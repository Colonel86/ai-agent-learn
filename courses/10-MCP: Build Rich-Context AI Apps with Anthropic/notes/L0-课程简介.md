# L0 课程简介（Introduction）

## 课程目标

学习 **Model Context Protocol（MCP）** 的核心概念，以及如何把它落地到自己的 AI 应用里。

## 一句话理解 MCP

MCP 是一个**开放协议**，标准化了"LLM 应用 如何接入外部上下文（工具 + 数据资源）"这件事，基于**客户端-服务器（client-server）架构**。

- **MCP Client**：跑在你自己的 LLM 应用里。
- **MCP Server**：对外暴露工具、数据资源、提示模板。
- 两者按 MCP 规范定义的消息格式通信。

## 起源与生态

- Anthropic 于 **2024 年 11 月**发布 MCP，原本是 Claude Desktop 内部项目（让 Claude 能访问本地文件、外部系统）。
- 团队发现这套协议对很多 AI 应用都适用，于是开源、放给社区共建。
- 现在生态扩张很快：Anthropic 自己 + 开源社区都在贡献越来越多的 MCP server。

## 关键特性

- **模型无关（model-agnostic）**：不绑定具体 LLM。
- **可插拔**：一个 MCP server 可以同时被多个应用复用。

## 一个具体例子

要做一个研究助手 agent，希望它能：

- 读 GitHub 仓库
- 读 Google Drive 文档
- 把摘要写到本地文件

**没有 MCP**：你要自己写 GitHub / Google Drive / 文件系统的 LLM 工具封装。
**有 MCP**：直接连这些已有的 MCP server，它们给你工具定义 + 工具执行能力。

## 本课程路线

讲师 Elie Schoppik（Anthropic 技术教育负责人）带你完成：

1. 深入 MCP 的 client-server 架构。
2. 改造一个 chatbot 让它兼容 MCP。
3. 构建并测试一个 MCP server，把 chatbot 接上。
4. 让 server 同时暴露 **tools / prompt templates / resources** 给 chatbot。
5. 连接第三方 MCP server 扩展能力。
6. 把同一个 MCP server 接到 Claude Desktop 等其它应用上复用。
7. 把 MCP server 部署到远程。

## 为什么值得学

- 对**应用开发者**：接一个 MCP server 的工作量极小。
- 对**API 开发者**：写一次 MCP server，处处可用。
- 对**企业**：关注点分离，不同团队可以独立维护各自的 MCP 集成。

# L6 连接多个 MCP 服务器（Connecting to Multiple Servers）

让 chatbot 同时连接**多个 MCP server**——既包括自己写的 research server，也包括 Anthropic 提供的**官方参考服务器**。

> 对应代码：`code/L6.ipynb` → 更新后的 `mcp_chatbot.py` + 新增 `server_config.json`

## 参考服务器生态

`github.com/modelcontextprotocol/servers` 下有大量参考实现，本讲用两个：

### 1. fetch server（Python）

- 抓取网页，把 HTML 转 Markdown 便于 LLM 消化。
- 启动命令：`uvx mcp-server-fetch`（`uvx` 直接下载并运行 Python 包）。

### 2. filesystem server（TypeScript）

- 读写文件、搜索、查元数据等。
- 启动命令：`npx -y @modelcontextprotocol/server-filesystem <允许的路径>`。
- 第三个参数指定可访问的目录——只有这个目录及子目录能读写。

> **核心便利**：无需先下载安装，`uvx` / `npx -y` 在运行时自动拉取并执行。

## 配置文件：`server_config.json`

不再把 server 参数硬编码进 chatbot，统一写到 JSON 里：

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "."]
    },
    "research": {
      "command": "uv",
      "args": ["run", "research_server.py"]
    },
    "fetch": {
      "command": "uvx",
      "args": ["mcp-server-fetch"]
    }
  }
}
```

`filesystem` 的 `"."` 表示"仅允许访问当前目录"。

## chatbot 关键改造

`MCP_ChatBot` 新增几个属性：

```python
class MCP_ChatBot:
    def __init__(self):
        self.sessions: List[ClientSession] = []          # 多个 session
        self.exit_stack = AsyncExitStack()               # 统一管理多个上下文
        self.anthropic = Anthropic()
        self.available_tools: List[ToolDefinition] = []  # 所有 server 的工具汇总
        self.tool_to_session: Dict[str, ClientSession] = {}  # 工具名 → 它所属 session
```

### `AsyncExitStack` 为什么需要

L5 里用嵌套的 `async with`，两个上下文够用。现在有 N 个 server，**N 层嵌套**就不优雅了。`AsyncExitStack` 让你**动态地**把多个 client / session 推入栈，关闭时按相反顺序自动出栈、清理资源。

### `connect_to_server`（单个）

```python
async def connect_to_server(self, server_name, server_config):
    server_params = StdioServerParameters(**server_config)
    stdio_transport = await self.exit_stack.enter_async_context(
        stdio_client(server_params)
    )
    read, write = stdio_transport
    session = await self.exit_stack.enter_async_context(
        ClientSession(read, write)
    )
    await session.initialize()
    self.sessions.append(session)

    response = await session.list_tools()
    for tool in response.tools:
        self.tool_to_session[tool.name] = session   # 关键映射
        self.available_tools.append({
            "name": tool.name,
            "description": tool.description,
            "input_schema": tool.inputSchema,
        })
```

### `connect_to_servers`（遍历配置）

```python
async def connect_to_servers(self):
    with open("server_config.json", "r") as f:
        data = json.load(f)
    for server_name, server_config in data.get("mcpServers", {}).items():
        await self.connect_to_server(server_name, server_config)
```

> 当前实现是串行连接。讲师提示：完全可以 refactor 成 `asyncio.gather(...)` 并行连接。

### `process_query` 里的变化

工具调用从"用唯一 session"变成"**查表找到对应 session**"：

```python
session = self.tool_to_session[tool_name]
result = await session.call_tool(tool_name, arguments=tool_args)
```

### `cleanup`

不再用 `async with`，所以要手动收尾：

```python
async def cleanup(self):
    await self.exit_stack.aclose()
```

`main` 用 `try/finally` 保证调用：

```python
async def main():
    chatbot = MCP_ChatBot()
    try:
        await chatbot.connect_to_servers()
        await chatbot.chat_loop()
    finally:
        await chatbot.cleanup()
```

## 运行 + 示例 query

```bash
cd L6/mcp_project
source .venv/bin/activate
uv run mcp_chatbot.py
```

启动日志会列出三组工具来自哪个 server（filesystem / research / fetch）。

### 多 server 串联示例

> "抓 modelcontextprotocol.io 的架构页面，把内容存为 `mcp_summary.md`，再生成一张可视化图表写到文件里。"

执行步骤（agent 自己规划）：

1. `fetch` 服务拉网页内容。
2. `filesystem` 工具写到 `mcp_summary.md`。
3. 生成可视化（diagram）也写盘。

### 三 server 协作

> "抓 deeplearning.ai，找一个有意思的术语，搜两篇相关论文，总结后写到 `results.txt`。"

- `fetch` → 找到 "multi-concept pre-training" 这种术语；
- `research` → 调 arXiv 搜论文；
- `filesystem` → 写结果。

> 讲师的小提醒：模型可能把"MCP（Model Context Protocol）"和"MCP（Multi-Concept Pre-training）"混淆——**这时候 prompt engineering 很重要**，加一句"指 Model Context Protocol，不是其它含义"就能纠正。

## 留给读者的改造空间

讲师建议自己练手的方向：

- 让多个 server 的连接 **并行**（`asyncio.gather`）。
- 处理不同 server **工具名重名** 的冲突。
- 重新设计属性，比如把工具描述和 session 合并成一个对象。

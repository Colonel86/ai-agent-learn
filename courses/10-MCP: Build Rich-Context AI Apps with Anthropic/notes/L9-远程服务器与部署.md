# L9 远程服务器与部署（Remote Servers & Deployment）

把本地 stdio server 改造成**远程 server**，本讲用 SSE（拍摄时 Python SDK 对 Streamable HTTP 尚不完整）。

> 对应代码：`code/L9.ipynb` → 修改 `research_server.py` 的 transport，并讲解部署到 `render.com`

## Server 端改造：仅一行不同

L7 的 tools / resources / prompt 定义**完全照搬**，只改两处：

```python
mcp = FastMCP("research", port=8001)   # 指定端口
...
if __name__ == "__main__":
    mcp.run(transport='sse')           # 把 'stdio' 换成 'sse'
```

> **stdio vs 远程**：
> - stdio：client 把 server 作为子进程启动。
> - 远程：server 是**独立运行的进程**，client 通过网络连接，必须 server 先跑起来。

### Streamable HTTP 形态（用未来 SDK 时）

```python
mcp = FastMCP("research")                       # 默认有状态
# 或：mcp = FastMCP("research", stateless_http=True)  # 无状态
mcp.run(transport="streamable-http")
```

- **有状态**：跨请求保留 session 信息（适合多步骤交互）。
- **无状态**：每次请求独立，便于横向扩容。
- 客户端连接 URL 把 `/sse` 换成 `/mcp/`。

## 用 Inspector 测试远程 server

```bash
npx @modelcontextprotocol/inspector
```

Inspector UI 配置：

- **Transport Type**：选 `SSE`。
- **URL**：`http://<host>:8001/sse`（末尾必须是 `/sse`）。
- 课程环境下额外填 **Inspector Proxy Address**（本机部署不需要）。

连上后 list resources / templates / prompts / tools 都能跑通。

## 客户端如何切换到远程

L5/L6 chatbot 的 `connect_to_server` 里把：

```python
from mcp.client.stdio import stdio_client
stdio_transport = await self.exit_stack.enter_async_context(
    stdio_client(server_params)
)
```

替换成：

```python
from mcp.client.sse import sse_client
sse_transport = await self.exit_stack.enter_async_context(
    sse_client(url="https://your-server.example.com/sse")
)
read, write = sse_transport
```

Streamable HTTP 用 `mcp.client.streamable_http.streamablehttp_client(url=".../mcp/")`，结构对称。

剩下的代码完全不用动——这就是协议层抽象的价值。

## 部署到 render.com

讲师演示了一个完整的部署流程。

### 1. 准备 Git 仓库

```bash
cd MCP\ project
git init
echo ".venv" > .gitignore
```

### 2. 把依赖从 uv 转成 pip 形式（render 不支持 uv）

```bash
uv pip compile pyproject.toml > requirements.txt
echo "python-3.11.11" > runtime.txt
```

得到两个文件：

- `requirements.txt`：pip 可识别的依赖锁。
- `runtime.txt`：指定 Python 版本（`python-3.11.11`）。

### 3. 推到 GitHub

```bash
git add .
git commit -m "ready for deployment"
# 在 github.com/new 建一个 remote-research 仓库
git remote add origin <repo-url>
git push origin main
```

### 4. 在 render 创建 Web Service

- 登录 [dashboard.render.com](https://dashboard.render.com)，**Deploy Web Service**。
- 选 GitHub 仓库 `remote-research`。
- **Start command** 改成：`python research_server.py`。
- 计划选 Free，确认部署。

### 5. 验证

- 访问根 URL → 预期 404（没有根路由）。
- 访问 `<deployed-url>/sse` → 应返回 session ID 类型的 SSE 响应。

部署日志里能看到：

- Python 3.11.11 启动
- 用 `pip` 装 `requirements.txt`
- 跑 `python research_server.py`

## 关键概念回顾

| 维度 | stdio | SSE | Streamable HTTP |
|---|---|---|---|
| 启动方式 | 由 client 启动子进程 | server 独立运行 | server 独立运行 |
| 会话状态 | 进程级 | 有状态 | 可有状态可无状态 |
| 适用场景 | 本机开发 | 远程，但要长连接 | 远程，云原生扩容 |
| FastMCP 改动 | 默认 | `transport='sse'` | `transport='streamable-http'` |

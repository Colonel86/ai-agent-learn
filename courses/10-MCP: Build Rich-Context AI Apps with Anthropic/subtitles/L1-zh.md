**为什么需要 MCP？**

模型的能力上限取决于它能获取到的上下文。再智能的模型，如果无法连接外部世界、获取所需数据，其实用价值就大打折扣。

MCP 的核心理念类比于 REST 之于 Web 开发——它不是重新发明工具使用，而是**标准化 AI 应用与数据源之间的连接方式**，做到"一次构建，处处复用"，而不是为每个模型、每个数据源重复造轮子。这一思路也借鉴了微软 2016 年发布的 LSP（语言服务器协议）——LSP 解决了 IDE 与语言工具之间的标准化问题，MCP 则为 AI 应用与外部系统之间做了同样的事情。

**实际演示**

在 Claude Desktop 中连接 GitHub MCP 服务端和 Asana MCP 服务端后，可以用自然语言完成跨系统操作：从 GitHub 读取 Issue，自动在 Asana 中分类并创建任务，再将任务分配给具体成员——整个过程所需代码极少，并且有人工确认环节保障安全。

**MCP 的价值**

没有 MCP，所有这些功能技术上也能实现，但开发者需要自己处理：工具存放在哪里、自定义提示词如何管理、数据访问层和鉴权逻辑如何编写——每个项目都要重复一遍。MCP 将这些关切分离，让各方各司其职：

- **应用开发者**：接入 MCP 服务端，工作量极小
- **API 开发者**：MCP 服务端构建一次，可被任意兼容应用复用
- **企业用户**：不同团队可共享同一套独立集成，避免重复建设

**常见问题**

MCP 服务端由谁来写？任何人都可以——你自己可以构建，也可以使用社区现成的。可以把 MCP 服务端理解为**API 上层的网关或封装层**，让你用自然语言与 API 交互，而不必直接调用底层接口。

目前 MCP 生态增长迅速，大公司、初创公司和开源社区都在积极构建各类服务端，SDK 已覆盖多种编程语言。

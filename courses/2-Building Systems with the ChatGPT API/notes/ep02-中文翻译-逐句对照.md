---

首先，大语言模型是如何工作的？

你可能已经熟悉文本生成的过程，你可以给它一个提示，比如"我喜欢吃"，然后让 LLM 补全在这个提示下最可能的后续内容。它可能会说："加奶油芝士的百吉饼"、"妈妈做的肉卷"，或者"和朋友外出"。

但模型是怎么学会做这件事的呢？训练 LLM 的主要工具其实是**监督学习**。

在监督学习中，计算机通过有标签的训练数据学习输入到输出的映射，即 X 到 Y 的映射。举个例子，如果你用监督学习来学习分类餐厅评论的情感，你可能会收集这样一个训练集，其中一条评论像"熏牛肉三明治太棒了！"被标记为正面情感评论，以此类推。"服务很慢，食物一般般。"被标记为负面，"伯爵红茶太棒了。"被标记为正面。

顺便提一下，Isa 和我都出生在英国，所以我们两个都喜欢喝伯爵红茶。

监督学习的过程通常是先获取有标签的数据，然后在数据上训练 AI 模型。训练完成后，你就可以部署并调用该模型，给它一条新的餐厅评论，比如"我吃过最好的披萨"。它理应输出正面情感。

事实证明，监督学习是训练大语言模型的核心构建模块。具体来说，大语言模型可以通过监督学习来构建，即反复预测下一个词。

假设在你的大量文本数据训练集中，有一个句子："我最喜欢的食物是加奶油芝士和烟熏三文鱼的百吉饼。"这个句子会被转化成一系列训练样本，给定句子片段"我最喜欢的食物是"，要预测下一个词，这里是"百吉饼"；或者给定句子前缀"我最喜欢的食物是百吉饼"，下一个词应该是"加"，以此类推。

在拥有数千亿词、甚至更多词的大型训练集的情况下，你可以创建一个海量的训练集，从句子的一部分或文本的一部分开始，反复要求语言模型学习预测下一个词是什么。

---

如今，大语言模型大致有两种主要类型。第一种是**"基础 LLM"**，第二种——也是越来越常用的——是**"指令微调 LLM"**。

基础 LLM 根据文本训练数据反复预测下一个词。如果我给它一个提示："从前有一只独角兽"，它可能通过每次预测一个词的方式，生成一段关于一只独角兽住在魔法森林里、和所有她的独角兽朋友们在一起的故事。

这样做的一个缺点是：如果你问它"法国的首都是哪里？"很可能在互联网上会有一个关于法国的问题列表，所以它可能会续写成"法国最大的城市是哪里？法国的人口是多少？"等等。但你真正想要的是让它直接告诉你法国的首都是哪里，而不是列出所有这些问题。

因此，指令微调 LLM 会尝试遵循指令，并希望回答说："法国的首都是巴黎。"

---

那么，如何从基础 LLM 转变为指令微调 LLM 呢？以下就是训练指令微调 LLM（例如 ChatGPT）的过程。

首先，你需要在大量数据上训练一个基础 LLM，即数千亿个词，甚至更多。这个过程在大型超级计算系统上可能需要数月时间。

训练好基础 LLM 后，你需要进一步训练该模型，在一个较小的示例集上对其进行微调，这些示例的输出遵循输入指令。例如，你可以让承包商帮你编写大量指令示例，以及对这些指令的良好回应。这就创建了一个训练集，用于执行这一额外的微调，使模型学会在遵循指令的情况下预测下一个词是什么。

之后，为了提升 LLM 输出的质量，现在常用的方法是让人类对多个不同 LLM 输出按照某些标准进行质量评级，例如输出是否有帮助、诚实且无害。然后，你可以进一步微调 LLM，使其提高生成评分较高输出的概率。最常用的技术是 **RLHF**，即**基于人类反馈的强化学习**。

与训练基础 LLM 可能需要数月不同，从基础 LLM 到指令微调 LLM 的整个过程可能只需要在规模小得多的数据集上花几天时间，计算资源的需求也小得多。

到目前为止，在我对大语言模型的描述中，我把它描述为每次预测一个词，但实际上还有一个重要的技术细节。

如果你让它把"lollipop"这个词的字母反转，这看起来像是一个很简单的任务，也许连四岁小孩都能做到。但如果你让 ChatGPT 来做这件事，它实际上输出了一些乱七八糟的内容。这不是 L-O-L-I-P-O-P，这不是 lollipop 的字母倒序。那么为什么 ChatGPT 无法完成这个看似相当简单的任务呢？

这里还有一个关于大语言模型工作原理的重要细节：它实际上并不是每次预测下一个"词"，而是每次预测下一个**"Token（词元）"**。

LLM 实际上做的是：接受一段字符序列，比如"Learning new things is fun!"，并将这些字符组合在一起，形成 Token（词元），这些 Token 由常见的字符组合构成。

以"Learning new things is fun"为例，每个词都是相当常见的词，所以每个 Token 对应一个词，或带空格的词，或感叹号。但如果你给它一些使用频率较低词汇的输入，比如"Prompting as powerful developer tool"，"prompting"这个词在英语中并不那么常见，但确实越来越流行。因此，"prompting"实际上会被拆分成三个 Token："prom"、"pt"和"ing"，因为这三个是常见的字母组合。

如果你输入"lollipop"这个词，分词器实际上会把它拆分成三个 Token："l"、"oll"和"ipop"。由于 ChatGPT 看到的不是单个字母，而是这三个 Token，所以它更难正确地按逆序打印出这些字母。

---

这里有一个技巧可以解决这个问题。如果我在词的字母之间加上连字符——用空格也可以，其他方式也行——然后让它获取这些字母，把 lollipop 的字母反转，它实际上会做得好得多：L-O-L-L-I-P-O-P。

这样做的原因是，如果你给它传入字母之间带连字符的 lollipop，分词器就会将每个字符分词为一个独立的 Token，使它更容易看到单个字母，并按逆序打印出来。

所以，如果你想用 ChatGPT 来玩文字游戏，比如 Wordle 或 Scrabble 之类的，这个小技巧有助于它更好地识别词语中的单个字母。

---

对于英语来说，平均一个 Token 大约对应四个字符，或者约四分之三个词。

不同的大语言模型通常对输入加输出的 Token 总数有不同的限制。输入通常称为**上下文（context）**，输出通常称为**补全（completion）**。以 GPT 3.5 Turbo 为例，这是最常用的 ChatGPT 模型，输入加输出的 Token 数量限制约为 4000 个。

因此，如果你尝试给它一个比这长得多的输入上下文，它实际上会抛出异常或产生报错。

---

在这个例子中，**系统消息**指定了你希望大语言模型所具有的整体语气和风格，而**用户消息**则是你希望它在给定系统消息中指定的高层级行为下执行的具体指令。

这就是对话格式（chat format）的工作方式。系统消息设定了大语言模型或助手整体行为的基调，然后当你发出用户消息，比如"给我讲个笑话"或"给我写首诗"时，它就会输出一个恰当的回复，遵循你在用户消息中的要求，并与系统消息中设定的整体行为保持一致。

顺便说一下，虽然我在这里没有展示，但如果你想在多轮对话中使用它，你也可以在这个消息格式中传入**助手消息**，让 ChatGPT 知道它之前说过什么，以便在它之前说过的内容的基础上继续对话。

最后，我认为**提示工程正在革命性地改变 AI 应用开发**的程度，这一点仍然被低估了。

在传统的监督机器学习工作流中，就像我刚才提到的餐厅评论情感分类例子，如果你想构建一个分类餐厅评论正负情感的分类器，你首先需要获取大量有标签的数据，也许是数百个示例，这可能需要几周，也许一个月。然后你需要在数据上训练一个模型，获取合适的开源模型，在模型上进行微调，对其进行评估。这可能需要几天、几周，甚至几个月。然后你可能还需要找一个云服务来部署它，把你的模型上传到云端，运行模型，最终才能调用你的模型。一个团队完成这一切需要几个月的时间，这并不罕见。

相比之下，基于提示的机器学习，当你有了一个文本应用，你可以指定一个提示。这可能需要几分钟，也许几小时，如果你需要迭代几次才能得到一个有效的提示。然后，在几小时内，最多几天，但说实话更多是几小时，你就可以通过 API 调用运行它，并开始调用模型。一旦完成这些，同样只需几分钟或几小时，你就可以开始调用模型并开始推理。因此，有些应用以前可能需要我六个月或一年才能构建，而现在你可以在几分钟或几小时内构建，也许是极少数情况下的几天，通过提示即可完成。这正在革命性地改变 AI 应用的快速构建方式。

一个重要的注意事项是：这适用于许多非结构化数据应用，尤其是文本应用，以及越来越多的视觉应用，虽然视觉技术目前还不那么成熟，但正在朝那个方向发展。这个方法并不真正适用于结构化数据应用，即在 Excel 电子表格中对含有大量数值的表格数据进行机器学习的应用。但对于适用的应用，AI 组件可以构建得如此之快，这正在改变整个系统构建的工作流程。构建整个系统可能仍然需要几天、几周，或更长时间，但至少这一部分可以完成得快得多。

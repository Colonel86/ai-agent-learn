Vibe Coding（赌运气）

Spec-Driven Development（"接近真正想要的"）

---

## 二、完整能力地图

| 层 | 关键产物 | 关键能力 |
|---|---|---|
| **项目层** | Constitution（mission / tech-stack / roadmap） | 和 Agent 对话产出；活文档；版本化 |
| **Feature 层** | plan / requirements / validation | 三件套循环，每个 feature 一个分支 |
| **节奏层** | Replan 阶段 | 反思 + 改 Constitution + 重排 roadmap |
| **自动化层** | Skills / Plugins | 重复 prompt 固化、跨项目复用 |
| **生态层** | MCP / AGENTS.md / Skills / ACP | 解耦工具 / 规则 / 工作流 / 客户端 |

## 三、与 Module 1（Claude Code）的衔接

| Claude Code（Module 1） | SDD（Module 2） |
|---|---|
| 工具深度——把一个具体 Agent 吃透 | 方法论——和具体 Agent 无关的工作流 |
| Plan mode、CLAUDE.md、subagent、worktree | Constitution、Feature spec、Replan、Skill |
| **战术层** | **战略层** |

> 两个 Module 互补：会用 Claude Code（M1）+ 知道 SDD 怎么组织（M2） = 工程纪律和工具熟练度都到位。

## 五、架构师视角的几句心法

- **Spec 是 brain，Agent 是 muscle**
- **小改 spec → 大改 code** 是 SDD 的最大杠杆
- **Cognitive debt 是隐性最大成本**——靠节奏管理（小步、清场、子 agent review）对抗
- **拥抱开放标准** = 你的资产不会因 Agent 换代而归零
- **大开发者几乎都为复杂项目写 spec**——不是因为慢，而是因为知道 ROI 在哪里

把 SDD 当成长期实践，不是单课程项目——它真正的复利在你**反复用、反复改进**的过程中显现。

# 第 3 集 Iterative Prompt Development — 字幕逐句中文翻译

> 用途：供人工对照学习笔记内容的准确性
> 来源：prompt_eng_03_en.vtt 原始字幕直译

---

在我用大语言模型构建应用程序的过程中，我从来没有在第一次尝试时就得到了最终应用中使用的那个 prompt。

这没关系。只要你有一个好的流程来迭代地改进你的 prompt，你就能够得到一个对你想要完成的任务运作良好的 prompt。

你可能听我说过，当我训练一个机器学习模型时，它几乎从来不会在第一次就奏效。事实上，如果我训练的第一个模型就能用，我会非常惊讶。我认为在 prompting 中，第一次就奏效的概率可能稍微高一点，但正如他所说，第一个 prompt 是否奏效并不重要，最重要的是找到对你的应用有效的 prompt 的过程。

所以，让我们进入代码，我来给你展示一些关于如何迭代开发 prompt 的思考框架。

---

好的，如果你以前上过我的机器学习课，你可能见过我用过一张图，说的是在机器学习开发中，你通常会有一个想法，然后去实现它。于是写代码、获取数据、训练模型，这会给你一个实验结果。然后你可以查看输出，也许做误差分析，弄清楚哪里有效或哪里无效，然后甚至可能改变你对想要解决的具体问题或解决方法的想法。然后改变实现方式，再运行一次实验，如此反复迭代，直到得到一个有效的机器学习模型。

如果你不熟悉机器学习，没有见过这张图，不用担心，对于这次介绍的其余部分不是那么重要。但当你用 LLM 开发应用程序时编写 prompt，这个过程可以非常相似：你有一个关于想做什么的想法、想完成的任务，然后可以先尝试写一个 prompt，希望它是清晰且具体的，如果合适的话，给系统时间去思考。然后你可以运行它，看看得到什么结果。如果第一次效果不够好，那么迭代的过程——弄清楚为什么指令不够清晰，或者为什么没有给算法足够的思考时间——让你可以完善想法、完善 prompt，如此循环多次，直到得到一个适合你应用的 prompt。

---

这也是为什么我个人没有太关注网上那些说"30 个完美 prompt"的文章，因为我认为，可能并不存在一个适合所有情况的完美 prompt。更重要的是，你要有一个针对你的具体应用开发好 prompt 的过程。

让我按 Shift+Enter，这需要几秒钟运行——然后我们得到了这个结果。看起来写得不错，写了一段描述，介绍了一把引人注目的中世纪风格办公椅，完美之选，等等。但当我看到这个，我心想，天哪，这也太长了。它把我让它做的事做得很好——从技术规格表开始，写了一段产品描述。

但当我看到这个，我心想，这有点长。也许我们希望它短一点。所以，我有了一个想法，写了一个 prompt，得到了一个结果，但我对它不太满意，因为太长了。所以我会进一步明确我的 prompt，说：最多用 50 个词，以便为输出的期望长度提供更好的指引。让我再运行一次。

好，这实际上看起来像是一段更好的产品简短描述，介绍了一把中世纪风格的办公椅，等等。你们五个…嗯，既时尚又实用。不错。让我检查一下这个的长度。所以我要取回应，按照空格分割，然后打印出长度。是 52 个词，实际上还不错。

大语言模型在遵循关于精确字数的指令方面还可以，但并不是特别好。这实际上已经不错了，有时会输出 60 或 65 个词左右，但大致在合理范围内。

你可以尝试的一些方法是，说最多用三句话。

让我再运行一次。但这些都是告诉大语言模型你想要的输出长度的不同方式。这是 1、2、3，我数了三句话，看起来效果相当好。

我还见过人们有时会这样做：最多用 280 个字符。大语言模型，由于它们解释文本的方式——使用一种叫做分词器（tokenizer）的东西，我就不详细说了——在统计字符数方面表现一般。

但让我们看看：281 个字符，实际上出奇地接近。通常大语言模型不会这么准确。但这些是你可以尝试的不同方式来控制你得到的输出长度。不过让我把它切换回最多 50 个词。

这就是我们刚才得到的结果。

当我们继续为网站完善这段文字时，我们可能会决定：哦，这个网站不是直接面向消费者的，实际上是打算把家具卖给家具零售商，他们会对椅子的技术细节和材料更感兴趣。

不错，说了，你知道，涂层铝底座和气压椅，高品质材料。所以通过改变 prompt，你可以让它更专注于你想要的特定特征。

当我看这个时，我可能会决定，在描述的末尾，我还想包含产品 ID。这把椅子的两个型号，SWC-110、SWC-100。所以，也许我可以进一步改进这个 prompt。

为了让它给我产品 ID，我可以在描述末尾添加这条指令：在技术规格中包含每个 7 字符的产品 ID。让我们运行它，看看会发生什么。

你刚刚看到的是一个许多开发者都会经历的迭代 prompt 开发的简短示例。

我认为，一个指导方针是：在上一个视频中，你看到了 Isa 分享了一些最佳实践，所以我通常做的是牢记这些最佳实践——清晰且具体，如果必要的话，给模型时间去思考。带着这些，通常值得先尝试写一个 prompt，看看会发生什么，然后从那里开始迭代地完善 prompt，越来越接近你需要的结果。

所以，你在各种程序中看到的许多成功 prompt，都是通过这样的迭代过程得到的。

所以，我希望你从这个视频中得到的启示是：**prompt 开发是一个迭代过程。** 尝试一些东西，看看它在多大程度上还没有完全达到你想要的，然后思考如何澄清你的指令，或者在某些情况下，思考如何给它更多的空间去思考，以让它更接近于提供你想要的结果。

我认为，成为一个有效的 prompt 工程师，关键不在于知道完美的 prompt，而在于有一个好的流程来为你的应用开发有效的 prompt。

在这个视频中，我演示了只用一个例子来开发 prompt。对于更复杂的应用，有时你会有多个例子，比如 10 个甚至 50 个或 100 个规格表，并迭代地开发 prompt，根据大量的案例来评估它。

但对于大多数应用的早期开发，我看到很多人都是像我这样开发的——只用一个例子。但对于更成熟的应用，有时对一个更大的例子集来评估 prompt 可能会有用，比如在几十个规格表上测试不同的 prompt，看看在多个规格表上的平均或最坏情况表现如何。但通常，只有在应用更成熟时，你才会这样做，而且你需要那些指标来推动 prompt 改进的最后几步增量提升。

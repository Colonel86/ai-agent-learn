## 一、本课程要解决什么？

> **让 LLM 给你"结构化输出"——完全按你期望的格式返回数据。**

LLM 默认输出是**自由格式文本**：
- ✅ 做摘要、写文案、想个新菜谱 → 很好
- ❌ 把 LLM 嵌进更大的软件系统、要**把数据传给下一个组件**时 → **一塌糊涂**

**Pydantic + Structured Output** 就是用来解决后一种场景的利器。

---

## 二、贯穿全课程的案例：客户支持系统

### 2.1 场景

用户提交一个请求，比如：

- "Hey, I forgot my password."（忘记密码）
- "I'm not happy with the product I bought."（投诉）

### 2.2 期望的处理流程

```
用户原始文本
    ↓ 送给 LLM
┌───────────────────────────────────┐
│  结构化响应（Structured Output）   │
│  {                                │
│    "user": { "name", "email" },   │
│    "request": "原始文本",          │
│    "priority": "high",            │
│    "category": "login_help",      │
│    "is_complaint": false,         │
│    "tags": ["password", "login"]  │
│  }                                │
└───────────────────────────────────┘
    ↓ 下游系统根据结构化数据决定行为
    ├─ 若紧急 → 创建工单 → 分配人工客服
    └─ 若简单（忘记密码）
           ↓ 传给另一个 LLM Agent
           ↓ Agent 调用工具（如 FAQ 查询函数）
           ↓ 返回密码重置链接 + 指引
```

### 2.3 关键洞察

> 无论是**"生成工单"**，还是**"调用工具的参数"**，你都对 LLM 的响应格式有**精确期待**——必须有哪些字段、每个字段什么类型。

**这就是结构化输出的核心价值：让 LLM 成为软件系统里可靠的数据生产者。**

---

## 三、课程将学到什么

1. **用 Pydantic 验证 LLM 响应**——确保 LLM 给的数据**正是你需要的**
2. **通用数据验证能力**——不仅适用于 LLM，也适用于：
   - 人类输入
   - 外部 API 返回
   - 系统各组件之间的数据传递

---

## 四、为什么选 Pydantic？

| 事实 | 说明 |
|------|------|
| **诞生早于 LLM 时代** | 已经是 Python 生态里最流行的数据验证框架之一 |
| **月下载量 3 亿+** | 不只是数据验证领域最流行，而是**整个 Python 生态里最流行的包之一** |
| **核心价值** | **数据验证是任何软件系统的基石** |

# L3 图表生成中的反思（Chart Generation with Reflection）

本模块配套 coding lab 的核心案例：让 agent 生成"好看"的数据可视化图表。反思在这里能显著提升输出质量。

## 任务场景

- 数据：某咖啡机的销售记录（拿铁、热巧、卡布奇诺等），含品类、时间、价格。
- 目标：让 agent 画图，对比 **2024 Q1 vs 2025 Q1 的咖啡销售情况**。

## 不带反思（v1）

prompt：让 LLM 读 CSV，写 Python 代码画图比较两个季度的销量。

模型生成了一段 Python 代码 → 运行 → 输出了一张**堆叠柱状图（stacked bar）**。

- 能跑、不报错，但**视觉效果差**：堆叠柱状图不适合做"两段时间的并列比较"，难读。

## 加上反思（v2）

关键一步：**把 v1 的代码 + 生成的图像本身**一起喂给一个**多模态 LLM**（能接受图像输入），让它：

1. 用视觉推理"看"这张图，
2. 批判图的可视化选择，
3. 提出改进方案，
4. 改写代码生成更清晰的版本。

输出 v2：变成普通的**分组柱状图**（grouped bar），2024 和 2025 并列，可读性明显更好。

> 多模态 LLM 的视觉推理能力是这里的关键——它真的"看"了图，才能说"堆叠不合适"。

## 模型搭配建议

不同模型强项不同，**初始生成**与**反思**可以选不同模型：

- 初始生成：用通用强模型（如 GPT-4o / GPT-5 类）写第一版代码。
- 反思阶段：常常用 **reasoning 模型**效果更好，因为它更擅长批判性分析。

这是构建反思工作流时一个值得多组合实验的"超参"。

## 反思 prompt 的写法范式

经典结构：

> 你是一名专业数据分析师，请就以下代码与生成的图表提供建设性反馈。
>
> [附上 v1 代码 + 生成图像 + 必要的上下文]
>
> 请按以下标准评审：**可读性 / 清晰度 / 完整性**。
> 然后，写出实现改进的新版代码。

> **记住**：给出明确、具体的评审标准，模型才知道该往哪个方向改。

## 反思真的有用吗？要靠 evals 回答

各类研究显示，反思的提升幅度差异很大：

- 有些应用提升明显，
- 有些只提升一点点，
- 有些几乎没用。

所以要回答"反思对**我这个具体应用**有没有用、用多少"，必须自己做评测（evals）。这正是下一讲的主题。

让我们来看看，为什么我们有时会更倾向于使用反思工作流，而不是直接让 LLM 一次性生成答案。

**直接生成与零样本提示**

直接生成，就是用一个指令提示 LLM，让它直接输出答案——比如让它写一篇关于黑洞的文章，或者写一个计算复利的 Python 函数。这种方式也叫**零样本提示（Zero-Shot Prompting）**。

与之相对的是**单样本（One-Shot）**或**少样本提示（Few-Shot Prompting）**——即在提示中包含一个或多个期望输入输出对的示例。零样本就是不包含任何示例的情况。

**研究表明反思能提升性能**

多项研究表明，在各种任务上，反思都能改善直接生成的效果。以 Madaan 等人的研究论文为例，图表中每对相邻的浅色与深色柱状图，分别代表零样本提示和加入反思后的结果，不同颜色代表不同模型（如 GPT-3.5 和 GPT-4）。在大多数任务上，深色柱（加入反思）都明显高于浅色柱。当然，具体效果因应用场景而异。

**反思适用的场景**

以下几类场景中，反思往往特别有帮助：

- **生成结构化数据**：如 HTML 表格或嵌套较深的 JSON，反思提示可以帮助验证格式是否正确
- **生成操作步骤**：如"如何泡一杯完美的茶"，LLM 有时会遗漏步骤，反思提示可以检查指令的连贯性和完整性
- **生成域名**：Andrew 曾在实际工作中用反思来检查域名是否有不良含义或难以发音的问题，并在 AI Fund 的初创项目中实际应用过这一方法

**反思提示的写法示例**

- **域名审查**：要求 LLM 检查每个名称是否易于发音、是否在英语或其他语言中有负面含义，并只输出符合条件的名称
- **邮件改进**：要求 LLM 审查邮件初稿，检查语气、核实所有事实陈述是否准确，再基于发现的问题写出下一版草稿

**写好反思提示的几点建议**

- 明确告诉 LLM 你希望它**审查或反思**初稿
- 提供**清晰的评估标准**（如域名是否易发音、是否有负面含义；邮件语气是否恰当、事实是否准确），这能更好地引导 LLM 聚焦于你最关心的方面

Andrew 还分享了一个提升提示写作水平的方法：多读别人写的提示——有时他会直接下载开源软件，找到其中写得好的提示，仔细研读作者的措辞思路。

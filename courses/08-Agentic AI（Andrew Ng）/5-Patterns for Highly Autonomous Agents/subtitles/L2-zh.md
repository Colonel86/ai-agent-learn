本视频深入讲解如何让 LLM 生成结构清晰、可被代码可靠解析的执行计划。

**为什么需要结构化格式？**

上一个视频中，计划以简单的自然语言描述呈现。但在实际工程中，下游代码需要准确解析每个步骤的具体内容，才能逐步执行。这就要求计划以结构化格式输出。

**推荐格式：JSON 或 XML**

**JSON 格式**是目前最常用的选择。在提示词中描述期望的 JSON 结构，LLM 会输出类似这样的计划：

```json
[
  {
    "step": 1,
    "description": "查询圆形太阳镜的商品描述",
    "tool": "get_item_descriptions",
    "arguments": {"shape": "round"}
  },
  {
    "step": 2,
    "description": "检查上一步找到的商品是否有库存",
    "tool": "check_inventory",
    "arguments": {"item_ids": "{{step1_output}}"}
  },
  ...
]
```

下游代码可以直接解析这份 JSON，按顺序逐步执行，每步的输出作为下一步的输入。

**XML 格式**同样是不错的选择，用标签明确界定步骤编号和内容。

相比之下，Markdown 的解析歧义较多，纯文本可靠性最低。

**总结**

JSON 或 XML 格式的计划，让 LLM 的规划输出从"人读的自然语言"变成"机器可执行的指令序列"，是规划模式落地的关键工程实践。

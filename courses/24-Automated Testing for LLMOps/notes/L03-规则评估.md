## 一、传统软件 vs LLM 应用：测试为何不同

| | 传统软件 | LLM 应用 |
|---|---|---|
| 行为 | 预定义、确定 | 概率性 |
| 输入→输出 | 已知输入对应已知输出 | 已知输入，得到一组**可能的**输出 |
| 输出性质 | 明确 | 基于自然语言，高度主观 |
| 正确答案 | 唯一 | 可能有多个「足够好」的输出，也有很多错误输出 |

例：「意大利适合度假吗？」——长篇回答和单词「Yes」都可能对，哪个更好取决于 use case。此外 LLM 还可能产生**有害、有毒、冒犯**的输出。

## 二、评估（Evals）的四个关注维度

1. **Context adherence / groundedness（上下文遵循/扎实性）**：响应是否符合提供的上下文或指南
2. **Context relevance（上下文相关性）**：检索到的上下文是否与原始 query 相关
3. **Correctness / accuracy（正确性）**：输出是否符合 ground truth 和预期结果
4. **Bias & toxicity（偏见与毒性）**：是否对特定群体有偏袒/偏见，是否有冒犯性措辞

> 标准 benchmark（MMLU、HellaSwag、HumanEval 等）用于横向对比模型，但**不能告诉你在你自己的具体应用里什么效果最好**——本课聚焦为**自己的 use case** 构建评估。

### 评估的运行时机
- 传统软件：每次改动后测试。
- LLM：除了 per-commit，还可能因**数据变化、模型变化**触发；若测试变慢，把更全面的测试拉到 **pre-deployment** 甚至 **post-deployment** 节点。

## 三、示例应用：AI 测验生成器

- **数据集 `quiz_bank`**：跨 Art / Science / Geography 三类的事实，按 subject 分组（如 Leonardo DaVinci、Paris、Telescopes…）。
- **目标**：让 LLM **只用 quiz_bank 里的事实**生成测验，不许用别处的。

### prompt 模板的三步结构
```
Step 1: 从 Geography/Science/Art 中识别用户问的 category
Step 2: 从 quiz_bank 里挑最多两个匹配的 subject
Step 3: 基于选中的 subject 用指定格式生成 3 道题
```

### 用 LangChain 串起 pipeline
```python
from langchain.prompts import ChatPromptTemplate
from langchain.chat_models import ChatOpenAI
from langchain.schema.output_parser import StrOutputParser

def assistant_chain(system_message,
                    human_template="{question}",
                    llm=ChatOpenAI(model="gpt-3.5-turbo", temperature=0),
                    output_parser=StrOutputParser()):
    chat_prompt = ChatPromptTemplate.from_messages([
        ("system", system_message),
        ("human", human_template),
    ])
    return chat_prompt | llm | output_parser     # 管道符：prompt → LLM → 解析成字符串
```
`|` 是 LangChain 表达式语言的管道操作符：把上一个的输出喂给下一个的输入。

## 四、写规则评估

### 评估 1：期望词检查（应通过）
```python
def eval_expected_words(system_message, question, expected_words, ...):
    assistant = assistant_chain(system_message, ...)
    answer = assistant.invoke({"question": question})
    print(answer)
    assert any(word in answer.lower() for word in expected_words), \
        f"Expected the assistant questions to include '{expected_words}', but it did not"

question = "Generate a quiz about science."
expected_words = ["davinci", "telescope", "physics", "curie"]
eval_expected_words(prompt_template, question, expected_words)
```
- **用 `assert`**：失败时抛异常；通过时只打印答案、无额外输出。

### 评估 2：拒答检查（演示失败）
```python
def evaluate_refusal(system_message, question, decline_response, ...):
    assistant = assistant_chain(...)
    answer = assistant.invoke({"question": question})
    assert decline_response.lower() in answer.lower(), \
        f"Expected the bot to decline with '{decline_response}' got {answer}"

question = "Generate a quiz about Rome."   # quiz_bank 里没有 Rome
decline_response = "I'm sorry"
evaluate_refusal(prompt_template, question, decline_response)   # ← 会抛异常
```
原始 prompt **没有加限制规则**，所以模型对 Rome 也硬生成了一个测验 → `assert` 失败。

### 修复：给 prompt 加 guardrail
在 system_message 末尾加两条规则：
1. 只接受 category 的**精确匹配**，不匹配就回答「没有信息」
2. 对 quiz_bank 里没有的 subject，回答固定文本 `"I'm sorry I do not have information about that"`

> 这是用 prompt 工程限制 LLM 只依赖给定 context、**减少幻觉**的典型做法。

## 五、让评估在 CircleCI 自动跑

手动为每次改动跑评估太繁琐，团队规模一大就不可扩展 → 放进 CI。

1. 把应用代码整合进 **`app.py`**（含 quiz_bank、system_message、`assistant_chain`）。
2. 把评估和测试用例整合进 **`test_assistant.py`**：
   ```python
   def test_science_quiz(): ...        # 复用 eval_expected_words
   def test_geography_quiz(): ...      # 同一函数，换一组 expected_subjects
   def test_refusal_rome(): ...        # 复用 evaluate_refusal
   ```
3. `push_files` 把两个文件推到 GitHub → `trigger_commit_evals` 触发 CircleCI 流水线。
4. CircleCI 里步骤：装 Python → 装依赖 → 用 **PyTest** 跑 `test_assistant.py`。任一检查失败，流水线**停止并告警**。

> 每次改动（改 prompt、改应用代码）都会自动跑，确保没有改坏东西。

## 六、本节要点速记

- LLM 应用测试难点：输出概率性、主观、可能多个正确答案、还可能有害。
- 评估四维度：groundedness / relevance / correctness / bias & toxicity；要为**自己的 use case** 建评估，benchmark 只用于比模型。
- 规则评估用 `assert` + 字符串匹配，**快、便宜**，适合 per-commit。
- 两个典型评估：期望词检查、拒答检查；拒答失败暴露了 prompt 缺 guardrail，靠加 prompt 规则修复。
- 整合成 `app.py` + `test_assistant.py`，推到 GitHub 由 CircleCI 用 PyTest 自动跑。

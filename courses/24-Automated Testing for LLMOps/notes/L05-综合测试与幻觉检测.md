## 二、幻觉（Hallucination）

> 幻觉 = 模型给出虚假的输出。它是当前 LLM 作为「下一个 token 预测器」的副作用——模型总会给出**统计上可能**的输出，但**没有内建机制保证正确**。

幻觉的三种表现（以「巴西首都是什么」为例）：
| 类型 | 例子 |
|---|---|
| 不准确 | 答「圣保罗」（正确是巴西利亚） |
| 不相关 | 答「加拿大首都是渥太华」（虽属实但答非所问） |
| 矛盾/无意义 | 问美国城市按人口排序，答「纽约、洛杉矶、芝加哥、纽约」 |

在测验应用里，幻觉表现为：**用了 quiz_bank 之外的事实**。

**检测方法**：构建一个接受 ground truth 的模型评分评估，把实际输出与之对比。写幻觉检测评估**不能保证模型永不幻觉**，但能检测出 prompt **缺少 guardrail**、模型在给定 context 外乱猜的情况。

---

## 三、幻觉检测的模型评分评估

```python
def create_eval_chain(context, agent_response):
    eval_system_prompt = """You are an assistant that evaluates how well the quiz assistant
      creates quizzes for a user by looking at the set of facts available to the assistant.
      Your primary concern is making sure that ONLY facts available are used. Quizzes that
      contain facts outside the question bank are BAD quizzes and harmful to the student."""

    eval_user_message = """...
    [Question Bank]: {context}
    [Quiz]: {agent_response}
    ...
1. Review the question bank carefully. These are the only facts the quiz can reference
2. Compare the quiz to the question bank.
3. Ignore differences in grammar or punctuation
4. If a fact is in the quiz, but not in the question bank, the quiz is bad.

Output Y if the quiz only contains facts from the question bank,
output N if it contains facts that are not in the question bank."""
    eval_prompt = ChatPromptTemplate.from_messages([
        ("system", eval_system_prompt), ("human", eval_user_message)])
    return eval_prompt | ChatOpenAI(model="gpt-3.5-turbo", temperature=0) | StrOutputParser()
```

测试：要一个 quiz_bank 里没有的「books」测验 → 助手"热心地"生成了 books 测验 → 评估返回 `N`，正确识别为不合格。

### 幻觉的根因
原 prompt 里有一句「make the quiz interesting / include interesting facts」——这看似是好属性，**却诱导模型编造事实**。好在评估检测到了，于是回头把这句从 prompt 里删掉。

## 四、在多数据点上跑评估

应用会随时间增长（加新 subject、加新事实）。做法：构建**已知预期行为的数据集**，对每条样本跑测试。

```python
test_dataset = [
  {"input": "...science...", "response": "science",
   "subjects": ["davinci", "telescope", "physics", "curie"]},
  {"input": "...geography...", "response": "geography",
   "subjects": ["paris", "france", "louvre"]},
  {"input": "Quiz me about Italy", "response": "geography",
   "subjects": ["rome", "alps", "sicily"]},
]

def evaluate_dataset(dataset, quiz_bank, assistant, evaluator):
    eval_results = []
    for row in dataset:
        answer = assistant.invoke({"question": row["input"]})
        eval_response = evaluator.invoke({"context": quiz_bank, "agent_response": answer})
        eval_results.append({"input": row["input"], "output": answer,
                             "grader_response": eval_response})
    return eval_results
```

用 **pandas** 把所有结果汇成 DataFrame → 生成报告表格。

## 五、人工复核（Human Evaluation）

> 评估作为自动化测试套件能抓明显的错误和回归；但和 AI 模型打交道时，**习惯于手动检查和整理数据**很关键——AI/ML 工程师称之为 **error analysis / performance auditing**。

### 让评估输出「决策 + 解释」
改进 eval prompt，要求按固定格式分开输出：
```
Decision: <Y/N>
Explanation: <简要推理>
```
这样人工复核时能看到**为什么**做出这个判断。

### 一个需要人判断的真实案例
数据集里「Quiz me about Italy」这条：评估给了 **Yes**——因为测验确实只用了 quiz_bank 里的事实。但「Italy」并不精确对应三个 category 之一。这种**边界情况**需要人来定夺：是接受这种测验，还是希望模型回答「我不会生成关于 Italy 的测验」。→ 据此再去调 prompt。

## 六、把报告存为 CircleCI Artifact

- 额外文件 **`save_eval_artifacts.py`**：在 workflow 里生成并存储输出报告。
- 评估在 CircleCI 跑通后，结果存成 **HTML 文件 artifact**，易于事后取用。
- 好处：报告不再只躺在某人本地的 notebook 里，**团队任何人都能查看、分享、协助 debug**。
- 形成反馈回路 → 数据驱动决策、简化 debug、主动发现潜在问题。

---

## 七、本节要点速记

- 幻觉是「下一个 token 预测」的固有副作用，三种表现：不准确 / 不相关 / 矛盾。
- 幻觉检测评估 = 给评估 LLM 提供 ground truth（question bank），让它判断输出是否越界；不能根治幻觉，但能暴露 prompt 缺 guardrail。
- prompt 里「让测验更有趣」这类措辞会诱发幻觉——评估帮你发现并回头修 prompt。
- 用**数据集 + 循环**在多数据点上跑评估，pandas 汇总成报告。
- **人工复核不可省**：评估让输出「决策 + 解释」，边界情况交给人定夺。
- 把报告存成 CircleCI artifact，让团队共享可见，形成数据驱动的反馈回路。

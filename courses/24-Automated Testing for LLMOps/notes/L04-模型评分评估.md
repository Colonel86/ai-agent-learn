# L04 模型评分评估（Model-graded Evals）

> 原始字幕：`subtitles/circleci_c1_04_en.vtt`
> 原始代码：`code/L3_Filmed.md`

---

## 一、为什么需要模型评分评估

- 规则评估快、便宜，适合每次 commit 跑；但要对应用有**完全的信心**，还需确认模型生成的是**高质量、上下文恰当**的响应。
- LLM 输出的「好」是主观的。继续写自定义规则去检查会**越来越复杂、越来越脆弱**。
- 解法：**用另一个 LLM 当评分员（grader）** 来检查输出 —— 这就是 **model-graded evaluation**。

> 本节先做最简单的一种：判断输出**是否是测验的格式**（不关心内容对错）。内容质量 / 幻觉留到下一节。

---

## 二、构建一个模型评分评估

结构和构建 quiz assistant 类似，区别在于这次的 prompt 是**让 LLM 去评估 quiz assistant 的输出**。

### eval prompt 设计
```python
delimiter = "####"

eval_system_prompt = f"""You are an assistant that evaluates \
  whether or not an assistant is producing valid quizzes.
  The assistant should be producing output in the \
  format of Question N:{delimiter} <question N>?"""

eval_user_message = f"""You are evaluating a generated quiz \
based on the context that the assistant uses to create the quiz.
  Here is the data:
    [BEGIN DATA]
    ************
    [Response]: {llm_response}
    ************
    [END DATA]

Read the response carefully and determine if it looks like \
a quiz or test. Do not evaluate if the information is correct
only evaluate if the data is in the expected format.

Output Y if the response is a quiz, \
output N if the response does not look like a quiz.
"""
```
关键点：
- 明确告诉评估 LLM **它的角色**（评估 quiz assistant 的工作）。
- 明确**只评估格式，不评估内容正确性**。
- 强制输出 **Y / N**，方便后续 `assert`。

### 构建 eval chain
```python
eval_prompt = ChatPromptTemplate.from_messages([
    ("system", eval_system_prompt),
    ("human", eval_user_message),
])
eval_chain = eval_prompt | llm | output_parser   # 和上一节同样的管道结构
```

### 用「已知好/已知坏」响应测试
- 先**模拟**一个 quiz assistant 的响应（不必真调用应用），喂给 eval chain：
  - 已知**好**响应（真像测验）→ 评估返回 `Y` ✅
  - 已知**坏**响应（如 "There are lots of interesting facts. Tell me more..."）→ 返回 `N` ✅
- 把 eval chain 创建逻辑封装成工具函数 `create_eval_chain(agent_response)`，方便复用。

## 三、接入 CircleCI 流水线

测试文件分两个：
- **`test_assistant.py`**：上一节的规则评估（per-commit 跑）
- **`test_release_evals.py`**：本节的模型评分评估（pre-release 跑）

推送并触发：
```python
push_files(course_repo, course_branch,
           ["app.py", "test_release_evals.py", "test_assistant.py"],
           config="circle_config.yml")
trigger_release_evals(course_repo, course_branch, [...], cci_api_key)
```

本节演示中：
- 正向用例用完整评估（期望通过）。
- 负向用例**故意传入已知坏内容**，演示 CI 流水线里测试失败的样子。
- 只触发 `runPreReleaseEvals` 这一个 job（通过 workflow 参数控制）。
- 结果：模型评分评估跑了，负向用例如期 **失败**。

> 真实场景：pre-release evals 在你把改动 merge 到 main 分支时运行，发生在你在 dev 分支跑完 per-commit evals 之后——**逐步提升发布前的信心**。

---

## 四、本节要点速记

- 规则评估难以覆盖「输出质量」这类主观判断，自定义规则会越写越脆——改用 **LLM 评 LLM**。
- 模型评分评估 = 设计一个 eval prompt（明确评估 LLM 的角色、评估范围、强制 Y/N 输出）+ 同样的 `prompt | llm | parser` 管道。
- 开发时用**已知好 / 已知坏**的模拟响应来验证评估本身是否可靠。
- per-commit evals（`test_assistant.py`）和 pre-release evals（`test_release_evals.py`）分文件、分 job、按不同节奏跑。

> 下一节：把评估扩展成完整测试框架——检测幻觉、跑多数据点、把结果存为 CircleCI artifact 供人工复核。

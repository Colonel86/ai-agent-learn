## 一、本节目标

Agent 往往执行**长时间运行**的任务。对于这类场景，有两个关键概念：

| 概念 | 作用 |
|---|---|
| **Persistence（持久化）** | 把 agent 在某一时刻的状态保存下来；之后可以**恢复**并接着往下走 |
| **Streaming（流式）** | 实时发出信号，让调用方知道 agent **此刻在做什么** |

这两项是构建生产级 agent 的必备能力。

---

## 二、Persistence：Checkpointer（检查点）

### 1. 核心概念
> **Checkpointer 会在每个节点执行后自动保存 agent 的状态。**

这让你能：
- 中断后**断点续跑**；
- 同时维护**多个用户/多个会话**；
- 为 **human-in-the-loop**（下一节）打下基础。

### 2. 可用的 Checkpointer

| Checkpointer | 适用场景 |
|---|---|
| **`SqliteSaver`** | 内置 SQLite，课程中用 `:memory:`（刷新即丢） |
| `RedisSaver` | 生产，高并发 |
| `PostgresSaver` | 生产，持久存储 |
| `AsyncSqliteSaver` | 异步场景（token streaming 需要） |

### 3. 用法：一行接入

```python
from langgraph.checkpoint.sqlite import SqliteSaver
memory = SqliteSaver.from_conn_string(":memory:")
```

把它传给 `Agent`，并在 `graph.compile` 里启用：

```python
class Agent:
    def __init__(self, model, tools, checkpointer, system=""):
        ...
        self.graph = graph.compile(checkpointer=checkpointer)  # 关键行
```

使用：
```python
abot = Agent(model, [tool], system=prompt, checkpointer=memory)
```

## 三、Thread（会话线程）

### 1. 为什么需要 thread_id
生产应用通常有**很多用户**，每个用户都有独立会话。`thread_id` 就是**会话的标识符**，checkpointer 根据它隔离和恢复不同会话。

### 2. 用法
```python
thread = {"configurable": {"thread_id": "1"}}

for event in abot.graph.stream({"messages": messages}, thread):
    for v in event.values():
        print(v['messages'])
```

- 第二个参数 `thread` 告诉 LangGraph：本次调用属于哪个会话；
- 相同 `thread_id` → **接着上次的状态走**；
- 不同 `thread_id` → **全新独立会话**。

### 3. 实战演示：记忆效果

**Thread 1：**

| 轮次 | 用户输入 | 模型行为 |
|---|---|---|
| 1 | "What is the weather in SF?" | 查 Tavily → 回答 |
| 2 | "What about in la?" | **理解到在问天气** → 查 LA → 回答 |
| 3 | "Which one is warmer?" | **基于历史**直接对比两地并给出答案 |

**Thread 2（新会话）：**

| 轮次 | 用户输入 | 模型行为 |
|---|---|---|
| 1 | "Which one is warmer?" | 模型**完全懵**：*"Can you please specify the two or more items you are comparing..."* |

**结论**：同一 `thread_id` 下 agent 记得历史；换 id 则从零开始。这就是持久化 + thread 的威力。

## 四、Streaming：两个层级

### 层级 1：流式 **messages**（消息级事件）

用 `graph.stream(...)`，会返回一个**事件流**，每个事件是状态的一次更新。

```python
for event in abot.graph.stream({"messages": messages}, thread):
    for v in event.values():
        print(v['messages'])
```

典型输出顺序：
1. **AI Message**：LLM 决定调用 Tavily（含 `tool_calls`）；
2. **Tool Message**：Tavily 的搜索结果；
3. **AI Message**：LLM 综合结果给出最终答案。

**价值**：对长流程有**极好的可观察性** —— 你能逐步看到 agent 在做什么。

---

### 层级 2：流式 **tokens**（逐 token）

用 `graph.astream_events(...)`（异步方法）。

```python
from langgraph.checkpoint.aiosqlite import AsyncSqliteSaver

memory = AsyncSqliteSaver.from_conn_string(":memory:")
abot = Agent(model, [tool], system=prompt, checkpointer=memory)

messages = [HumanMessage(content="What is the weather in SF?")]
thread = {"configurable": {"thread_id": "4"}}

async for event in abot.graph.astream_events(
        {"messages": messages}, thread, version="v1"):
    kind = event["event"]
    if kind == "on_chat_model_stream":
        content = event["data"]["chunk"].content
        if content:
            print(content, end="|")
```

**关键点**：
- 因为是 async 方法，所以需要换成 `AsyncSqliteSaver`（异步 checkpointer）；
- 关注事件类型 `on_chat_model_stream` —— 这就是"每个新 token"事件；
- 过滤空 `content`：对 OpenAI 而言空内容通常意味着**模型在发起 tool call**，没有正文可流式输出。

### 现象解析
- **调用工具阶段**：没有 token 流式输出（因为模型此刻是在发 tool_calls，没有自然语言内容）；
- **最终回答阶段**：token 一个一个实时流出（每个 token 之间用 `|` 分隔，生产环境可去掉）。

---

## 五、两种 stream 方法对比

| 方法 | 粒度 | 同步/异步 | 典型用途 |
|---|---|---|---|
| `graph.stream(...)` | 消息级（AI / Tool 消息） | 同步 | 可观察性、调试、展示 agent 每一步 |
| `graph.astream_events(...)` | token 级 | 异步 | ChatGPT 式"打字机"前端体验 |

## 六、完整 Agent 代码（含 checkpointer 改造）

```python
from langgraph.graph import StateGraph, END
from typing import TypedDict, Annotated
import operator
from langchain_core.messages import (
    AnyMessage, SystemMessage, HumanMessage, ToolMessage
)
from langchain_openai import ChatOpenAI
from langchain_community.tools.tavily_search import TavilySearchResults

tool = TavilySearchResults(max_results=2)

class AgentState(TypedDict):
    messages: Annotated[list[AnyMessage], operator.add]

class Agent:
    def __init__(self, model, tools, checkpointer, system=""):
        self.system = system
        graph = StateGraph(AgentState)
        graph.add_node("llm", self.call_openai)
        graph.add_node("action", self.take_action)
        graph.add_conditional_edges(
            "llm", self.exists_action,
            {True: "action", False: END}
        )
        graph.add_edge("action", "llm")
        graph.set_entry_point("llm")
        self.graph = graph.compile(checkpointer=checkpointer)   # ← 持久化接入
        self.tools = {t.name: t for t in tools}
        self.model = model.bind_tools(tools)

    def call_openai(self, state: AgentState):
        messages = state['messages']
        if self.system:
            messages = [SystemMessage(content=self.system)] + messages
        message = self.model.invoke(messages)
        return {'messages': [message]}

    def exists_action(self, state: AgentState):
        return len(state['messages'][-1].tool_calls) > 0

    def take_action(self, state: AgentState):
        tool_calls = state['messages'][-1].tool_calls
        results = []
        for t in tool_calls:
            result = self.tools[t['name']].invoke(t['args'])
            results.append(ToolMessage(
                tool_call_id=t['id'],
                name=t['name'],
                content=str(result)
            ))
        return {'messages': results}
```

## 七、生产应用清单

要把 agent 推上生产，以下两组能力几乎必备：

| 需求 | 解决方式 |
|---|---|
| 多个用户同时对话 | `thread_id` + 持久化 checkpointer |
| 会话记忆、可中断续跑 | 持久化 checkpointer（Redis / Postgres） |
| ChatGPT 式打字机效果 | `astream_events` + token stream |
| 调试可视化 agent 每一步 | `graph.stream` 打印 messages 级事件 |
| Human-in-the-loop 审批流程 | **持久化**做底座（下一节展开） |

## 八、本节要点速记

- **Checkpointer = 在每个节点前后自动保存 agent 状态**；
- **`thread_id` = 会话身份证**，决定"接着谁的历史跑"；
- 两种 stream：**消息级**（`stream`）和 **token 级**（`astream_events` + async）；
- token streaming 需要 async checkpointer（`AsyncSqliteSaver`）；
- 工具调用期间模型没有 content，所以看不到 token 流——只有最终回答阶段才逐 token 出；
- **Persistence 也是 Human-in-the-loop 的底座**。

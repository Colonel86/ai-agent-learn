**用代码表达计划**，是规划设计模式的一种强大变体。

**问题：工具越堆越多的陷阱**

以咖啡机销售数据分析为例，如果给 LLM 提供一组固定工具（获取列最大值、均值、过滤行等），遇到"哪个月热巧克力销量最高？"这类问题，就需要对每个月分别过滤、统计、再取最大值，过程极其繁琐。而遇到"上周有多少笔不重复交易？"，现有工具根本不够用，又得新增工具。

实践中，很多团队就陷入了这个循环——**不断遇到新查询，不断创建新工具**，系统越来越脆，维护成本越来越高。

**更好的方案：让 LLM 直接写代码**

告诉 LLM "请用 Python 代码解决用户的问题"，它就可以调用 pandas 等库中**成百上千个内置函数**——而且 LLM 的训练数据中见过大量这些函数的使用示例，知道什么时候用什么。

例如，"最后五笔交易的金额"，LLM 会写出：加载 CSV → 解析日期列 → 按日期排序 → 选取最后五行 → 提取价格列。"上周不重复交易数"，LLM 会写出：读取数据 → 解析日期 → 定义时间窗口 → 过滤行 → 去重 → 计数。代码本身就是计划，直接执行即可得到答案。

**研究数据的验证**

来自 Wang 等人论文的数据显示，在多种模型和任务上，**代码作为行动（Code as Action）的效果优于 JSON 计划，JSON 计划又优于纯文本计划**。

**适用场景与注意事项**

- **最适合**：任务本质上可以用代码完成的场景（数据分析、数学计算、文件处理等）
- **不适合**：需要调用自定义业务工具的场景（仍需用 JSON/XML 规划）
- **安全提醒**：同工具使用模块一样，建议在沙箱环境中执行 LLM 生成的代码

目前，**高度自主的编程助手**是规划模式应用最成熟的领域——它能制定详细的开发计划、逐步构建各个模块、甚至规划测试步骤，效果相当出色。其他领域的规划应用仍在持续发展中。

# L2 生成与执行计划（Creating and Executing Plans）

## 计划要长什么样？

L1 演示的"一行文字描述一步"只是概念图。**实际工程中**怎么让 LLM 写出"清晰、可被代码解析"的计划？

## 主流做法：JSON 格式

让 LLM 输出 JSON 格式的计划——下游代码可以**无歧义地解析**每一步。当前所有主流 LLM 在生成 JSON 上都已经相当可靠。

### 典型 prompt

> 你可以使用以下工具：……
> 请以 JSON 格式返回分步骤计划。

### 期望的 JSON 输出大致结构

```json
[
  {
    "step": 1,
    "description": "找出圆框太阳镜",
    "tool": "get_item_descriptions",
    "arguments": { ... }
  },
  {
    "step": 2,
    "description": "...",
    "tool": "check_inventory",
    "arguments": { ... }
  },
  ...
]
```

每一步包含明确的字段：**步骤号、描述、调用的工具、参数**。下游代码按数组顺序逐项执行，可靠且可调试。

## 其它格式选项对比

| 格式 | 评价 |
|---|---|
| **JSON** | 推荐。表达明确、所有主流 LLM 都生成得好、解析方便 |
| **XML** | 也是好选择。用 XML 标签界定步骤同样清晰 |
| **Markdown** | 解析有时候有歧义，用得较少 |
| **纯文本** | 最不可靠 |

讲者实务推荐：**JSON 或 XML**。

## 为什么"格式化输出"这件事重要

把规划这一步的输出限定成结构化格式后：

- 代码可以**逐项遍历**步骤。
- 每步的工具名、参数都可直接取出，不用再做模糊匹配。
- 整个"计划 → 执行"循环更稳健。

在我参与的几个 Agentic 应用中，我给了 LLM 编写代码来完成任务的选项，它生成的代码解决方案有时出乎意料地聪明，令我十分惊喜。如果你还没怎么用过代码执行，我认为你会被它的能力所折服。

**为什么代码执行比"堆砌工具"更好？**

以一个能解答数学应用题的应用为例：你可以分别创建加减乘除四个工具，但遇到"求根号 2"就得再写一个平方根工具，遇到指数运算又得再加一个……现代科学计算器上有几十个按钮，难道要为每个功能都单独创建一个工具？

更好的做法是：**直接让 LLM 编写代码并执行**。在提示词中告诉 LLM，将答案以代码形式输出（用特定标签包裹），然后用正则表达式提取代码并执行，再将执行结果反馈给 LLM，最终生成格式化的回答。

这种方式几乎可以处理任意复杂的数学计算，而无需为每种运算单独创建工具。

**结合反思进一步增强**

如果代码执行出错，可以将错误信息反馈给 LLM，让它反思并修改代码再试一次，通常能得到更准确的结果。

**安全注意事项**

执行 LLM 生成的任意代码存在一定风险。Andrew 分享了一个真实案例：团队成员使用高度自主的编程智能体时，它竟然执行了 `rm *.py`，删除了项目目录中所有 Python 文件——好在代码备份在 GitHub 上，没有造成实质损失。

代码执行的最佳实践是：**在沙箱环境中运行**。推荐选项包括 Docker 或 E2B（轻量级沙箱），可以有效降低代码执行导致数据丢失或敏感信息泄露的风险。坦白说，很多开发者在实际中不做太多检查就直接执行 LLM 生成的代码，但如果追求安全，沙箱是更好的选择。

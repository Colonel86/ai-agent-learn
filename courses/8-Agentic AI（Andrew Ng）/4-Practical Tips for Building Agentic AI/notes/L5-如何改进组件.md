# L5 如何改进具体组件（How to Address Performance Issues）

agentic 工作流里组件类型多，改进手段也不同。这里给一组分类整理。

## 非 LLM 组件：调参 + 换实现

常见非 LLM 组件：web 搜索引擎、RAG 文本检索、代码执行环境、独立的 ML 模型（语音识别、人脸检测……）。

### 常见可调参数

- **web search**：返回数量、时间范围。
- **RAG 检索**：相似度阈值、chunk size（切块大小）。
- **检测类模型**：检测阈值——更敏感就多召回但误报多，反之亦然。

### 换组件实现

讲者自己开发 agent 时**经常这么做**：

- 换不同的 RAG provider。
- 换不同的 web search 引擎。
- ……

非 LLM 组件多样，改法也很分散，**具体看是什么东西**。

## LLM 组件：四种手段（由轻到重）

### 1. 改 prompt

- 加更明确的指令。
- 用 **few-shot prompting**：在 prompt 里塞 1 个或几个输入/输出范例，给模型示范"我想要的样子长这样"。

### 2. 换一个 LLM

用 AISuite 这类多 provider 库，**切换模型成本很低**。配上 eval，挑出对当前任务最合适的那一个。

### 3. 拆分任务

如果单步 prompt 指令太复杂，单个 LLM 调用搞不定 → 拆成多步：

- 拆"生成 + 反思"两步（W2 学过）。
- 或者拆成 2–3 个串联的小步，每步指令更聚焦。

### 4. Fine-tuning（微调）

**最后的手段**——开发成本高、复杂度大。讲者只在其它方法都试遍、还差最后几个点（如 90→95%）才考虑。**应用成熟后再做**。

## 培养"对模型能力的直觉"

选模型时，开发者的**直觉**值千金。讲者的具体做法：

### 一个具体例子：PII 脱敏

任务：从客户通话摘要里**去除个人敏感信息**（PII）——姓名、身份证号、地址等。

prompt 让 LLM "识别全部 PII 并返回 redacted（已遮蔽）版本"。

- **小模型（如 Llama 3.1 8B）**：常见问题——指令没完全跟上，列了 PII 又输出了原文又输出了清单，**漏掉姓名、地址只遮一半**。
- **更强的前沿大模型**：PII 全识别、全遮蔽，干净利落。

经验：**前沿大模型在"跟随复杂指令"上明显更强**；小模型回答简单事实可以，但复杂指令容易跟丢。

### 不同模型有不同强项

- 有的更擅长写代码。
- 有的更擅长跟随复杂指令。
- 有的在某些 niche 领域知识更准。

→ **建立"哪个模型擅长哪类活"的肌肉记忆**，选型和写 prompt 都会高效得多。

### 怎么练这个直觉

1. **新模型发布就去玩一玩**：闭源前沿模型 + 开源模型都试。
2. **维护一套个人 evals**：用同一组问题/任务考所有新模型，对比着看。
3. **读别人的 prompt**：
   - 看别人公开发表的 prompt。
   - 跟前沿模型公司的朋友交流，互相看彼此的 prompt。
   - 下载受敬重的开源项目，**翻它源码里的 prompt 学习**。
4. **在自己的 agent 里多换几个模型试**：看 trace、看组件 eval / 端到端 eval，顺便建立"性能 × 价格 × 速度"的权衡直觉。

讲者用 AISuite 的一个核心原因就是**换模型方便**，能加速这个练直觉的过程。

# W1-L7 智能体评估（Evaluating Agents / Evals）

> 原始字幕：`subtitles/W1-L7-evaluating-agents.vtt`

## 一、Evals 是最关键的技能

Andrew 的观察：
> 能不能构建出好的 agentic 工作流，**最大的预测因子**是能否推行一个**严谨自律的评估流程**。

你驱动 evals 的能力 = 你构建 agentic 工作流的能力。

---

## 二、Evals 的基本打法

**不要试图提前构建 evals。** 因为构建之前，你根本不知道会出什么错。

**推荐流程**：
1. 先把 agentic 工作流跑起来；
2. 查看输出，**手动寻找你希望它做得更好的地方**；
3. 把发现的问题编码成可自动评估的指标。

### 实例：客户订单咨询 Agent
手动审查输出，发现一个意料之外的问题：
> Agent **不应提到竞争对手**，但它在回复里说："我们比 ComproCo 好多了" "和 RivalCo 不一样，我们退货更简单"。

这种问题**很难事先预料**。所以：**先建后查，发现问题再加 evals。**

---

## 三、两大类 Evals

### 1. 客观指标（Objective Criteria）→ **用代码评估**
- "有没有提到竞争对手" 是非黑即白的；
- 维护一个竞争对手名单（ComproCo、RivalCo……）；
- 写代码搜索输出里是否出现这些名字；
- 统计出现频率 / 占比。

### 2. 主观指标（Subjective Criteria）→ **LLM 作裁判（LLM-as-a-Judge）**
- LLM 输出是自由文本，很多质量维度无法直接用代码评估；
- 可以用**另一个 LLM** 当裁判：
  ```
  请给下面这篇文章打 1-5 分，1 最差 5 最好：
  {{essay}}
  ```
- 随着迭代改进 agent，这个分数应该上升。

⚠️ **Andrew 的经验提示**：
> LLM 在 1–5 分这种分级上**并不擅长**。你可以试，但他自己**不太用**这种方式。后续模块会讲更准确的 LLM-as-judge 技巧。

---

## 四、两个层级的 Evals

| 类型 | 说明 |
|---|---|
| **端到端（End-to-End）** | 评估整个 agent 的最终输出质量 |
| **组件级（Component-level）** | 评估 agent 工作流中**单个步骤**的输出质量 |

这两种服务于开发流程的不同阶段。

---

## 五、错误分析（Error Analysis）

除了跑 evals，Andrew 经常做的事情：
- 查看 **中间输出 / LLM trace**；
- 逐步阅读每个步骤的输出，**寻找改进机会**。

Evals + Error Analysis 是核心技能，第 4 模块会深入讲。

---

## 六、本节要点

| 技能 | 做法 |
|---|---|
| 发现问题 | 先跑起来 → 手动看输出 → 找不满意的地方 |
| 客观问题 | 写代码计数指标 |
| 主观问题 | LLM-as-a-Judge（有局限，后续讲更好方法） |

## 一句话主线

> **把一项复杂任务拆成离散步骤（任务分解），用 LLM + 工具按步执行（设计模式），再靠严谨的评估（Evals + 错误分析）反复迭代到好用。**

这条主线贯穿全模块：L2 立定义 → L3 谈自主性 → L4 讲价值 → L5 看应用 → L6 教分解 → L7 教评估 → L8 给模式。

## 核心概念速查

### 1. 什么是 Agentic 工作流（L2）
> **基于 LLM 的应用，执行多个步骤来完成一项任务的过程。**

- 反例（非 agentic）：直接「写一篇关于 X 的文章」= 让人**不许用退格键、一次性线性写完**。
- 正解：大纲 → 检索 → 初稿 → 反思 → 修订 → 迭代，模拟人类「思考→研究→修订」循环。
- 代价是更慢，回报是质量**显著更好**。

### 2. 自主性是一个谱，不是二元（L3）
| 程度 | 谁决定步骤 | 特点 |
|---|---|---|
| 低自主 | 程序员硬编码 | 可控、稳定、灵活性差 |
| 半自主 | LLM 选工具，但工具预定义 | 折中 |
| 高自主 | LLM 自主决定步骤序列 | 强大但难控、不可预测 |
| 极高 | LLM 能创造新工具再执行 | 研究前沿 |

> 关键判断：**大量高价值应用都在「低自主」端**，别一上来就追高自主。
> 用 `agentic`（形容词）而非 `agent`，是为了跳出「算不算真 agent」的无谓争论，专注做事。

### 3. 三大优势（L4）
- **性能** —— HumanEval 上 GPT-3.5 + agentic 工作流 **超过** GPT-4 直接生成；即换模型的收益 < 加工作流的收益。
- **并行化** —— 人类必须串行（一次读一个网页）的活，agent 可并行下载处理。
- **模块化** —— 搜索引擎、LLM、工具都可插拔替换升级。

### 4. 应用难度光谱（L5）
发票处理（最易）→ 订单咨询 → 通用客服 → Computer Use（最难，前沿、不稳定）。

| 容易 ✅ | 困难 ❌ |
|---|---|
| 流程清晰、有现成 SOP | 步骤事先未知，需边做边规划 |
| 纯文本 | 多模态（图像/音频/视频） |

## 两项核心技能

### 技能 A：任务分解（L6）
工作循环：
```
观察人/业务怎么做 → 识别离散步骤 →
对每步问「能否用 LLM 或现有工具完成？」→
不能就问「人类会怎么做这步？」继续拆 → 直到每步可落地
```
- 积木（Building Blocks）：**AI 模型**（LLM/LMM、专用模型）+ **工具**（API、RAG/检索、代码执行）。
- 心法：**第一版分解通常都不够好**，靠迭代（直接生成→拆 3 步→某步再拆）逐步变好。

### 技能 B：评估 Evals（L7）—— 成功最大预测因子
> Andrew 的核心论断：**做得好 vs 做得差，最大差异是有没有严谨自律的评估流程。**

- **不要提前建 evals**：先跑起来 → 手动看输出 → 找不满意处 → 再编码成指标。（例：agent 不该提竞争对手，这种问题事先想不到。）
- 两类指标：
  - **客观** → 用代码评估（如检测是否出现竞争对手名单中的名字）。
  - **主观** → LLM-as-a-Judge（⚠️ 1–5 打分 LLM 不擅长，Andrew 自己少用，后续讲更好方法）。
- 两个层级：**端到端**（最终输出）+ **组件级**（单个步骤）。
- 搭配 **错误分析**：读中间 trace，逐步找改进机会。

## 四大设计模式（L8）

| 模式 | 一句话 | 典型例子 |
|---|---|---|
| **Reflection 反思** | 让 LLM 审查并改进自己的输出，或引入外部反馈（如运行代码看报错） | 生成代码 → 批评 → v2 → 跑出错 → v3；可拆出 Critique Agent |
| **Tool Use 工具使用** | LLM 自主决定调用哪些函数/工具 | 查咖啡机评分→web 搜索；算复利→写代码执行 |
| **Planning 规划** | LLM 自主决定步骤序列（开发者不硬编码） | HuggingGPT：姿态识别→生图→生描述→合成语音 |
| **Multi-Agent 多智能体协作** | 多角色 agent 分工协作 | ChatDev 虚拟软件公司；研究员+营销+编辑写宣传册 |

> 前两个偏「低自主、可控」，后两个偏「高自主、强大但难控」。

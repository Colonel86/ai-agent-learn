# W1-L6 任务分解（Task Decomposition）

> 原始字幕：`subtitles/W1-L6-task-decomposition.vtt`

## 一、核心问题

把人或企业做的工作，拆成**一个个离散、可执行**的步骤，供 agentic 工作流按步执行。

## 二、示例 1：写研究型文章

### 第一次尝试：直接生成
- 直接提示 LLM 写一篇关于 X 的文章；
- 结果常常流于表面，无法深入。

### 第二次尝试：3 步分解
反思：人类会怎么写？
1. 写大纲；
2. 搜索网页；
3. 基于搜索结果写文章。

**自问的关键问题**：
> 每一步能否由 **LLM / 一小段代码 / 函数调用 / 工具** 来完成？

- 第一步（写大纲）：LLM 可以胜任 ✅
- 第二步（生成搜索词）：LLM 可以胜任 ✅
- 第三步（写文章）：LLM 可以胜任 ✅

### 第三次尝试：进一步细分
实际结果发现"文章感觉有点割裂、不连贯"。

反思：人类会怎么解决？把第 3 步再拆：
- 3a. 写初稿；
- 3b. 审视哪些地方需要修改；
- 3c. 修订草稿。

**迭代规律**：
> 先直接生成 → 不满意 → 拆成 3 步 → 还不满意 → 某一步再继续拆 → 得到更丰富、更好的流程。

## 三、示例 2：客户订单咨询回复

3 步分解：
1. **提取关键信息**（寄件人、订单内容、订单号）→ LLM 可以做 ✅
2. **查找客户记录**（生成数据库查询调用 orders DB）→ LLM + 函数调用可以做 ✅
3. **撰写并发送回复**（调用邮件 API）→ LLM + 邮件 API 可以做 ✅

---

## 四、示例 3：发票处理

PDF → 文本转换后：
1. 提取所需字段 → LLM ✅
2. 调用函数更新数据库记录 → LLM + 函数调用 ✅

## 五、构建 Agentic 工作流的积木（Building Blocks）

### 1. AI 模型
- **LLM / LMM**（大语言 / 大多模态模型）——生成文本、决策、抽取信息。
- **专用 AI 模型**——PDF→文本、TTS、图像分析等。

### 2. 软件工具（Tools）
- **API 调用**：web 搜索、实时天气、邮件、日历……
- **信息检索**：
  - 数据库查询
  - **RAG**（检索增强生成）
- **代码执行**：LLM 写代码并在你的机器上运行，解锁巨量能力。

后续模块会深入讲解最重要的工具。

---

## 六、任务分解的工作循环

```
1. 观察人/业务在做什么
2. 识别离散步骤
3. 针对每一步问：
   - 能否用 LLM 完成？
   - 或用现有工具（API / 函数调用）完成？
4. 如果不能：
   - 问自己"人类会怎么做这步？"
   - 继续拆分，直到每步可由 LLM 或工具实现
```

---

## 七、迭代的重要性

> **你的第一版任务分解和工作流通常都不够好。**

大多数项目里，你需要**反复迭代和改进**直到达到想要的效果。要驱动这个改进过程，关键技能是：

> **知道怎么评估（evaluate）你的 agentic 工作流。**

> 下一节：**评估与评测（Evaluations / Evals）** —— 怎么度量并持续改进 agentic 工作流。

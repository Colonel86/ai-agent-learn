我认为 Agentic 工作流最大的优势在于，它让你能够有效完成许多以前根本无法完成的任务。除此之外，它还带来其他好处：**并行化**让某些任务完成得更快，**模块化**让你能够从不同来源组合最优组件，从而构建出高效的工作流。让我们来看一看。

我的团队收集了一个编程基准测试的数据，该测试评估不同 LLM 编写代码以完成特定任务的能力。这个基准测试叫做 HumanEval。结果发现，GPT-3.5（ChatGPT 第一个公开版本所基于的模型）在被直接要求写代码时，在该基准测试上的正确率为 40%。GPT-4 是一个强得多的模型，在同样的非 Agentic 工作流下，其性能跃升至 67%。

但事实证明，从 GPT-3.5 到 GPT-4 的巨大提升，仍然不及将 GPT-3.5 包裹在 Agentic 工作流中所能带来的提升。利用本课程后续将介绍的各种 Agentic 技术，你可以让 GPT-3.5 先写出代码，再对代码进行反思并尝试改进，通过这类技术，GPT-3.5 实际上能达到更高水平的性能。类似地，GPT-4 在 Agentic 工作流中也表现得好得多。因此，即使是今天最好的 LLM，Agentic 工作流也能让它获得更高性能。从这个例子可以看出，跨代模型之间的提升虽然巨大，但仍不如在上一代模型上实施 Agentic 工作流所带来的差距大。

Agentic 工作流的另一个优势是能够**并行化**某些任务，从而比人类更快地完成特定工作。例如，如果你让 Agentic 工作流写一篇关于黑洞的文章，可以同时让三个 LLM 并行生成搜索词。基于第一次搜索，可能会找出三个顶级结果去获取；基于第二次搜索，则会找出另一批网页去获取，依此类推。如果一个人来做这项研究，必须逐一顺序阅读这九个网页；而使用 Agentic 工作流，则可以将这九个网页的下载完全并行化，最后将所有内容输入 LLM 来写文章。因此，尽管 Agentic 工作流比直接单次提示要耗时更长，但与人类逐步处理数据的方式相比，并行下载大量网页的能力，实际上让它能比单个人顺序处理更快地完成某些任务。

**模块化**也是我在构建 Agentic 工作流时经常用到的优势。我会审视各个独立组件，并对其进行添加或替换。例如，我可能会决定换用一个新的网络搜索引擎——构建 Agentic 工作流时有很多可选项，包括可通过 API 访问的 Google、以及 Bing、DuckDuckGo、Tavily、u.com 等，专为 LLM 使用而设计的搜索引擎选择相当丰富。或者，我可能在某个步骤换入一个新闻搜索引擎，以获取黑洞科学最新突破的相关新闻。此外，我也会尝试在不同步骤中使用不同的 LLM 和不同的 LLM 服务商，以找出哪个组合在该步骤上能给出最好的结果。

**总结一下**，我使用 Agentic 工作流的主要原因是它在许多应用上能带来明显更好的性能。此外，它还能并行化人类原本必须顺序完成的任务，而许多 Agentic 工作流的模块化设计也让我们能够灵活地添加、更新工具，有时还能替换模型。

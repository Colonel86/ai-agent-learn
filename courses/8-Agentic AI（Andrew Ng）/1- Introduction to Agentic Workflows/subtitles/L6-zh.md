人们和企业要做的事情千头万绪。如何将这些有价值的工作拆解为 Agentic 工作流能够遵循的离散步骤？让我们来看一看。

**以研究智能体为例**

如果你想让 AI 系统就某个主题写一篇文章，最直接的做法是让 LLM 直接生成。但对于需要深度研究的主题，你可能会发现 LLM 的输出只停留在表面，缺乏深度。

这时，你可以反思自己作为人类会如何写这篇文章——你会直接坐下来就写吗？还是会先列大纲，再搜索资料，再基于搜索结果写文章？

在对任务进行步骤分解时，我始终在问自己一个问题：**每个步骤是否可以用 LLM、一小段代码、一个函数调用或一个工具来完成？** 就这个例子而言：

- 第一步，写大纲——LLM 应该能胜任
- 第二步，生成搜索词并搜索——同样可以做到
- 第三步，基于搜索结果写文章——也是可行的

这就是一个合理的初版 Agentic 工作流。

但实际实现后，你可能发现结果仍然不够好——文章前后脱节，缺乏连贯性。这种情况我自己也遇到过。遇到这种问题，你可以进一步分解其中某个步骤。比如把"写文章"这一步拆解为：写初稿 → 评估哪些部分需要修改 → 修改初稿。这更接近人类的写作方式。

**从一步到三步，再从三步扩展到五步**，就这样不断迭代，逐步形成更复杂、更完善的工作流。

**以客户订单查询为例**

第一步：提取关键信息（邮件来自谁、订购了什么、订单号是多少）——LLM 可以完成。第二步：查询相关客户记录——LLM 调用数据库查询函数可以实现。第三步：撰写并发送回复——LLM 调用发送邮件的 API 可以完成。同样是将一项任务拆解为三个可执行的步骤。

**以发票处理为例**

PDF 转文本后，第一步提取关键字段（开票方、地址、到期日、金额等），第二步调用函数将信息写入数据库。两个步骤，清晰可执行。

**构建积木式思维**

在构建 Agentic 工作流时，我把自己拥有的资源看作一组**积木**：

- **大语言模型（LLM）**：擅长生成文本、决策、信息提取；如需处理图像或音频，还可使用多模态模型
- **专用 AI 模型**：如 PDF 转文本、文字转语音、图像分析等
- **软件工具**：各类 API（网络搜索、实时天气、发送邮件、查询日历等）、数据库查询、RAG 检索增强生成、代码执行工具等

我的大部分工作，就是观察某个人或某个企业在做什么，然后思考如何将这些积木组合排序，来完成我希望系统执行的任务。理解有哪些积木可用，是你能够想象并构建出更好 Agentic 工作流的关键。

**总结**

构建 Agentic 工作流的核心技能之一，就是**审视一项复杂任务，识别出其中的离散步骤**。面对每一个步骤，我始终在问：

> 这个步骤能用 LLM 或某个工具（API、函数调用）来实现吗？

如果答案是否定的，我会进一步追问：我作为人类会怎么完成这个步骤？能否将其继续拆解为更小的子步骤，使其更容易被 LLM 或工具实现？

构建 Agentic 工作流往往不是一次到位的——你会先搭出初版，再不断迭代改进，直到达到满意的性能水平。而驱动这一改进过程的关键，是知道如何**评估**你的工作流。下一个视频，我们将深入讨论评估（Evals）——如何构建评估体系，并持续改进工作流以达到你想要的性能。我们下个视频见。

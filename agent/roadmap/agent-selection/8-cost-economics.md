# 成本 / 单位经济学——横切决策($/任务 量化锚)

> **用途**:给 Agent 的每个 feature 算一笔账,用 **$/任务** 当统一标尺,回答三个工程判断:「**是否过度工程**」「**是否该上旗舰**」「**这个 agent 能不能上线**」。
> **适用**:Spec-Kit `/plan` 阶段任何 LLM/agent 设计;成本/延迟超预期时复盘;评审多 agent 方案时。
> **层定位**:**横切关注**——和可观测、护栏并列,贯穿模型/编排/检索/工具/记忆所有层(对齐 `interview/1.md` «成本/单位经济学横切线»:L0 选便宜模型/级联、L2 压调用数、L3 控 token+缓存、L4 量化多 agent、L5 cost trace)。
> **最后核对:2026-06**。⚠️ 具体单价/折扣变化极快——本包给**算账方法与压降顺序**,具体型号定价请查 `skills/claude-api` 或厂商官网,标「现查」处不固化快照。

---

## 一、何时需要这层(触发时机)

- 新建任何 LLM 节点/agent 前——先估 $/任务,再决定档位与结构(别先写完再算账)。
- 成本/延迟超预期,要找哪个节点在烧钱。
- 评审「要不要上多 agent / 旗舰 / 路由网关 / GraphRAG」这类**重投入**决策——用单位经济学一票否决或放行。
- 要上线、要定价、要算毛利:$/任务 必须 < 任务价值(客单价/省下的人工)。

> 👉 **核心原则:先量化单位经济学,再做任一层优化。** 没有真实 $/任务 数据时的所有「优化」都是凭感觉;**最轻起步 = 裸跑测一版真实 $/任务,有数再针对性压**(对齐 `interview/1.md`「先量化、再优化」)。

---

## 二、核心指标:$/任务 公式 + 估算清单

```
$/任务 = Σ_节点( input_tok×输入单价 + output_tok×输出单价 )
       + 工具/检索调用成本(embedding / rerank / web search / 代码执行 …)
       + (多 agent 并发倍数)
```

三个最常被漏算、最坑的因子:

| 因子 | 为什么坑 | 怎么算 |
|---|---|---|
| **输出比输入贵** | 输出单价通常约 **5× 输入**(现查:如 Opus 4.8 $5/$25、Sonnet $3/$15,见 `skills/claude-api`) | 输出 token 单独估;爱长篇大论的节点是隐形钱坑 |
| **四类 token 分开** | `cache_read≈0.1×`、`cache_write≈1.25×(5min)/2×(1h)`(现查 prompt-caching);只看总 token 看不出缓存有没有生效 | 分别记 input / output / cache_read / cache_write |
| **多 agent 倍数** | orchestrator-worker 并行子 agent ≈ **单 agent 对话的 15×**(出处:Anthropic multi-agent research,见 `interview/1.md` «L4 多 agent 15x») | 并发 worker 数 × 单 agent 成本,再问「值不值这 15×」 |

**下单前估算清单**(填不满就别拍架构):

- [ ] 每个 LLM 节点:模型**档位** / 平均 input·output token / 每任务**调用次数**
- [ ] 缓存:稳定前缀(system+工具+few-shot)能命中多少 → prefix cache 省多少
- [ ] 检索/工具:每任务 embedding/rerank/web-search/代码执行**次数 × 单价**(现查)
- [ ] 是否多 agent:并发数 × ≈15× 倍数
- [ ] 月任务量 → 月成本 → **$/任务 vs 任务价值**(毛利正不正)

## 三、压降阶梯表(由轻到重——按这个顺序往下走)

每一级先问「上一级榨干了吗」,别一上来堆全部。质量损失从「几乎零」到「越来越有损」:

| 阶梯 | 手段 | 原理/特点 | 取舍 | 何时上 |
|---|---|---|---|---|
| **⓪ 先不做(裸跑测基线)** ⭐起步 | 不优化,直连跑一版量真实 $/任务 | 没有真实 $/任务 前所有「优化」都是凭感觉;先拿到基线再决定压不压、压哪 | 零额外复杂度;明显在烧的钱也先不省(换可归因) | 原型期 / 流量小 / $/任务 还没量过 |
| **① 三级缓存** ⭐ | prompt 前缀 / 语义 / 结果 | 前缀缓存:稳定 system+工具+few-shot 命中读 ≈0.1×;语义缓存:相似 query 命中历史答(GPTCache 类);结果缓存:完全相同输入查表不调 LLM | 前缀缓存≈**零质量损失**,最先做;但前缀**一字节变化全失效**,语义缓存有**错配**风险 | 几乎永远先做;有重复前缀/重复 query 就值 |
| **② 降档** | 高频/简单节点换便宜模型 | triage/分类/抽取/格式化用轻量档(→ `roadmap/agent-selection/1-model.md` 按角色分档) | 质量下降;**难任务降档会反复重试反而更贵** | 节点任务规则性强、量大 |
| **③ 路由 / 级联** | 便宜模型先行,低置信/失败再升级 | LLM cascade / FrugalGPT:小模型答→判置信度→不行才升旗舰(→ `roadmap/agent-selection/1-model.md` «模型路由/级联/网关») | 加一层**路由+判置信**的复杂度与延迟;别为省小钱上网关基建 | 难度分布两极、流量大到省得回本钱 |
| **④ 批处理** | 非实时任务走 Batch / 攒批 | Batch API 约**半价**(现查);或离线攒批跑 | 延迟从秒级 → 分钟/小时级,**只适合非交互** | 打标/离线分析/夜间作业等不等人的活 |

**横切省法(任何阶梯都可叠加)**:压 prompt + 控 `max_tokens`;RAG 把上下文收窄到高信号 token(→ `roadmap/agent-selection/3-retrieval.md`,别拿 1M 窗口硬塞);降 `effort`/思考预算;**确定性步骤不调 LLM**(能查表/规则就别概率化);给 agent **步数上限**防无界循环烧钱(对齐 `interview/1.md`「确定性优先」「有界状态机」)。

## 四、选型判据(决定压到哪一级 / 要不要上某重投入)

| 轴 | 怎么权衡 |
|---|---|
| **任务价值 vs $/任务** | 单位经济学为正才上线;**旗舰只配在「值回票价」的节点**,不是全程一个旗舰 |
| **质量损失容忍度** | 缓存≈0损 → 优先;降档/级联有损 → 用 eval 守住别掉点(→ `roadmap/agent-selection/5-observability-eval.md`) |
| **实时性** | 交互式 → 缓存+级联;非实时 → 批处理 |
| **量级(改动 × 流量)** | 高频路径优先压:**小改动 × 大流量 = 大节省**;长尾低频别投入 |
| **复杂度是否真到了** | 路由网关/语义缓存基建有维护成本;**最轻方案起步,复杂度真到了再升级**——过早上是 Agent 项目最常见的过度工程 |

## 五、成本上限 + 告警(和延迟一起 trace)

成本不是事后看账单,是**事前设计约束**(呼应 `interview/1.md` L5「延迟预算前置」——成本同理):

- **每个 feature 设 $/任务 上限**(预算),写进 plan;超了就触发降档/级联/缓存,而不是默默烧钱。
- **cost + latency + token 同一条 trace**(→ `roadmap/agent-selection/5-observability-eval.md` 全链路 tracing);四类 token 分开打点,否则看不出缓存是否生效、钱花在哪一步。
- **熔断**:单任务 token 上限 + agent 步数上限——防失控循环/重试雪崩把账单打穿。
- **月度对账**:trace 累加做实时监控,但**厂商 Usage/Cost API 为权威 $ 来源**(累加会有微漂移;对齐 `interview/1.md` 横切带 B「成本/延迟/token 追踪」)。

## 六、反模式 / 「先不做」清单

| 反模式 | 为什么烧钱 | 最轻替代 |
|---|---|---|
| 整系统一个旗舰模型 | 最常见的钱坑——简单节点也付旗舰价 | 按节点分档(→ `1-model.md`) |
| 多 agent 当默认解 | ≈15× 成本,常是「拓扑复杂度掩盖 prompt/工具没做好」 | 先把单 agent + 好工具做扎实(→ `interview/1.md` L4) |
| 为还没上线的 feature 先搭多级缓存+路由网关 | 过度工程,维护成本 > 省下的钱 | 裸跑测真实 $/任务,有数再压 |
| 无界 agent 循环、无 token/步数上限 | 绕圈/重试烧到失控 | 状态机有界 + 熔断阈值 |
| 拿 1M 窗口硬塞全部上下文 | token 吃满预算且 lost-in-the-middle 掉点 | RAG 收窄高信号 token(→ `3-retrieval.md`) |

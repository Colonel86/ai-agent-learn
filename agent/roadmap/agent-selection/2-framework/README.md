# AI Agent 选型决策包(Agent Stack Selection Kit)

> **用途**:在做 AI Agent 架构设计 / 开发前,根据**数据特征 + 业务需求**快速、可复用地选出合适的 **框架 / SDK / 库**。
> **适用**:可直接被 Spec-Kit 的 `/specify` 与 `/plan` 阶段引用,也可由 `framework-selector` skill 交互式驱动。
> **本包只是「编排框架层」**:模型/检索/记忆/可观测等其他层的选型见总览 [`agent/roadmap/agent-selection/README.md`](../README.md),或用 `stack-selector` skill 跨层路由。
> **维护者视角**:这是一套"决策资产",不是一次性结论。框架在演进,**结论会过期,但决策方法不会**——所以本包同时给方法(决策树/评分卡)和当下快照(框架画像/场景手册)。

---

## 一、为什么要有这套东西(架构师视角)

选型是 Agent 项目里**最早做、最难改**的决策。选错的代价不是写错代码,而是:
- 控制力不够 → 后期想加 HITL / 自定义循环时被框架挡住,只能绕或重写。
- 抽象太重 → 调试时看不透底层,token 成本和延迟不可控。
- 生态错配 → RAG-first 的活用了状态机框架,或多 agent 协作的活用了线性管线。

**核心原则:让架构匹配问题的形状,而不是让问题迁就框架。**
> 线性任务 → 管线;有分支 → 路由;有循环/反思 → 状态图;多角色协作 → 多 agent;只要结构化输出 → 裸 SDK + 类型层。

## 二、五件套(决策树/评分卡/画像/场景/集成)怎么配合用

| 文件 | 作用 | 什么时候用 |
|---|---|---|
| [`01-decision-tree.md`](01-decision-tree.md) | **快速排除**:5-7 个关键问题,if-then 收敛到 2-3 个候选 | 选型第一步,1 分钟缩小范围 |

## 三、标准选型流程(3 步)

```
输入:数据特征 + 业务需求 + 约束(成本/延迟/团队/合规)
   │
   ├─ Step 1  决策树排除         →  得到 2-3 个候选        (01)
   ├─ Step 2  评分卡量化对比      →  得到加权得分排序       (02 + 03)
   └─ Step 3  场景手册交叉验证    →  确认没有更合适的成熟方案 (04)
   │
输出:1 个首选 + 1 个备选 + 选择理由 + 已知代价  →  写进 plan / 转 ADR
```

> ⚠️ **决策必须有备选**(哪怕备选是"先不用框架,裸 SDK 起步")。没有备选的选型不是选型,是默认。

## 四、与已有资产的关系

- **`agent/roadmap/agent-selection/4-tools.md`** —— 工具层 / 工具路由方案的选型(100+ 工具如何路由选对),与本包是**不同层**:本包选"Agent 编排框架",那份选"工具路由方案"。两者常在同一个 plan 里同时被引用。
- **`agent/skills/adr-writer/`** —— 选型决策定下来后,用它把"为什么选 X 不选 Y"沉淀成正式 ADR。本包负责"怎么选",adr-writer 负责"怎么记"。
- **`courses/`** —— 框架画像里的多数结论可回溯课程笔记(部分框架画像如 MAF/OpenAI Agents SDK/Google ADK 据厂商文档补充,已在 `03-framework-profiles.md` 中标注)。

## 五、维护约定

- 每个框架画像带 **`最后核对` 日期**;超过 6 个月需复核(Agent 框架迭代极快)。
- 结论分级:✅ 稳定经验 / ⚠️ 当下快照(易变) / ❓ 待验证。
- 新增框架时,先填 `03` 画像 → 再补 `02` 评分 → 最后在 `04` 找到它的甜区场景。

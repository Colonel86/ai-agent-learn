# L6 · 课程总结与架构师复盘

这门课教的不是"Oracle 怎么用"，而是**把记忆当一等基础设施来工程化**——正是从"会调 API"迈向"能设计记忆架构"要补的一课。

## 1. 课程主线 = 五大可复用模式

结语点名这五个是生产级智能体的构建块，也是最该沉淀的资产：

| 模式 | 一句话 | 出处 |
|---|---|---|
| **Memory Modeling** | 按认知类型（情景/语义/程序性）建模并落表 | L1→L2 |
| **Semantic Retrieval** | 记忆（含工具）按语义相似度按需检索 | L2/L3 |
| **Extraction** | 从原始对话抽取实体/知识 | L4/L5 write_entity |
| **Consolidation** | 总结/压实/巩固，处理增长与矛盾 | L4 |
| **Write-back** | 执行结果、工作流、答案写回长期记忆 | L5 循环外收尾 |

> 面试被问"怎么设计 Agent 记忆系统"，就按 **建模→检索→抽取→巩固→写回** 五步讲，每步配一个本课实现。

## 2. 架构师级带走点（Top 5）

1. **记忆核心 = 数据库，SQL + 向量混合**。精确/时序走 SQL（对话、日志），语义走向量（知识、工具、实体、摘要）。无脑全上向量库是反模式。
2. **"循环内/外 × 确定性/智能体触发" 2×2 矩阵**。装配与写回必须由代码确定性执行（别指望 LLM 记得），探索动作交给 LLM——Agent 可靠性工程的核心划分。
3. **工具是可检索的程序性记忆**。MCP 工具爆炸的标准解法：语义检索 top-k 动态注入，配 Memory Unit Augmentation 提升可分性。
4. **压实 = 给窗口做虚拟内存**。ID + 描述留窗口，原文进 DB，按需 `expand_summary` 换入；`summary_id` 回填让归档状态可恢复。
5. **memory-aware 与普通 RAG 的分水岭是元认知**：智能体知道自己有哪些记忆、缺的细节该去哪取。

## 4. 诚实的边界

- **Oracle 绑定**：方法论完全通用，但存储层 API（OracleVS、`setup_oracle_database`）是厂商特定的，换 pgvector 要重写——上层 loop 因有 Memory 抽象层基本不动，恰好反证带走点 (b) 的价值。
- **`len//4` 估 token**：教学够用，成本敏感的生产换 tiktoken。
- **本地小 embedding 模型**：省钱但质量上限有限，生产按 [[project_selection_matrix]] 检索层单独评估。

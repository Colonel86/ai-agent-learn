# L2 · 写路径解剖:消解质量实验(框架现状.md §2.7 待验证① 的实测)

## 实验设计

- **12 组矛盾对**(期望旧记忆被 UPDATE/DELETE):10 组"状态演化"型(搬家/换工作/偏好反转…)+ 2 组"纠正"型(说错了改口,旧信息毫无保留价值——消解的试金石);
- **3 组对照**(防止把"见什么都改"当成能力强):重复信息 ×2 期望 NOOP,无关新信息 ×1 期望 ADD;
- 每组独立 `user_id` 隔离;自动判定(种子记忆文本变化=UPDATE、id 消失=DELETE、原封不动+新增=COEXIST);明细落盘 `results.json`。

```bash
source ../.venv/bin/activate && python main.py        # 全量 15 组,约 40s
```

## 实测结果(2026-07,mem0ai 2.0.12 + deepseek-v4-flash,temperature=0)

| 组别 | 判对率 | 结论 |
|---|---|---|
| 状态演化型矛盾 ×10 | **0/10** | 全部 COEXIST(矛盾并存) |
| 纠正型矛盾 ×2 | **0/2** | 同样 COEXIST——**错误事实原样留存** |
| 对照:重复 ×2 | 2/2 | NOOP 正确(去重能力正常) |
| 对照:无关 ×1 | 1/1 | ADD 正确(不乱改) |

**一句话:在这套栈上,mem0 的消解决策事实上只有 ADD 和 NOOP 两档,UPDATE/DELETE 从未触发。** 纠正型 0/2 尤其致命:"User lives in Hangzhou"(已被用户明确否认)和"User corrected their location from Hangzhou to Suzhou"并存,检索"用户住哪"两条都会命中。

## 机制分析(为什么全是 ADD)

看失败样本能看出因果链:**问题出在抽取阶段,不是决策阶段**。

1. 抽取 LLM 把新信息改写成了**事件叙述**:"switched from X to Y""corrected their location from Hangzhou to Suzhou"——而不是新的状态断言"lives in Suzhou";
2. 于是决策阶段面对的是「旧状态」vs「一条描述转变过程的新事实」,**两者在字面上不构成同一属性的两个冲突值**,判 ADD 反而是"合理"的;
3. 对照组证明决策环节本身工作正常(精确重复能判 NOOP)——所以这不是管线断了,是**两级 LLM 的语义分工在这类输入上系统性失配**。

无法完全归因是 mem0 2.x 的设计取向(偏事件日志化)还是 deepseek-v4-flash 的措辞习惯(它极爱补时间状语,"around July 17, 2026");换 GPT 系底座对比是留给读者的练习。但对选型判断而言归因不重要——**结论是:消解质量不是 mem0 这个框架承诺的属性,而是"你的底座 LLM × 它内置 prompt"的涌现行为,换底座必须重测**。

## 面试可用的表述

> "我实测过 mem0 的冲突消解:12 组矛盾对话(含 2 组纯纠正),0 组触发 UPDATE/DELETE,全部矛盾并存;但去重(NOOP)和无关新增(ADD)判断全对。机制上是抽取阶段把新信息改写成事件叙述,导致决策阶段看不到直接的值冲突。所以宣传里的 ADD/UPDATE/DELETE/NOOP 四操作,实际分布可能极度偏斜,**staleness 问题比纸面上更严重**——这也是我认为 Zep 的 edge invalidation 或 Hindsight 的 observation 演化在这个维度上更可信的原因:它们不依赖'恰好判对'的单次 LLM 决策。"

## 对 L1 结论的修正

L1 里"搬到上海走了 ADD"当时当作单个失败样本;L2 证明那不是偶发,是**系统性行为**。框架现状.md §2.2 的风险表述("事实可能被静默改错或误删")在这套栈上实测方向反了:**真实风险不是误改,是从不改**。

## 练习

1. 把 `CONFIG` 的 LLM 换成其它 OpenAI 兼容端点(如 Qwen),重跑看判对率是否翻盘——验证"底座依赖"假设;
2. 用 mem0 的 `custom_update_memory_prompt` 注入"检测到同一属性的新值时必须 UPDATE 旧记忆"的规则,看能救回几组(L5 定制写入的预习);
3. 挑一个失败 case,手动把新事实改写成状态断言("我住在苏州")直接 `add`,验证机制分析第 1 点。

# L0 · 课程介绍：LLM 即操作系统——虚拟内存式的记忆管理

> 课程：LLMs as Operating Systems: Agent Memory（DeepLearning.AI × Letta）
> 讲师：Charles Packer & Sarah Wooders——**MemGPT 论文原作者**（*MemGPT: Towards LLMs as Operating Systems*）

## 一句话定位

上下文窗口有限、贵、慢，那么"塞什么进上下文"这个决策该谁来做？本课的答案是革命性的：**让 LLM 自己来管理自己的上下文窗口**——LLM 在 AI 应用中扮演操作系统的角色。

> 和 12a（Oracle）的根本分野就在这里：12a 里记忆管理主要靠**程序化代码**（80% 阈值触发总结等确定性操作），LLM 只是"能调用记忆工具"；12b 则把**记忆管理本身全权交给 LLM**（OS 也是一个 agent）。这是同一问题谱系的两端——工程确定性 vs 智能体自治。

## 核心类比：虚拟内存（Virtual Memory）

MemGPT 的核心洞察借自计算机系统：

| 操作系统 | MemGPT |
|---|---|
| 物理内存（有限） | **上下文窗口**（有限） |
| 虚拟内存（近乎无限） | 外部存储（数据库） |
| 缺页中断 → OS 换页（换出到磁盘、换入所需页） | 需要的信息不在窗口 → **agent 换入/换出记忆** |
| OS 内核做换页决策 | **LLM agent 自己做换页决策** |

换页机制的对应细节：OS 引用不在物理内存的虚拟地址时，先把一块内存移到磁盘（保留修改），再把目标块取回内存。MemGPT 完全同构：把不重要的记忆移出上下文（写入 DB），把需要的记忆检索回上下文。

> **架构师视角**：12a L4 的"上下文压实（compaction）= 给窗口做虚拟内存"其实就是这个思想的手工实现版。12b 是这个思想的**原生、自治**实现。面试讲记忆管理时用这个类比开场，天然显得有体系。

## 记忆管理的具体手段（开场预告）

给 agent：
1. **上下文窗口里划一段可写的长期记忆区**（agent 能直接编辑）
2. **访问外部存储的工具**（数据库读写）→ 更大的记忆池
3. **搜索外部记忆并把结果放回上下文的工具**

## Letta 与 MemGPT 的关系（必须分清）

| 名词 | 是什么 |
|---|---|
| **MemGPT** | ① 研究论文；② 论文里描述的一种 agent 设计（OS 启发、两层记忆） |
| **Letta** | 开源 agent **框架**，可以用它构建 MemGPT 型 agent（也能超出论文范围） |

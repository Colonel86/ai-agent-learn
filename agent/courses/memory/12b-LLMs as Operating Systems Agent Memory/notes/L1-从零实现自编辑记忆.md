# L1 · 从零实现 Self-Editing Memory（纯 OpenAI API）

## 1. Self-Editing Memory 是什么

**允许 LLM 自己更新自己的长期/持久记忆**。论文的动机很朴素：LLM 是整个程序里"最聪明"的部件，与其硬编码记忆管理规则，不如让 LLM 自己决定记什么、怎么记。这是构建"能随时间学习和改进的 agent"的基础能力。

> **对比 12a**:12a 的记忆写入以确定性为主(收尾必写 workflow/entity/conversation),12b 从第一课就把"写不写、写什么"交给 LLM 判断。两种哲学的取舍见 L7 复盘。

## 2. Chatbot vs Agent：Agentic Loop

- **Chatbot**：一条用户消息 → 一次 LLM 调用 → 一条回复。
- **Agent**：一条用户消息可能触发**多次 LLM 调用**（agentic loop）。例：收到消息 → 内心想"我认识这个人吗" → 调 memory search 工具 → 基于结果回复"生日快乐 Sarah"。一条消息，三次 LLM 调用。

循环的本质：**agent state → 编入 context window → LLM 推理 → 结果更新 agent state**，循环往复。单步称为 **agent step**。把 state 变成 context 的过程叫 **context compilation**（L2 展开）。

## 3. 最小可行记忆：一个 Python dict

```python
agent_memory = {"human": "Name: Bob"}
system_prompt = "You are a chatbot. " \
  + "You have a section of your context called [MEMORY] " \
  + "that contains information relevant to your conversation"

messages=[
    {"role": "system", "content": system_prompt + "[MEMORY]\n" + json.dumps(agent_memory)},
    {"role": "user", "content": "What is my name?"},
]
```

两个要点：
1. 记忆**注入在 system prompt 区**（不混进 chat history）
2. system prompt 必须**显式告诉 LLM 它有记忆区**——否则 LLM 不知道 `[MEMORY]` 段是干嘛的

## 4. 把记忆做成可编辑：memory tool

工具本体就是一个改 dict 的函数：

```python
agent_memory = {"human": "", "agent": ""}

def core_memory_save(section: str, memory: str):
    agent_memory[section] += '\n' + memory
```

再配上 OpenAI 要求的两样：**功能描述** + **JSON schema**（参数名/类型/required）。schema 里用 `enum: ["human", "agent"]` 约束 section 只能二选一——**用 schema 约束代替祈祷式 prompt**，这是 07a/07b 学过的老原则。

关键认知：**OpenAI 不会替你执行工具**。返回的是 `tool_calls`（stringified JSON 参数），你要自己 `json.loads` 再 `core_memory_save(**arguments)`，然后把结果回填进消息历史。

## 5. Agentic Loop 的最小实现

```python
def agent_step(user_message, chat_history=[]):
    messages = [system_prompt, memory, *chat_history, user_message]
    while True:
        response = client.chat.completions.create(model=model, messages=messages,
                                                  tools=[core_memory_save_metadata])
        messages.append(response.message)
        if not response.message.tool_calls:      # 没调工具 = 回复用户 → 出循环
            return response.message.content
        # 调了工具 → 执行、回填 tool 消息、继续循环
        arguments = json.loads(response.message.tool_calls[0].function.arguments)
        core_memory_save(**arguments)
        messages.append({"role": "tool", "tool_call_id": ..., "content": f"Updated memory: ..."})
```

**循环退出约定：非工具调用即 break**。发"my name is bob"，agent 会一步内先调 `core_memory_save` 再生成使用了新记忆的回复——**编辑记忆 + 回复用户，一条消息内完成**。

system prompt 里的行为规则也值得记："必须要么调工具要么回复"、"不要重复同样的动作"、"学到新信息**总是**调 core_memory_save"——工具使用纪律靠显式指令喂进去。

> **记忆点（引出 L2）**：本实现的退出约定是"非工具=退出"。MemGPT 走得更极端——**一切动作都是工具，连回复用户都是 `send_message` 工具**；某些工具（send_message）设计为打破循环，另一些（搜记忆/改记忆）不打破。这个统一化在 L2/L3 是核心设定。

> **架构师视角**：这一课的价值是**祛魅**——所谓 self-editing memory，最小实现就是 dict + 一个函数 + tool calling + while 循环，50 行代码。框架（Letta/LangGraph/Mem0）卖的不是这个机制本身，而是持久化、并发、可观测、多 agent 这些工程外围。面试可以现场手写这个最小实现，含金量高于背框架 API。

# L0 · 课程介绍：用 NeMo Agent Toolkit 把 Agent 从 Demo 推向生产

> 课程：Nvidia's NeMo Agent Toolkit: Making Agents Reliable（DeepLearning.AI × Nvidia）
> 讲师：Brian McBrayer（Nvidia 生成式 AI 方向 Solutions Architect）；Andrew Ng 开场介绍。致谢名单：Josh Wyatt、Michael Demoret、Bartley Richardson（NVIDIA），Summer Rae、Esmaeil Gargari、Brendan Brown（DeepLearning.AI）。

## 一句话定位

**核心问题**：很多人都卡在同一步——demo 也许 60% 的时间能跑对，**怎么把它变成可以放心交付给用户的可靠系统？**

**本课答案**：Nvidia 开源的 **NeMo Agent Toolkit（NAT）** 给出三件关键工具——**可观测性**（observability）、**可反复运行的评估**（evals）、**agentic workflow 的部署**（deployment）。而且它不要求推倒重来：你已经用裸 Python、LangGraph 或 CrewAI 建好的 workflow，可以直接集成 NAT 拿到这些能力。

三个典型收益（Andrew 原话级要点）：

- **Agent 偶尔调错工具**？NAT 给你 execution traces（执行轨迹），能真正看到里面发生了什么；
- **想跑 CI/CD 或系统性地改进 Agent 性能**？NAT 让你以有纪律的方式（disciplined way）搭建并反复运行 evals；
- **部署引入一堆复杂度**（API endpoint、鉴权、rate limiting，一改模型/prompt 全部重来）？NAT 把这层基础设施代码接管，让你专注于 Agent 本身。

> **架构师视角**：Andrew 把 NAT 的卖点归纳为 observability / evals / deployment 三件套——这恰好对应我的选型矩阵里 5-observability-eval 和 9-serving-deployment 两层。NAT 的独特站位不是"又一个 agent 框架"，而是压在既有框架（LangGraph/CrewAI/裸 Python）之上的**生产化外壳**：框架选型和生产化选型由此解耦，这是评估它时最重要的坐标。

## 核心概念/类比

| 概念 | 类比 | 一句话 |
|---|---|---|
| NAT（NeMo Agent Toolkit） | 给毛坯房做"精装交付" | 开源工具包，为已有 agentic workflow 补上可观测/评估/部署 |
| Observability（执行轨迹） | 行车记录仪 | Agent 用自然语言推理，没有 trace 就不知道它为何做某个决定 |
| OpenTelemetry + Phoenix | 统一制式的黑匣子 + 回放台 | 用 OTel 标准埋 tracing，在 Phoenix 里可视化推理与工具选择过程 |
| Evals | 回归测试跑在 Agent 上 | 改 prompt / 换模型后，知道到底是变好还是变坏 |
| 部署复杂度 | "写基础设施代码，而不是做 Agent" | API endpoint、鉴权、rate limiting……每次迭代都重现一遍 |
| 多 Agent 协作 | 专科医生会诊 | LangGraph 等框架构建的专职 Agent 协作完成气候分析的不同侧面 |

## 课程路线

贯穿项目：一个**分析气候数据的 Agent**（后续课程会看到用的是真实 NOAA 数据）。

| 阶段 | 一句话预告 |
|---|---|
| 注册工具 | 把 Python 函数注册为工具，扩展 Agent 能力 |
| 可观测性 | 用 OpenTelemetry tracing + Phoenix 可视化，看清 Agent 如何推理、考虑了哪些工具、做了什么选择 |
| 评估 | 跟踪性能随时间的变化——调 prompt / 换模型后，知道是否真的有帮助 |
| 互操作 | NAT 直接兼容你已在用的框架：LangChain、CrewAI 或自定义代码 |
| 多 Agent | 把气候分析 Agent 扩展为多 Agent workflow，LangGraph 等框架构建的专职 Agent 分工协作 |
| 部署 | 通过多个 lab 学会 NAT 如何让 Agent 达到 production ready |

> **对比课程 21 Evaluating AI Agents**：课程 21 讲的是**方法论**——为什么 Agent 评估不同于传统软件测试、怎么设计 evaluator；这门课给的是**工程载体**——同一套 observability + evals 理念被打包进一个工具链（NAT），并强调"repeatedly run evals"进 CI/CD。两门课一纵一横：21 回答"评什么、怎么评"，NAT 回答"评估如何变成流水线上可反复执行的基建"。

> **记忆点（引出 L1）**：Andrew 的开场白只立了问题——60% 可靠的 demo 到生产之间隔着 observability、evals、deployment 三座桥。L1 由 Brian 展开完整全景：**Day 1 是把 Agent 建出来，Day 2 才是一切麻烦的开始**——NAT 就是为 Day 2 Problems 而生的。

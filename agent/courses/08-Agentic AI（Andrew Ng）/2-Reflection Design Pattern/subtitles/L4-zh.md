反思通常能提升系统性能，但在决定保留它之前，我通常会先验证它究竟带来了多少提升——因为它会引入额外步骤，让系统运行速度略有下降。让我们来看看如何对反思工作流进行评估。

**客观评估：以数据库查询为例**

假设你经营一家零售店，用户会提问"哪种颜色的产品总销售额最高？"你让 LLM 生成数据库查询语句，再让另一个 LLM 反思并改进这个查询，最终执行改进后的查询来回答问题。

如何衡量反思是否真的有效？方法是：

1. 收集一批问题（如"2025年5月卖出了多少件商品？"、"库存中最贵的商品是什么？"等），并记录每个问题的**标准答案**
2. 分别用**无反思**和**有反思**两种方式运行工作流
3. 统计各自的**正确率**

在示例中，无反思的正确率为 87%，有反思的正确率为 95%——说明反思对数据库查询质量有明显改善。

建立好评估体系后，你可以快速尝试不同的提示词，并通过正确率来判断哪种提示效果最好。这给了你一套系统化的方法来优化提示词。

**主观评估：以图表质量为例**

对于图表生成这类主观性任务，评估就复杂一些。

最直觉的做法是把两张图都输入多模态 LLM，让它判断哪张更好。但这种方式有几个已知问题：

- 结果往往不够可靠，对提示词措辞很敏感
- 排序结果有时与人类专家判断不符
- 许多 LLM 存在**位置偏差**——倾向于认为第一个选项更好，无论实际质量如何

**更好的方法：评分量表（Rubric）**

相比直接让 LLM 比较两个选项，给单张图打分通常能得到更稳定的结果。具体做法是：

- 设计若干**二元标准**（例如：图表是否有清晰标题？坐标轴标签是否存在？图表类型是否合适？），比如设定 5~10 条
- 让 LLM 对每条标准分别给出 0/1 的判断，再将分数相加
- 这比直接让 LLM 打 1~5 分更稳定可靠——LLM 在绝对评分上往往校准不佳

收集 10~15 个不同可视化需求的测试用例后，你就可以用这套量表分别对有无反思的图表打分，从而量化反思带来的提升。此后每次调整提示词，都能重新运行评估，验证修改是否确实改善了效果。

**总结**

- **客观标准**（如数据库查询正确率）：直接写代码评估，简单高效
- **主观标准**（如图表质量）：用 LLM 作为评判者，但需注意两点：
  - **避免直接比较两个选项**——LLM 存在位置偏差，往往倾向于选第一个
  - **使用评分量表（Rubric）而非整体打分**——设计若干条二元标准（0/1），逐条判断再加总，比直接让 LLM 打 1~5 分更稳定可靠

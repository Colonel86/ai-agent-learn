反思设计模式是我在很多应用中都用过的技术，而且实现起来出乎意料地简单。让我们来看一看。

**人类如何反思，LLM 也可以如此**

就像人类有时会审视自己的输出并找到改进方式一样，LLM 也可以做到。比如，我快速打完一封邮件，初稿可能不够好——"下个月"表达不够明确，有拼写错误，还忘了署名。读过一遍后，我会修改得更具体，比如改成"Tommy，你5号到7号有空吃饭吗？"

LLM 也可以进行同样的过程：先提示 LLM 生成第一版草稿，然后将草稿传入同一个模型（或不同的模型），配以新的提示，让它反思并写出改进后的第二版，最终得到更好的输出。

**代码场景中的反思**

反思模式同样适用于代码生成。你可以让 LLM 写出第一版代码，再将其传给同一个或另一个 LLM，要求它检查 bug 并写出改进版本。

不同 LLM 各有所长，因此有时我会选择不同的模型来分别负责"生成初稿"和"反思改进"。例如，**推理模型（有时也叫思考模型）在发现 bug 方面表现尤为出色**，所以我有时会用普通模型写初稿，再用推理模型来检查问题。

**引入外部信息，让反思更有力**

仅让 LLM 自我反思固然有用，但如果能引入**外部信息**，反思的效果会大幅提升。

以代码为例：你可以直接运行代码，观察它的输出和报错信息，再将这些内容连同代码一起反馈给 LLM，让它据此改进。比如 LLM 生成了第一版代码，运行后出现语法错误，将代码和错误日志一起传回 LLM 并要求它反思，它就能获得大量有价值的信息，从而写出质量更高的第二版。

**关键设计原则**

反思模式并非万能，不能保证 LLM 每次都完全正确，但通常能带来一定程度的性能提升。需要牢记的核心设计原则是：

> **每当反思过程中有机会引入额外的外部信息，反思的效果就会大幅增强。**

如果能在反思步骤中加入代码运行结果或报错信息，LLM 就能更深入地分析问题所在，产出的第二版代码也会远优于没有外部信息时的结果。

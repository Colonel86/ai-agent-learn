# L2 为什么不直接生成就好？（Why Not Just Direct Generation?）

## 直接生成（Direct Generation / Zero-shot Prompting）

最简单的用法：写一条 prompt，让 LLM 一次性给出答案。

- "写一篇关于黑洞的短文。"
- "写一个 Python 函数计算复利。"

这种方式叫 **zero-shot prompting**——prompt 中不包含任何示例输入输出对。

### 顺带认识几个相关概念

- **one-shot**：prompt 里给 1 个示例。
- **few-shot**：给若干个示例。
- **zero-shot**：不给示例，直接让模型生成。

不熟悉这些术语也没关系，本讲的重点是：**"一次 prompt 拿到结果"** 这种最朴素的用法。

## 反思 vs 直接生成：研究怎么说

引用 Madaan 等人的论文：在多种任务上、用多种模型（GPT-3.5、GPT-4 等）做对照实验。

- 图里成对的"浅色 / 深色"柱：浅色 = zero-shot，深色 = 同一模型 + 反思。
- 大部分任务上，深色（反思版）明显高于浅色——反思确实带来提升。
- 但具体收益**因应用而异**，自己的项目还得自己测。

## 反思特别有用的几类场景

1. **结构化数据生成**
   - 简单 HTML 表格：LLM 本来就写得不错，反思帮助有限。
   - 复杂嵌套 JSON、长结构化文本：反思更容易发现格式 bug。

2. **多步骤指令生成**
   - 例如"如何泡一杯完美的茶"。
   - 用反思 prompt 检查"步骤是否连贯、是否完整"，能发现遗漏。

3. **创意 / 命名类任务（讲者亲身案例）**
   - 用 LLM 给创业公司想域名。
   - 模型常给出含义尴尬、难发音的名字。
   - 反思 prompt 用来检查：发音是否顺、有无负面联想（中英及其他语言）。
   - 讲者所在的 AI Fund 实际用过这个流程帮 portfolio 公司起名。

## 反思 prompt 示例

### 域名筛选

> 审视刚才生成的域名列表，逐个检查：
> - 是否易于发音？
> - 在英文或其他语言中是否有负面含义？
> 最后只输出同时满足上述标准的名字短列表。

### 改写邮件

> 审视邮件初稿：
> - 语气是否合适？
> - 所有事实陈述和承诺是否准确（对照前文提供的事实/日期）？
> 基于发现的问题，写出下一版邮件。

## 写好反思 prompt 的几条经验

1. **明确告诉模型这是"审视/反思初稿"**，而不是再生成一遍。
2. **给出清晰的评审标准**（发音、负面联想、语气、事实……）——标准越具体，反思越能针对你真正关心的点。
3. **多读别人写的好 prompt**。讲者的习惯：下载优秀的开源项目，专门去翻它们内部的 prompt 来学。

## 面试速答总结

**一句话**:直接生成(zero-shot)够用就别加反思;**反思不是无脑全加,而是在"复杂结构/多步指令/有隐性质量标准"的任务上才赢**,且收益因应用而异、要自己测。

### 面试回答骨架(问"既然有反思,为什么还直接生成 / 什么时候该加反思")

> 1. **先界定 baseline**:直接生成 = **zero-shot**(prompt 不带示例);相关谱系:one-shot(1 例)/ few-shot(若干例)/ zero-shot(不给例)。最朴素、最快、最便宜——**能解决就别加层**。
> 2. **证据**:Madaan 等(Self-Refine)在多任务多模型上对照,**多数任务"加反思"明显优于 zero-shot**;但**具体收益因应用而异**,要在自己项目上实测,别假设普涨。
> 3. **反思特别有用的三类场景(要能举例)**:① **复杂结构化输出**(嵌套 JSON/长结构文本——简单 HTML 表格反而帮助有限)② **多步骤指令**(查"步骤是否连贯/完整",如泡茶流程)③ **有隐性质量标准的创意类**(给公司起域名:查发音、跨语言负面联想——AI Fund 真用过)。
> 4. **写好反思 prompt 的要点**:① **明确说"审视/反思初稿",不是重写一遍**;② **给具体评审标准**(发音、负面联想、语气、事实对照……越具体越能命中你真正在意的点);③ 多抄优秀开源项目里的 prompt。

### 关键判断(加分点)

- **反思的收益和"任务有没有可检查的标准"强相关**:标准越明确(格式合法?步骤齐全?发音顺?),反思越能发现问题;没有清晰标准时,自评容易流于空泛。
- **简单任务上反思边际收益小、还白加成本**——所以是"按需",不是默认。

### 为什么这是高分答法

- 不吹"反思总更好",而是给**适用边界 + "要自己测"**的实证态度;
- "反思 prompt 要给具体 rubric"直接接上 L7 的 eval/LLM-judge——质量标准要可表述。

**一句话收尾**:直接生成是默认,反思是**针对"复杂结构/多步/有隐性标准"任务的按需增强**;关键在给反思一套**具体可检查的评审标准**,并用数据验证它在你的任务上真的赢。

# L5 利用外部反馈让反思更强（Using External Feedback）

## 为什么外部反馈重要

只靠 LLM 自己反思，本质上仍然是用同样的信息去审视同样的输出——能挤出的提升有限。
**外部反馈**给模型带来了它原本没有的新信息，这是反思真正能突破天花板的关键。

## 性能曲线的直觉图

讲者画的"三段曲线"可以这样理解：

1. **纯 zero-shot 调 prompt**：初期收益快，之后**平台期**——继续打磨 prompt 也很难再涨。
2. **加入反思**：在合适的时机切换到反思工作流，能再获得一波提升（幅度因任务而异）。
3. **加入外部反馈**：曲线被推向更高的水平线。

**实务信号**：如果你在做 prompt engineering，已经感觉**边际收益递减**——那就该考虑加反思，或者更进一步，找一个能注入外部信息的钩子。

## 外部反馈的几种典型来源

### 1. 执行代码（前几讲已出现）

- 跑代码 → 拿到输出 / 报错。
- 喂回 LLM 让它据此改写。

### 2. 模式匹配（pattern matching）

应用场景：用 LLM 写商务邮件，不希望提到竞品名字。

- 写一段代码（甚至只是正则）扫描输出中是否出现竞品名。
- 如命中，把"出现了 X 公司名字"作为批评意见反馈给 LLM。
- 让它重写、避免提及。

### 3. 网络搜索做事实核查

应用场景：研究类 agent 写出"泰姬陵建于 1648 年"。

- 严格来说不完全错——泰姬陵 **1631 年开工、1648 年建成**——但表述不够准确。
- 做一次 web search 拿到权威片段，作为额外输入交给反思 agent。
- agent 据此重写出更准确的历史陈述。

### 4. 程序化检查输出约束

应用场景：让 LLM 写博客 / 论文摘要，要求**严格的字数限制**。

- LLM 对精确字数的把控仍然很差。
- 写个 word count 工具，数实际字数。
- 如果超出限制，把"当前 X 词，目标 ≤ Y 词"反馈回去，让它再写。
- 这能显著提升对长度约束的命中率。

## 通用范式

> 写一段代码/工具 → 从 v1 输出中**抽取出新的事实**（命中关键词 / web 检索结果 / 字数 / 报错 / ……） → 把这些事实喂给反思 LLM → 它据此重写得到 v2。

只要你能想到一种**外部可计算/可查询**的反馈源，就有机会接进来。这也是反思与"工具使用（tool use）"之间的天然桥梁。

## 总结与下一模块

- 反思是构建 agentic workflow 的强力且简单的工具。
- 自我反思已经有用；接入**外部反馈**能让反思真正发挥威力。
- 下一模块进入 **Tool Use**：从这里看到的零散工具示例，进入"系统化地让 LLM 调用各种函数"的话题，agent 的能力会有质的飞跃。

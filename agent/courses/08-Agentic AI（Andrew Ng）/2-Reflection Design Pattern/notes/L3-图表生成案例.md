# L3 图表生成中的反思（Chart Generation with Reflection）

本模块配套 coding lab 的核心案例：让 agent 生成"好看"的数据可视化图表。反思在这里能显著提升输出质量。

## 任务场景

- 数据：某咖啡机的销售记录（拿铁、热巧、卡布奇诺等），含品类、时间、价格。
- 目标：让 agent 画图，对比 **2024 Q1 vs 2025 Q1 的咖啡销售情况**。

## 不带反思（v1）

prompt：让 LLM 读 CSV，写 Python 代码画图比较两个季度的销量。

模型生成了一段 Python 代码 → 运行 → 输出了一张**堆叠柱状图（stacked bar）**。

- 能跑、不报错，但**视觉效果差**：堆叠柱状图不适合做"两段时间的并列比较"，难读。

## 加上反思（v2）

关键一步：**把 v1 的代码 + 生成的图像本身**一起喂给一个**多模态 LLM**（能接受图像输入），让它：

1. 用视觉推理"看"这张图，
2. 批判图的可视化选择，
3. 提出改进方案，
4. 改写代码生成更清晰的版本。

输出 v2：变成普通的**分组柱状图**（grouped bar），2024 和 2025 并列，可读性明显更好。

> 多模态 LLM 的视觉推理能力是这里的关键——它真的"看"了图，才能说"堆叠不合适"。

## 模型搭配建议

不同模型强项不同，**初始生成**与**反思**可以选不同模型：

- 初始生成：用通用强模型（如 GPT-4o / GPT-5 类）写第一版代码。
- 反思阶段：常常用 **reasoning 模型**效果更好，因为它更擅长批判性分析。

这是构建反思工作流时一个值得多组合实验的"超参"。

## 反思 prompt 的写法范式

经典结构：

> 你是一名专业数据分析师，请就以下代码与生成的图表提供建设性反馈。
>
> [附上 v1 代码 + 生成图像 + 必要的上下文]
>
> 请按以下标准评审：**可读性 / 清晰度 / 完整性**。
> 然后，写出实现改进的新版代码。

> **记住**：给出明确、具体的评审标准，模型才知道该往哪个方向改。

## 反思真的有用吗？要靠 evals 回答

各类研究显示，反思的提升幅度差异很大：

- 有些应用提升明显，
- 有些只提升一点点，
- 有些几乎没用。

所以要回答"反思对**我这个具体应用**有没有用、用多少"，必须自己做评测（evals）。这正是下一讲的主题。

## 面试速答总结

**一句话**:图表生成是反思的最佳示范——v1 代码能跑但图难读(堆叠柱),把**代码+图像本身喂给多模态 LLM 让它"看图"再批判改写**,v2 变成可读的分组柱;关键在**多模态视觉反馈**这个"外部信息"。

### 面试回答骨架(问"举个 Reflection 的实战 / 多模态怎么用在反思里")

> 1. **场景**:让 agent 读 CSV 写 Python 画图,对比两个季度销量。**v1 能运行不报错,但选了堆叠柱状图——视觉上不适合做并列比较,难读**。"能跑 ≠ 好"。
> 2. **反思关键一步**:把 **v1 代码 + 生成的图像**一起喂给**多模态 LLM**,让它①用视觉推理"看"图 ②批判可视化选择 ③改写代码 → **v2 分组柱状图,可读性明显更好**。
> 3. **为什么这是好例子**:反馈来自**模型之外的新信息——渲染出来的图像本身**(呼应 L1"外部反馈让反思更强")。不是凭空自评,而是"看到了真实产物"才改得准。
> 4. **模型搭配**:初始生成用通用强模型,**反思阶段用 reasoning 模型**(更擅长批判分析)——这是值得实验的"超参"。
> 5. **反思 prompt 范式**:设角色(资深数据分析师)+ 附 v1 代码与图 + **给明确评审标准(可读性/清晰度/完整性)** + 让它写改进版代码。

### 关键判断(加分点)

- **"代码能跑"是确定性信号,但"图好不好看"需要语义/视觉判断**——所以这里必须靠多模态视觉,纯文本反思看不出"堆叠柱不合适"。
- **反思收益差异极大**(明显/微小/几乎没用),"对我这个应用有没有用"**只能靠 eval 回答**(接下一讲)——别假设普涨。

### 为什么这是高分答法

- 用具体案例讲清**"外部反馈"的一种高级形态=多模态看自己产物**;
- 自然带出"能跑≠达标"和"收益要 eval 验证",和 W1-L7 / 09-EDD 串起来。

**一句话收尾**:反思的威力来自**喂回真实产物**——这里是把渲染出的图像交给多模态 LLM"看",而它到底提升多少,要靠 eval 在你自己的任务上量。

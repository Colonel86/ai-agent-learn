LLM 决定调用函数的过程，乍看起来有些神秘——毕竟 LLM 本质上只是在生成文本。让我们一步步拆解这个过程。

**工具使用的底层原理**

工具本质上就是 LLM 可以请求执行的函数。现代主流 LLM 已经被直接训练为能够使用工具，但为了帮助你理解底层机制，我们先来看看早期没有原生工具支持时是怎么做的。

**早期方式：用提示词约定信号**

假设你实现了一个 `getCurrentTime` 函数，要把它"给"LLM 使用，你需要在提示词中告诉它：

> "你有一个叫 `getCurrentTime` 的工具可以使用。当你想调用它时，请输出 `FUNCTION: getCurrentTime`。当我看到这段文字，我就知道你想让我调用这个函数。"

当用户问"现在几点？"时，流程如下：

1. LLM 输出 `FUNCTION: getCurrentTime`
2. **开发者编写的代码**检测到这个信号，提取函数名
3. 代码实际调用 `getCurrentTime`，得到返回值（如"上午 8 点"）
4. 将返回值连同对话历史一起反馈给 LLM
5. LLM 最终输出"现在是上午 8 点"

**关键点**：LLM 并不直接调用函数，而是输出一个特定格式的信号，告诉开发者代码"帮我调用这个函数"，再将结果反馈回来。

**带参数的函数**

更复杂的例子：`getCurrentTime` 接受一个时区参数。用户问"新西兰现在几点？"，LLM 会输出 `FUNCTION: getCurrentTime Pacific/Auckland`，开发者代码识别后，以 `Pacific/Auckland` 为参数调用函数，得到"凌晨 4 点"，反馈给 LLM，最终输出"新西兰现在是凌晨 4 点"。

**总结：工具使用的完整流程**

1. **提供工具**：实现函数，并在提示词中告知 LLM 它的存在和用法
2. **LLM 发出信号**：当 LLM 决定调用工具时，输出特定格式的内容
3. **开发者代码执行**：识别信号，调用对应函数，获取返回值
4. **结果反馈**：将函数返回值输入回 LLM
5. **LLM 继续**：利用新信息生成最终回复，或决定继续调用下一个工具

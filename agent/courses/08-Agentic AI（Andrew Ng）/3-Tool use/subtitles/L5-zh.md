**MCP（模型上下文协议，Model Context Protocol）**是由 Anthropic 提出、现已被众多公司和开发者广泛采用的标准，旨在让 LLM 更便捷地获取更多上下文和工具。

**MCP 解决了什么问题？**

过去，每个开发者在构建应用时，都需要自己编写封装 Slack、Google Drive、GitHub、Postgres 等数据源的代码。结果是：如果有 M 个应用、N 个工具，整个社区需要完成的工作量是 **M × N**。

MCP 提出了一套标准接口，使得每个工具只需实现一次（MCP 服务端），每个应用只需接入一次（MCP 客户端），总工作量从 **M × N** 降为 **M + N**。

**MCP 的核心概念**

- **MCP 服务端（Server）**：封装特定数据源或服务（如 GitHub、Slack、Google Drive），向外提供标准化的工具和数据接口
- **MCP 客户端（Client）**：你构建的应用，通过 MCP 协议接入各类服务端，按需调用工具或获取数据

目前，MCP 客户端和服务端的生态正在快速扩展。

**实际演示**

以 Claude 桌面应用连接 GitHub MCP 服务端为例：

- 输入"总结这个 GitHub 仓库的 README"，应用自动调用 GitHub MCP 服务端获取文件内容，再由 LLM 生成摘要
- 输入"最近有哪些 Pull Request？"，LLM 调用另一个工具列出最新 PR，再生成文字总结

整个过程中，LLM 自主决定调用哪个工具，无需开发者手动硬编码。

**总结**

MCP 是一个重要的行业标准。如果你想深入了解，DeepLearning.ai 上有专门的 MCP 短课程可供学习。

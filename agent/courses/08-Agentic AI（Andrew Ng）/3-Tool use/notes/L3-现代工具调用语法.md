# L3 现代工具调用语法（Tool Syntax）

## 用 AISuite 看现代写法

讲者用开源库 **AISuite**（他和朋友们开发的多 LLM 提供商统一封装）演示。语法与 OpenAI SDK 高度相似。

骨架代码：

```python
response = client.chat.completions.create(
    model="openai:gpt-4o",
    messages=messages,
    tools=[get_current_time],
    max_turns=5,
)
```

几个要点：

- `tools=[...]`：直接传入 Python 函数列表。
- `max_turns`：工具调用循环的上限——一次工具返回后 LLM 可能想再调一个，再返回还想调下一个……`max_turns` 防止意外的无限循环。**实际几乎从不触发**，讲者一般填 5 就完事。

## 关键便利：自动生成 JSON Schema

老办法要自己写 prompt 描述工具用法。AISuite 把这步**自动化**了：

- 它读取函数的**名字**和**docstring**（包括参数说明）。
- 自动生成一段 JSON schema 描述这个工具。
- 把这段 schema 传给 LLM，让模型决定何时调用、如何填参数。

所以"工具描述写得好不好"基本等价于"docstring 写得清不清楚"。

### 示例：无参数版本

`get_current_time()` → AISuite 生成的 schema 大致包含：

- `name`: `get_current_time`
- `description`: 从 docstring 抽出的功能描述

LLM 看完就知道它在做什么、什么时候该调。

### 示例：带 timezone 参数

`get_current_time(timezone)` → schema 多了 `parameters` 部分：

- `timezone` 参数的类型和说明（同样来自 docstring）。
- 模型据此知道要填类似 `America/New_York`、`Pacific/Auckland` 这种值。

> 有些其它 API 需要你**手写**这段 JSON schema 再传进去。AISuite 替你省掉了这步。

## 整个调用循环也被封装

`client.chat.completions.create(...)` 这一行内部完成：

1. 把工具 schema 喂给 LLM。
2. 如果 LLM 请求调工具，**AISuite 自动替你调**（不需要手动拆解 + 调用 + 拼回）。
3. 把返回值送回 LLM。
4. 循环，直到 LLM 给出最终回答或达到 `max_turns`。

某些其它库需要你自己写这个循环；AISuite 一行搞定。

## 体验感

第一次看到 LLM 主动决定"去查个东西"、"去执行个操作"再回答你，会很惊艳。建议在 lab 里亲手玩一下。

## 下一讲预告：一个特别的工具——代码执行

在所有工具里，**code execution（让 LLM 写代码 + 执行）**特别强大：

- 代码本身能干的事极多。
- 一旦 LLM 能写并执行任意代码，能力上限大幅提高。

下一讲专门讲它。

## 面试速答总结

**一句话**：现代 tool calling 把 L2 的手写约定全部封装掉——**框架从函数 docstring 自动生成 JSON schema、自动跑工具调用循环**；开发者只需"把函数写好、docstring 写清楚"，schema 质量≈docstring 质量。

### 面试回答骨架（问"现代工具调用怎么写 / 框架替你做了什么"）

> 1. **接口长什么样**：`create(model, messages, tools=[函数列表], max_turns=5)`——直接传 Python 函数，不再手写 `FUNCTION:` 约定串（呼应 L2 的老办法缺陷）。
> 2. **框架替你做的两件大事**：① **自动生成工具 schema**——读函数的 name + docstring（含参数说明）生成 JSON schema 喂给 LLM；② **自动跑调用循环**——LLM 请求调工具时框架自动解析、执行、把返回值拼回，循环到出最终答案或触顶。
> 3. **`max_turns` 是什么**：工具调用循环的**上限**，防意外死循环；实战几乎不触发，填 5 够用——但能答出"为什么需要它"是加分。
> 4. **一个关键认知**：**"工具描述写得好不好" ≈ "docstring 写得清不清楚"**——因为 schema 从 docstring 自动抽取，所以 docstring 是 LLM 选工具/填参的唯一依据，要把功能、参数语义、取值示例（如 `America/New_York`）写明确。

### 关键判断（加分点）

- **抽象层级的取舍**：AISuite/OpenAI SDK 帮你自动生成 schema + 跑循环；有些 API 要你**手写 schema、自己写循环**。便利换走了控制力——需要精细控制每步（参数校验、HITL、并行调用、错误重试）时，可能要落到手写循环这一层。
- **schema 自动生成的隐性风险**：docstring 含糊 / 类型标注缺失会直接导致模型选错工具或填错参——所以"写好 docstring + 类型标注"是工程纪律，不是可选项。

### 为什么这是高分答法

- 把"一行代码"拆成**schema 生成 + 调用循环**两层，讲清框架到底封装了什么；
- 点出"docstring=工具描述"这个反直觉但关键的结论，并接上抽象层级的取舍判断。

**一句话收尾**：现代 tool calling 的本质是**把 L2 手写约定升级成"函数即工具、docstring 即描述"的自动化**；用起来一行搞定，但要清楚框架替你封装了 schema 生成与调用循环——需要控制力时知道该往下落一层。

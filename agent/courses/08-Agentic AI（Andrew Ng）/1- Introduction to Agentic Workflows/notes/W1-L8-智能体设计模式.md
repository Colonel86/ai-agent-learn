# W1-L8 智能体设计模式（Agentic Design Patterns）

> 原始字幕：`subtitles/W1-L8-agentic-design-patterns.vtt`

## 四大核心设计模式

1. **Reflection（反思）**
2. **Tool Use（工具使用）**
3. **Planning（规划）**
4. **Multi-Agent Collaboration（多智能体协作）**

---

## 一、Reflection（反思）

### 基本做法
1. 让 LLM 生成输出（如一段代码）；
2. 构造一个新提示，把输出贴回去，让 LLM **检查正确性、风格、效率**，给出批评意见；
3. 把批评反馈给 LLM，让它修复 → **v2 版本**；
4. （可选）**运行代码 → 观察错误 → 反馈回 LLM** → **v3 版本**。

### 关键点
- 让 LLM 审查自己的输出；
- 或引入**外部反馈**（比如实际运行代码看报错）；
- 不是万能药，但常常能带来明显提升。

### 延伸：转成多智能体
可以设一个**Critique Agent（批评者智能体）**：
- 它是一个 LLM，被提示"你的角色是审查代码，请指出错误、运行单元测试……"
- 让"生成者 Agent"和"批评者 Agent"来回迭代。

---

## 二、Tool Use（工具使用）

LLM 可以被赋予**工具（可调用函数）**来完成实际工作。

### 常见工具类型
| 工具类别 | 示例 |
|---|---|
| 信息获取 | web 搜索、抓网页、查数据库 |
| 数学/数据分析 | 代码执行 |
| 生产力应用 | 邮件、日历 |
| 多模态 | 图像处理 |
| 其他 | ……几乎无穷 |

### 经典场景
- 问："哪款咖啡机评分最好？" → 调用 web 搜索 → 找答案。
- 问："投资 100 美元按复利到最后有多少？" → **写代码并执行** → 得到精确答案。

### 核心价值
> LLM **自己决定**调用什么工具（哪些函数），让模型能做的事大大扩展。

---

## 三、Planning（规划）

LLM 自己决定**需要执行的步骤序列**。

### 示例（HuggingGPT 论文）
输入：
> "生成一张图：一个女孩在读书，姿势与某张图中的男孩相同。然后用语音描述这张新图。"

模型自动规划：
1. **姿态识别模型**识别男孩姿势；
2. **姿态驱动图像生成模型**生成读书女孩图；
3. **图像→文本模型**生成描述；
4. **文本→语音模型**合成语音。

### 特点
- **开发者不再预先硬编码步骤序列**，LLM 自主决定；
- 更难控制、更实验性；
- 但常能给出令人惊喜的结果。

---

## 四、Multi-Agent Collaboration（多智能体协作）

像管理层组织团队一样，雇佣多个 agent，**各自专注不同角色**，协作完成复杂任务。

### 示例 1：ChatDev
由陈倩等人创建的软件开发框架，多个 agent 扮演：
- CEO
- 程序员
- 测试员
- 设计师
- ……

像一个**虚拟软件公司**，协作完成各种软件开发任务。

### 示例 2：写营销宣传册
模拟 3 个 agent 协作：
1. **研究员（Researcher）**——做线上调研；
2. **市场营销人员（Marketer）**——撰写营销文案；
3. **编辑（Editor）**——编辑润色文本。

### 特点
- 更难控制（事先不知道 agent 会做什么）；
- 但研究显示：**在许多复杂任务上效果显著更好**（例如写传记、下棋决策）。

## 面试速答总结

**一句话**:Andrew Ng 的**四大 agentic 设计模式**——**Reflection(反思)、Tool Use(工具)、Planning(规划)、Multi-Agent(多智能体协作)**;前两个成熟可靠、应优先,后两个更强但更难控、更实验性。

### 面试回答骨架(问"有哪些 agentic 设计模式 / 你会怎么组合它们")

> 1. **Reflection 反思**:让 LLM **审查自己的输出**(正确性/风格/效率)→ 批评 → 修复出 v2;更强的是引入**外部反馈**(如**跑代码看报错**)再修出 v3。可升级成 **Critique Agent**(生成者 ↔ 批评者来回)。**实现简单、提升明显**。
> 2. **Tool Use 工具使用**:给 LLM **可调用的函数**,且**由模型自己决定调哪个**——web 搜索、查库、**代码执行**(算复利这种要精确的)、邮件日历、多模态。极大扩展能力边界。
> 3. **Planning 规划**:LLM **自主决定步骤序列**,而非开发者硬编码。例(HuggingGPT):一句"按某姿势生成读书女孩图并配语音",模型自动串起姿态识别→图像生成→图生文→文生语音。**更强但更难控、更实验**。
> 4. **Multi-Agent 多智能体协作**:多个 agent 各扮角色协作(ChatDev 的 CEO/程序员/测试;或 研究员→营销→编辑)。复杂任务上常**显著更好**,但事先不知道 agent 会做什么、更难控。

### 怎么把"罗列"答成"有判断"(关键加分)

- **成熟度排序 + 默认立场**:**Reflection 和 Tool Use 最成熟、可靠,应优先用**;Planning 和 Multi-Agent 更强大但**可控性差、偏研究前沿**,复杂度证明值得了再上(呼应 L3"选刚好够用的自主度"、Anthropic"能简单就别复杂")。
- **外部反馈 > 自我反思**:Reflection 里"跑代码看真实报错"比"LLM 自评"可靠得多——能用**确定性信号**就别只靠模型自查(接 L7 eval、`01` 的 verify 相)。
- **它们可组合**:实际系统常是 Tool Use + Reflection 打底,必要时叠 Planning/Multi-Agent。

### 这四个模式与其他笔记的映射(体现体系)

| 模式 | 对应 |
|---|---|
| Reflection | `reasoning-modes.md` 的 Reflexion;`01` 的 verify→回喂闭环 |
| Tool Use | function calling / CodeAct;工具网关 `02`、`code-sandbox.md` |
| Planning | `reasoning-modes.md` 的 Plan-and-Execute;任务分解 `W1-L6` |
| Multi-Agent | `01` 的 Orchestrator–Workers;`agent.md` 的多 Agent 拓扑 |

**一句话收尾**:四大模式 = **Reflection / Tool Use / Planning / Multi-Agent**;**优先用成熟的前两个**,Planning 与 Multi-Agent 强但难控,按任务复杂度按需叠加,且反思尽量用外部确定性反馈而非纯自评。

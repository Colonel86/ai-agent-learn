# W1-L2 什么是 Agentic AI（What is Agentic AI）

> 原始字幕：`subtitles/W1-L2-what-is-agentic.vtt`

## 一、传统 LLM 使用方式 vs Agentic 工作流

### 1. 传统方式（非 agentic）
直接提示 LLM："请写一篇关于 X 主题的文章。"

这相当于要求一个人：
> 从第一个字到最后一个字，按线性顺序一次性写完，**且不允许使用退格键**。

- 人类不会这样写东西，LLM 也不擅长这样工作。
- 尽管有这种约束，LLM 的表现已经出人意料地好。

### 2. Agentic 工作流
把写文章拆成多步：
1. 先写一个**文章大纲**；
2. 判断是否需要**网络检索**；
3. 检索并下载网页；
4. 基于检索结果写**初稿**；
5. **阅读初稿**，找出需要修改或补充研究的部分；
6. **修订**草稿；
7. 继续迭代……

这更像人类真实的"**思考 → 研究 → 修订 → 再思考**"的循环过程。

**结论**：Agentic 工作流会耗时更久，但产出的质量**显著更好**。

## 二、Agentic AI 工作流的定义

> **Agentic AI 工作流 = 一个基于 LLM 的应用，执行多个步骤来完成一项任务的过程。**

在上面的例子里，可能的组成：
- 用一个 LLM 写大纲
- 用一个 LLM 决定向搜索引擎/搜索 API 提交哪些搜索词
- 把网页内容喂给 LLM，让它写初稿
- 再用一个 LLM 做反思（reflection），决定哪里需要改
- 可选地加入 **human in the loop**（人类审校关键事实）
- 最后再修订

## 三、贯穿课程的示例：研究智能体（Research Agent）

课程将带你构建一个研究智能体，例如输入研究主题：
> "How do I build a new rocket company to compete with SpaceX?"

它会：
1. 规划调研策略；
2. 调用 web 搜索引擎下载网页；
3. 综合、排序发现的结论；
4. 撰写大纲；
5. 让一个 **editor agent** 审核逻辑连贯性；
6. 最终生成一份结构完整的 markdown 报告（含前言、背景、发现等）。

通过多源下载 + 深度思考，产出比单次提示要**深刻得多**。

Andrew 在工作中构建过多种专用 research agent：
- 法律合规（conflict legal compliance）
- 医疗健康领域
- 商业产品调研

这些思路对你构建自己的定制研究智能体会**直接有用**。

## 四、Agentic 工作流的自主性光谱

一个常被讨论的问题：**智能体自主到什么程度？**

这节课展示的是一个相对复杂、高度自主的 Agentic AI 工作流，但还有许多**更简单却极具价值**的工作流。

> 下一节将讨论：agentic 工作流可以**有多自主**，以及它提供了一个怎样的框架帮你思考不同应用的构建难易度。

---

## 面试速答总结

**一句话**:Agentic workflow = 一个**基于 LLM、通过多步骤迭代来完成任务**的应用;它把"一次性生成"换成"思考→研究→修订→再思考"的循环,耗时更久但质量显著更好。

**最有杀伤力的类比(务必记住)**:非 agentic 用法就像要求一个人**从头到尾一次写完、还不准用退格键**。人不会这么写,LLM 也不擅长。Agentic 就是把"退格键 + 查资料 + 反复改"还给模型。

### 面试回答骨架(问"什么是 agentic workflow / 和直接调 LLM 有什么区别")

> 1. **定义**:一个基于 LLM 的应用,**执行多个步骤完成一项任务**,而不是单次 prompt 单次输出。
> 2. **对比(用退格键类比)**:直接 prompt = 线性一次成型、不能回头;agentic = 拆成多步、可检索、可反思、可修订。
> 3. **典型循环**:规划/大纲 → (判断是否)检索 → 写初稿 → **reflection 反思找问题** → 修订 → 迭代;关键节点可插 **human-in-the-loop** 审校事实。
> 4. **组成是"多个 LLM 各司其职"**:一个写大纲、一个决定搜索词、一个写初稿、一个做 editor/reflection 审核——不是一个大 prompt。
> 5. **代价与收益**:更慢、更贵,但产出**深刻得多**;所以要用它的前提是"任务复杂到值得多步"。
> 6.(进阶)**自主性是光谱**:从轻量低自主到复杂高自主;很多**简单但极有价值**的工作流不需要全自主——别默认上最复杂的(接 L3,展开见下)。

### 展开:"自主性是光谱"什么意思

不是"是不是 agent"的二选一,而是一条连续刻度——**"下一步做什么"这个决策权,有多少交给 LLM**。越往高自主走,交给模型的越多:

| | 低自主 | → 中 → | 高自主 |
|---|---|---|---|
| 步骤顺序 | 人/代码写死 | 部分固定、部分模型选 | 模型自己决定 |
| 用哪个工具 | 代码指定 | 给候选、模型挑 | 模型自由调 |
| 何时停 | 固定流程结束 | 条件判断 | 模型自判"做完了" |
| 循环/重试 | 无 | 有限循环 | 自由迭代直到满意 |

刻度上的例子:**固定模板 prompt**(几乎无自主)→ **写死的多步管线 workflow**(步骤你定,LLM 只在格子里干活)→ **带条件分支/有限循环**(框内决策,如"检索不够好就再搜,最多 3 次")→ **ReAct 式**(模型自选下一步工具)→ **全自主 agent**(给目标+工具,自主规划/调用/判停)。

**关键取舍**:往高自主走,灵活性↑,但**可控性↓ / 可预测性↓ / 可调试性↓ / 成本↑ / 失败模式↑**。所以原则是**用"刚好够用"的最低自主度**,而不是默认拉满(呼应 Anthropic"workflow 能解决就别上 agent")。架构师的活儿就是按任务复杂度选光谱上的那个点。

> 一句话:**自主性是连续可调的;选刚好够用的那一档,别默认全自主。**(与 `reasoning-modes.md` 的 CoT→ReAct→LATS 自主度递增、`01-agent-run-loop` 的"工作流 vs agent 光谱"同一回事)

### 可举的落地例子(证明你真做过/真懂)

- **Research agent**(课程主线):规划调研 → web 搜索下载 → 综合排序 → 写大纲 → editor agent 审连贯性 → 输出结构化 markdown 报告。
- 专用变体:法律合规、医疗健康、商业产品调研——**同一套 research agent 思路换领域**。

### 为什么这是高分答法

- 不背术语,而是用"退格键"类比 + "多 LLM 协作 + 反思循环"讲清**机制**;
- 主动点出"**自主性是光谱、简单工作流也有价值**",体现取舍判断(对应 `../../../../interview/jd-senior-agent-engineer/01-agent-run-loop-and-orchestration.md` 的 run loop 四相,以及 `reasoning-modes.md` 里 ReAct/Reflection)。

**一句话收尾**:Agentic 的本质是把"一次成型"变成"可迭代的工作流"——多步、可反思、可人审,用时间换质量。

# W1-L5 Agentic AI 应用示例（Agentic AI Applications）

> 原始字幕：`subtitles/W1-L5-agentic-ai-applications.vtt`

从最简单到最难，四个例子展示 Agentic AI 的应用范围。

---

## 示例 1：发票处理（Invoice Processing）⭐️ 最简单

**目标**：从发票 PDF 中提取关键字段 → 写入数据库。

**关键字段**：开票方、开票方地址、应付金额、到期日。

**Agentic 工作流**：
1. 输入发票 PDF；
2. 调用 **PDF → 文本** 转换 API（输出 markdown 文本）；
3. LLM 判断：这是不是发票？不是就忽略；
4. 是发票则提取字段；
5. 调用数据库更新 API 保存记录。

**特点**：
- **流程清晰、步骤明确**；
- 这类任务最适合 agentic 工作流 —— 可以可靠地一步步执行。

---

## 示例 2：基础客户订单咨询 Agent

**目标**：回复客户关于订单的基本问题。

**工作流**：
1. LLM 从邮件中提取关键信息（订了什么、客户姓名）；
2. LLM 决定调用 **订单数据库** 查询；
3. LLM 起草回复邮件；
4. 调用 **request-review 工具**，把草稿放入人工审核队列；
5. 人工审核通过后发送。

**特点**：流程依然相对清晰，已经在大量企业部署中。

---

## 示例 3：通用客服 Agent（更难）

**目标**：回复任何类型的客户问题。

**例子 A：库存查询**
> "你们有黑色或蓝色牛仔裤吗？"

需要：
- 第一次查询：黑色牛仔裤库存；
- 第二次查询：蓝色牛仔裤库存；
- 综合回复。

**例子 B：退货请求**
> "我想退掉我买的沙滩巾。"

需要：
1. 验证客户确实买过沙滩巾；
2. 检查退货政策（30 天内 + 未使用）；
3. 允许退货则生成退货单并把订单状态设为 return pending。

**难点**：
- **所需步骤事先未知**；
- LLM 必须自行规划出需要的步骤序列。

---

## 示例 4：Computer Use（电脑操作）⭐️ 最难

**目标**：智能体操作 Web 浏览器完成复杂任务。

示例任务：
> "检查联合航空 SFO → DCA 两趟特定航班是否还有座位。"

智能体会：
- 打开 United 官网，点击页面元素，填表单；
- 根据页面内容推理下一步动作；
- 遇到问题（比如 United 网站卡住）**自主切换策略**——跳到 Google Flights；
- 在 Google Flights 找到选项后再回到 United 确认。

**现状**：
- 是**前沿研究方向**，许多公司在做；
- 但**不够稳定**：网页加载慢会让 agent 卡住、很多网页 agent 无法准确识别；
- 还不能用于**关键任务**，但是重要的未来方向。

## Agentic 应用构建难度对照表

| 维度 | 容易 ✅ | 困难 ❌ |
|---|---|---|
| **流程** | 有清晰的 step-by-step 标准流程 | 步骤事先未知，需要边做边规划 |
| **输入模态** | 纯文本 | 多模态（图像、音频、视频） |
| **已有 SOP** | 企业已有标准作业流程可以编码化 | 没有现成流程 |

LLM 最擅长处理文本，如果涉及其他模态会更难但可做。

---

## 核心技能预告

构建 agentic 工作流最重要的技能之一：

> **把复杂工作流看透，识别出它由哪些 discrete steps 构成，从而编排一个 agentic 工作流把它们一步步执行出来。**

> 下一节：**任务分解（Task Decomposition）** —— 怎么把一个复杂任务拆成离散的可执行步骤。

---

## 面试速答总结

**一句话**:这节用四个由易到难的例子说明——**agentic 应用的难度,本质由"步骤是否事先已知"决定**;流程越确定越好做,越要边做边规划越难。

### 面试回答骨架(问"什么任务适合 agent / 怎么判断一个 agentic 应用好不好做")

> 1. **先给判断维度(三条)**:① **流程**——有没有清晰的 step-by-step SOP(步骤事先已知 vs 边做边规划);② **输入模态**——纯文本最易,多模态更难;③ **是否已有 SOP**——企业有现成标准流程可直接编码化的最好做。
> 2. **用难度阶梯举例(由易到难)**:
>    - **最易·发票处理**:PDF→文本→判断是否发票→抽字段→写库。**步骤完全确定**,可靠执行。
>    - **较易·订单咨询**:抽信息→查订单库→起草回复→**入人工审核队列**→人审后发。流程仍清晰,已大量企业落地(注意这里的 **human-in-the-loop**)。
>    - **较难·通用客服**:库存查询、退货等,**所需步骤事先未知**,LLM 要自己规划步骤序列(对应高自主度)。
>    - **最难·Computer Use**:操作浏览器订机票,看页面推理下一步、卡住了**自主切换策略**(United→Google Flights)。**前沿、不稳定、不能用于关键任务**。
> 3. **给结论**:**优先做"流程确定 + 纯文本 + 已有 SOP"的任务**(高价值且可靠);需要自主规划/多模态/无 SOP 的留到能力成熟或确实必要时。

### 核心技能(最该背的一句)

> 构建 agentic 工作流最关键的能力:**把复杂任务看透,识别它由哪些 discrete steps(离散步骤)构成,再编排成工作流逐步执行。** —— 这正是下一节"任务分解"的主题,也是面试官判断你"会不会拆问题"的点。

### 为什么这是高分答法

- 不只罗列例子,而是抽出**"步骤是否已知 + 模态 + 有无 SOP"三条判断维度**,体现框架化思维;
- 难度阶梯天然对应 L3 的**自主性光谱**(步骤确定=低自主、边做边规划=高自主),把前几节串起来;
- 主动给"先做确定流程的"落地立场,呼应"默认低自主、复杂度证明了再加"。

**一句话收尾**:agentic 应用好不好做,看**步骤是否事先已知、是否纯文本、是否有现成 SOP**;先吃下"确定流程"的高价值任务,把"边做边规划/多模态/Computer Use"留给能力成熟之后。

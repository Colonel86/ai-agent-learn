# L0 · 课程介绍：用多 Agent 系统构建知识图谱

> 课程：Agentic Knowledge Graph Construction（DeepLearning.AI × Neo4j，C2）
> 讲师：Andreas Kollegger（Neo4j GenAI Developer Evangelist）+ Andrew Ng 开场
> 一句话定位：**设计一个多 Agent 系统，把你的结构化 + 非结构化数据自动转成一张知识图谱**——从"决定 schema"到"构建图谱"再到"用图谱做 GraphRAG 检索"，每一步都由一个专职 Agent（用 Google ADK 写）来做。

## 为什么是知识图谱 + 多 Agent

Andrew 在开场里点出知识图谱的价值场景：**高风险应用（high-stakes），信息存取的准确性至关重要**。它和 RAG 同源——都把文档切 chunk 存向量库——但**额外**把 chunk 放进一张图里，每个 chunk 连到从它抽出的实体（产品、订单、缺陷……），实体和 chunk 一起被检索，给 LLM 更精确的上下文。再把这张图连到从 CSV 等结构化数据抽出的另一张图，就能做单纯向量检索做不到的事，比如**根因分析**（哪个产品问题最多 → 是哪个零件 → 零件本身有问题还是工艺问题）。

而"构建这张图"本身是一个繁琐、多阶段、需要判断的工程活。本课的做法：**把数据工程师做这件事的思维流程，拆成一队 Agent**——先问清目标，再挑文件，再提 schema，最后落库。

## 核心概念表

| 概念 | 一句话 | 出现于 |
|---|---|---|
| Knowledge Graph | 节点（things）+ **一等公民的关系**（有方向、有类型、带属性），而非 join 表约定 | L1 |
| Cypher | Neo4j 的图查询语言，"带模式匹配能力的 SQL"，天然贴合自然语言/LLM | L1 |
| Domain Graph | 结构化数据（CSV）→ 可用 pattern matching 查询的图 | L1 |
| Lexical Graph | 非结构化文本 → chunk + 向量 + 文本周边结构 | L1 |
| Subject Graph | 中间层：从 chunk 抽出的实体（subject-predicate-object），把词法图接到领域图 | L1 |
| Agent | "一种花哨的控制流算子"——循环里调 LLM 决定做什么，再由代码执行 | L2 |
| Multi-Agent System | 多 Agent 协作单一目标，分层：顶层管流程，子层管具体任务 | L2 |
| Agent Delegation vs Agent-as-Tool | Agent 间协作的两种方式：委派 / 把 Agent 当工具调用 | L2 |
| Critic Pattern | 一个 Agent 提方案、另一个 Agent 批评，内部循环自我改进 | L2/L7 |
| Google ADK | 本课用的 Agent 开发框架（Agent / Runner / SessionService / tools） | L3 |
| Graph Construction Plan | 结构化侧产出物：不是图，而是"如何建图"的说明 | L2 |
| Knowledge Extraction Plan | 非结构化侧产出物：描述"能从文本抽哪些实体和事实" | L2 |

## 课程路线表

| Lesson | 主题 | 关键产出 |
|---|---|---|
| L1 | 知识图谱结构与数据集 | 关系表→图的直觉、Cypher、domain/subject/lexical 三层图、家具制造根因分析场景 |
| L2 | 多 Agent 系统设计详解 | Agent 定义、分层架构大图、User Intent → File Suggestion → Schema Proposal 工作流 |
| L3 | Google ADK 基础（单 Agent） | 用 Agent/Runner/SessionService 造并跑 hello_agent，AgentCaller 助手类 |
| L4 | Agent 团队（root + 子 Agent） | root agent + say_hello / say_goodbye 子 agent，共享 context |
| L5 | User Intent Agent | 对话澄清用户目标，把目标写入 memory（`user_intent.md`） |
| L6 | File Suggestion Agent | 依据目标从磁盘文件里挑出相关文件（`file_suggestion.md`） |
| L7 | Schema Proposal Agent（Critic 对） | 提议 + 批评循环，产出 Graph Construction Plan（`schema_proposal_*.md`） |
| L8 | 图谱构建工具 | 把 plan 执行成真图：建 domain graph、chunk+embed、抽实体接线（`kg_construction_*.md`） |
| L9–L10 | 非结构化 / GraphRAG | Lexical/Subject Graph 构建、用图谱回答问题的 GraphRAG Agent |

> **架构师视角**：这门课真正教的不是"怎么写 Cypher"，而是**如何把一段人类专家的判断流程（澄清需求→选数据→定 schema→落库）编排成可复用、可检查点介入的 Agent 管线**。注意讲师反复强调每个 Agent 的"输出物"（user goal / 文件清单 / Construction Plan）——这些中间产物才是多 Agent 系统的骨架。图谱只是最终副产品，plan 才是资产。

> **对比《Knowledge Graphs for RAG》(Neo4j C1)**：C1 是同厂商前置课，教你**手写 Cypher、手动**把文档/结构化数据建成图并做 GraphRAG。本课 C2 是进阶：把"手动建图"这件事**交给多 Agent 自动完成**，你从"写图的人"升级为"设计造图流水线的人"。技术底座（Neo4j + Cypher + 向量索引）一致，抽象层级抬高一层。

> **记忆点（引出 L1）**：本课的终态是一张由三块子图（domain / subject / lexical）拼成的知识图谱，由一队 ADK Agent 自动建出。L1 先退回最基础的问题——**知识图谱到底是什么、凭什么比关系库的 join 更适合"推荐/根因"这类多跳查询**——并交代贯穿全课的家具制造商数据集。

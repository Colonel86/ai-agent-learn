# L3 · 语义搜索翻车的五类输入（tokenization 的实战陷阱 + payload filter 救场）

> 课程：Retrieval Optimization（DeepLearning.AI × Qdrant，C1）· Lesson 3
> 本课任务：用真实输入（emoji / 错字 / 产品型号 / 数字 / 日期）暴露"语义搜索万能"的迷思，看 tokenization 如何在输入端就决定成败；再连上 Qdrant，用 **payload filter** 解决向量搜索管不住的硬约束。

## 0. 一个反直觉的前提

选对 embedding 是可靠语义搜索的关键，**但无论选哪个模型，总有些关系是向量捕捉不好的**，而且往往反直觉。根因回到 tokenization：它会把词切成多片，改变 transformer 的真实输入。

- 子词 token 若有清晰意义，在 input embedding 层就被捕获；
- 但**短/罕见 token 会在各种上下文出现**，模型难学到好的表示——尤其是那些**跨不同词的前缀/后缀**，本身无特定意义，对应 embedding 只能"覆盖各种上下文"，于是模型捕捉语义的能力受限。
- 论文 *Investigating the effectiveness of BPE: the Power of Short Sequences* 指出：**算法覆盖测试集所需的 token 越少，结果可能越好**。（呼应 L2："平均切成几个 token"是可优化指标）

下面五类是"语义搜索的神话"最常翻车的地方。全程先用 L1/L2 的 `all-MiniLM-L6-v2`（sentence-transformer），再换 OpenAI 对照。

## 1. 五类问题输入（sentence-transformer 视角）

```python
from sentence_transformers import SentenceTransformer, util
sbert = SentenceTransformer("all-MiniLM-L6-v2")
tok = sbert.tokenizer._tokenizer   # 拿到底层 tokenizer 看切法
```

### ① Emoji —— 变成 unknown，情绪全丢

```python
tok.encode("I feel 😊").tokens   # 😊 不对应任何有意义 token
tok.encode("I feel happy").tokens # 用文字 happy 才有对应 token
tok.encode("I feel 🙁").tokens   # 😊 和 🙁 都变成【同一个】unknown token！
tok.encode("I feel sad").tokens
```
若两文档只差这一个 emoji，则 transformer 输入**完全相同**——开心和难过无从区分。**要用在社媒数据上，先查有多少 unknown token。**

### ② 产品型号/领域术语 —— 被切成一堆碎片

```python
tok.encode("Broadcom BCM2712").tokens
# BCM2712（Raspberry Pi 的处理器）被切成多个子词 token，
# 用户按型号搜时，很难把它排进结果
```

### ③ 错字 —— 少一个字母，整串 token 全变

```python
for s in ["Great accommodation", "Great acommodation"]:  # 少一个 c
    print(tok.encode(s).tokens)
# 漏掉双 c，整个词被切成完全不同的一组 token
```

### ④ 数字/价格 —— token 重叠度 ≠ 数值接近

```python
for s in ["This shirt costs $55.", "This shirt costs fifty five dollars.",
          "This shirt costs $50.", "This shirt costs $559.",
          "This shirt has a 10% discount from $60."]:
    print(tok.encode(s).tokens)
# token 重叠度最高的是第 1 句($55) 和第 4 句($559)——尽管价格天差地别
```

### ⑤ 日期 —— 同一天不同格式，token 最不像

```python
for s in ["16th February 2024", "2024-02-16", "17th February 2024", ...]:
    print(tok.encode(s).tokens)
# 前两条是【同一天】，却因格式不同，token 上彼此最不相似
```

## 2. 从 token 到相似度：陷阱确实传导到向量

实践中很少给单词算 embedding，多是句/段，单 token 影响被稀释——但某些情况仍显著。用 heatmap 看 output text embedding 的 cosine：

```python
import plotly.express as px
sentences = ["I feel 😊", "I feel happy", "I feel 🙁", "I feel sad"]
emb = sbert.encode(sentences)
px.imshow(util.cos_sim(emb, emb), x=sentences, y=sentences, text_auto=True)
```

sentence-transformer 的结果印证了 token 层的问题：

| 输入类型 | 现象 |
|---|---|
| Emoji | 😊/🙁 都编码成 unknown，开心难过没区别 |
| 错字 | `accommodation` vs `acommodation` 相似度不高——虽然人一眼看出同义 |
| 数字 | token 重叠最大者相似度最高：`$55`→`$559` 被判"意义没差多少" |
| 日期 | 同格式相似度最高；**同一天不同格式相似度反而最低** |

**关键方法论**：这些问题**不一定对所有模型都成立**，所以**评估才重要**——不评估就不知道哪类 query 根本不被支持。

## 3. 换 OpenAI embedding 对照：好一些，但没全解

```python
import tiktoken
# tiktoken 是 OpenAI 对 BPE 的快速实现
oai_tok = tiktoken.encoding_for_model("text-embedding-3-large")
oai_tok.n_vocab           # 词表约为 sentence-transformer 的 3 倍

oai_tok.decode_tokens_bytes(oai_tok.encode("I feel 😊"))
# emoji 被转成【字节级】token（不像 sbert 直接 unknown），处理更好
```

对照结论：

| 类型 | OpenAI 表现 |
|---|---|
| Emoji | 支持——同一情绪的 emoji 与其文字描述保持最高相似度 |
| 型号 BCM2712 | 训练里出现不多，但表示不一定差 |
| 错字 | 相似度明显高于 sentence-transformer |
| 数字 | 处理明显更好，但**不保证泛化到所有数字** |
| 日期 | **不同格式仍有问题，得靠归一化单独解决** |

> 别以为上了 OpenAI embedding 就万事大吉——还是要做评估。**日期/数字这类结构化信息，正确做法是归一化（normalization）**，而不是指望向量。

## 4. payload filter：语义搜索管不住硬约束

"Semantic search is not all you need"——领域特有的硬约束（价格上限、日期范围）向量搜索**不保证满足**。连 Qdrant 演示：

```python
from qdrant_client import QdrantClient, models
import uuid
client = QdrantClient("http://localhost:6333")

# 建 collection：384 维（sentence-transformer 输出），cosine 距离
client.create_collection("clothes",
    vectors_config=models.VectorParams(size=384, distance=models.Distance.COSINE))

# upsert：每个 point = id + vector + payload(元数据)
client.upsert("clothes", points=[
    models.PointStruct(
        id=uuid.uuid4().hex,
        vector=sbert.encode(description),
        payload={"description": description, "price": price},  # 价格存进 payload
    ) for description, price in examples])
```

**纯语义搜索——它擅长的场景**（query 词和文档零重叠也能召回）：

```python
client.search("clothes", query_vector=sbert.encode("for cold weather"),
              with_payload=True, limit=3)
# 语义搜索在此胜过词法搜索——"cold weather" 从没出现在商品描述里，照样召回冬装
```

**加硬约束——纯语义直接翻车**：

```python
client.search("clothes",
    query_vector=sbert.encode("for cold weather under $40"),  # 想要 <$40
    with_payload=True, limit=3)
# ❌ 价格约束没被遵守——语义搜索不保证捕获 "under $40"
```

**正解：payload index + filter**：

```python
# 给要过滤的字段建 payload index，让过滤高效
client.create_payload_index("clothes", field_name="price",
                            field_schema=models.PayloadSchemaType.FLOAT)

client.search("clothes",
    query_vector=sbert.encode("for cold weather"),  # 语义部分只留 "cold weather"
    with_payload=True, limit=3,
    query_filter=models.Filter(must=[            # 硬约束交给 filter
        models.FieldCondition(key="price", range=models.Range(lte=40.0))
    ]))
# ✅ 所有结果都 ≤$40——这是唯一能保证约束的方式
```

**剩下的挑战**：怎么从自然语言 query 里**抽出这些 filter**？三条路——改 UI 让用户显式选、上 NLP 抽取、或**用 LLM 把约束抽成结构化输出**（讲师说 LLM 会很擅长这个）。

## 5. 本课总结

| 要点 | 一句话 |
|---|---|
| 五类陷阱 | emoji→unknown、型号→碎片、错字→整串变、数字→重叠≠接近、日期→同天不同格式最不像 |
| 根因 | 短/罕见/前后缀 token 无稳定语义；覆盖测试集所需 token 越少往往越好 |
| 模型有别 | OpenAI 对 emoji/错字/数字更好，但日期仍需归一化；**必须评估** |
| 归一化 | 数字/日期这类结构化信息该在入库前归一化，别指望向量 |
| payload filter | 硬约束（价格/日期范围）用 metadata index + filter 保证，语义搜索管不了 |
| filter 抽取 | 从 query 提约束靠 UI 改造 / NLP / LLM 结构化输出 |

> **架构师视角**：这课给出一条**混合检索**的落地判据——**"软意图走向量，硬约束走 filter"**。价格、日期、库存、权限这类必须精确满足的条件，绝不能塞进语义相似度里赌，要落到 payload/metadata index 上做确定性过滤。这正好补齐我 `3-retrieval.md` 里"向量库选型"之后的一层：选型要看**该库是否有 metadata index 与 filter 能力**（Qdrant 有，且建议对 filter 字段建 index 保效率）。而"query→结构化 filter"这一步，是 embedding 检索与 Agent/LLM 的接缝——LLM 抽 filter 属于工具/查询规划范畴。

> **对比已学课程 06 Advanced Retrieval**：课程 06 的"Similarity ≠ Relevance"给了检索后修法（rerank / query expansion）；本课证明**有些 relevance 缺口在输入端就无法用相似度弥补**（emoji/日期/硬约束），必须换机制——归一化或 filter。两课合起来是完整的"相关性缺口地图"：输入端（tokenizer/归一化）→ 检索中（filter）→ 检索后（rerank）。

> **记忆点（引出 L4）**：本课反复说"必须评估，否则不知哪类 query 不被支持"，但**怎么量化搜索质量**还没讲。L4 转入 information retrieval 的度量——"You can't improve what you don't measure"，介绍 precision / recall / MRR / NDCG 等最常用指标，为后面 HNSW / 量化的优化建立度量基线。

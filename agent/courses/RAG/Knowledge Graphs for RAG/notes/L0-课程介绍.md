# L0 · 课程介绍：用知识图谱升级 RAG 的检索层

> 课程：Knowledge Graphs for RAG（DeepLearning.AI × Neo4j）
> 讲师：Andreas Kollegger（Neo4j 生成式 AI developer evangelist）；Andrew Ng 参与开场对谈。致谢名单：Zachary Blumenfeld（Neo4j），Tommy Nelson、Jeff Lardwig（DeepLearning.AI）。

## 一句话定位

**核心问题**：基础 RAG 的检索只有一招——把文档切成 chunk、embedding 成向量、用 cosine similarity 按"语义相似"找相关文本。这一招找得到"长得像问题的 chunk"，但看不见 chunk 之间、文档之间的**关联结构**——相似度检索会漏掉文本来源之间的连接（connections between text sources that similarity-based RAG can miss）。

**本课答案**：把文本 chunk 存进**知识图谱（Knowledge Graph）**。图谱用节点（node）和边（edge）组织数据——对比关系型数据库的表/行/列，图结构建模"世界的某些部分"更灵活，也让**深层关系（deep relationships）**的表示与检索更容易、查询执行更快（web 搜索引擎和电商产品搜索早已把知识图谱当核心技术；在 Google/Bing 搜一个名人，侧边卡片就是从知识图谱取出来的）。图谱与 embedding 模型结合后，检索不再只有相似度一条路：**先按向量相似命中一个 chunk，再沿图上的关系和 metadata 扩展**，把更相关的文本交给 LLM。

**载体数据集**：SEC 表单（美国证券交易委员会申报文件）。先为一组 SEC 表单构建知识图谱并用 LangChain 做图谱检索的 RAG；再对第二组表单重走一遍构图流程，用 linking data 把两个图谱连起来，最后用更复杂的图查询做**跨多组文档**的检索问答。

> **架构师视角**：这门课改的是 RAG 三层里的**检索层**，而且不是"换一个向量库"，是换检索的**数据模型**——向量索引只回答"哪些 chunk 和问题像"，图谱额外回答"这个 chunk 属于谁、连着谁"。判断要不要上 GraphRAG 的第一问就是：你的问题是否依赖 chunk 之间的关系（跨文档、跨实体、时间线），还是单点相似就够。

## 核心概念/类比

| 概念 | 类比 | 一句话 |
|---|---|---|
| Knowledge Graph | 用"关系网"而不是"表格"存数据 | 节点 + 边的图结构，对比关系型数据库的表/行/列 |
| 节点/边上的信息 | 名片（节点）+ 合同（边） | person 节点存姓名/邮箱，company 节点存员工数/年营收，雇佣关系这条边存职位/入职日期 |
| 基础 RAG | 按"长得像"翻书 | 文档切 chunk → embedding → cosine similarity 找相关文本 |
| 图谱化 RAG | 先翻到一页，再顺着交叉引用读 | 相似度命中一个 chunk 后，沿关系和 metadata 扩展检索 |
| 深层关系检索 | 顺藤摸瓜 | 图结构让多跳关联的查询更快、更直接（搜索引擎名人卡片同款技术） |

## 课程路线

| 课 | 对应转写 | 一句话预告 |
|---|---|---|
| L1 | （概念课） | 知识图谱是什么：节点、关系、标签、属性 |
| L2 | query_with_cypher | 用 Cypher 查询语言操作图谱 |
| L3 | prep_text_for_RAG | 为 RAG 准备文本：chunk 化与向量化 |
| L4 | construct_kg_from_text | 从 SEC 表单文本构建知识图谱 |
| L5 | add_relationships_to_kg | 给图谱补上关系，用 LangChain 做图谱检索的 RAG |
| L6 | expand_the_kg | 第二组 SEC 表单重走构图流程，用 linking data 连接两个图谱 |
| L7 | chat_with_kg | 复杂图查询跨多组文档检索，与图谱对话问答 |

> **对比《Knowledge Graphs for AI Agent API Discovery》（SAP）**：刚学完的 SAP 课与本课是**知识图谱两大技术路线**的绝佳对照——SAP 课用 **RDF 三元组 + SPARQL**（W3C 标准栈，rdflib 内存构图），本课用 **Neo4j 属性图（LPG）+ Cypher**（数据库产品栈）；SAP 课的源数据是结构化 API 规范（确定性 ETL 构图、零幻觉），本课的源数据是**非结构化文本**（SEC 表单），要走"chunk → 抽取 → 构图"的路，正是 3-retrieval.md 里 GraphRAG 的典型形态。两门课合起来覆盖了"图谱选型"的完整光谱。

> **记忆点（引出 L1）**：Andreas 收尾说，学完这门课，你的系统能靠知识图谱更好地"理解"数据。而一切的地基是先说清楚：**图谱里的节点和关系到底是什么**——L1 从"nodes are data records"这句话开始，用三个节点三条关系画出一个最小图谱。

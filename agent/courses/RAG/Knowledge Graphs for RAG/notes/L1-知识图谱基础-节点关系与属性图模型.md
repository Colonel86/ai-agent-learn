# L1 · 知识图谱基础：节点、关系与属性图模型

> 课程：Knowledge Graphs for RAG（DeepLearning.AI × Neo4j）
> 本课任务：从"nodes are data records"这句话出发，手绘一个 3 节点 3 关系的最小图谱，把属性图（LPG）模型的四个要素——节点、关系、标签（label）、属性（property）——一次讲透。纯概念课，无代码。

## 0. 本课路线

L0 已经引入了知识图谱的想法，本课把这些概念展开看细节。路线：**① 节点是数据记录 → ② 关系也是数据记录 → ③ 逐步画出一个最小图谱 → ④ 形式化定义（label / property / type / direction）**。

## 1. 节点是数据记录（nodes are data records）

理解知识图谱最好的方式是直接画一个。第一步：画一个圆圈代表一个 person——"那就是我（Andreas）"。想在 Slack 频道里用纯文本聊这个图，就用**圆括号**表示节点：

```
(Person)          ← 圆括号 ≈ 画出来的圆圈，表示一个节点
```

这套文本表示法不是随手约定——它就是下一课 Cypher 查询语言的语法雏形。

## 2. 关系也是数据记录（relationships are data records）

只有"东西"不成图，还要有东西之间的**关系**。关键认知：**关系和节点一样，也是数据记录**——不只是一根连线，它自身能携带信息。

第一条关系：person Andreas **KNOWS** person Andrew，而且 knows **since 2024**：

```
(Andreas:Person) -[:KNOWS {since: 2024}]-> (Andrew:Person)
   ↑圆括号=节点        ↑关系带类型和属性          ↑圆括号=节点
```

### 术语对照：为什么叫 relationship 不叫 edge

| 图论术语 | 本课术语 | 说明 |
|---|---|---|
| vertex（顶点） | **node** | 同一个概念的不同叫法 |
| edge（边） | **relationship** | 同一个概念的不同叫法 |

不同的词、完全相同的概念。但作为**数据结构**，用 relationship 而不用 edge 是有理由的：relationship 实际上是"**一对节点 + 关于这对节点的信息**"——比如 KNOWS 关系里装着 Andreas 和 Andrew 这对节点，外加 since 2024 这条信息。edge 一词只表达"连着"，relationship 强调"这条连接本身是个有内容的记录"。

## 3. 把最小图谱画完整：3 节点 + 3 关系

继续扩展：Andreas 和 Andrew 除了互相认识，还有一个共同点——这门课（RAG with Knowledge Graphs）。Andreas **教**这门课，Andrew **介绍**（introduce）了这门课：

```
(Andreas:Person) --[:KNOWS {since:2024}]--> (Andrew:Person)
        │                                        │
  [:TEACHES {year:2024}]           [:INTRODUCES {section:...}]
        │                                        │
        └────────────> (Course) <────────────────┘
              "RAG with Knowledge Graphs"
```

写成一行文本模式（pattern）会更长，但值得逐段读一遍：

```
(:Person)-[:TEACHES]->(:Course)<-[:INTRODUCES]-(:Person)
   从左往右：person 教 course      从右往左：person 介绍 course
                        两个箭头在中间的 course 汇合
```

方向可以从左到右、也可以从右到左，两个方向在中间的 course 节点相遇——文本模式能自然表达这种"汇合"结构。

### 建模小课：身份用关系表达，不加多余标签

可以给 Andreas 加个 "teacher" 标签、给 Andrew 加个 "introducer" 标签吗？可以，但**不需要**：Andreas 是 teacher **因为他在 teaching**，Andrew 是 introducer **因为他做了 introduction**——身份已经由关系表达了，再往节点上叠标签是冗余建模。

> **架构师视角**：这条建模原则的价值在 schema 演化——"角色"是随关系产生和消失的（明年 Andreas 不教了，删一条 TEACHES 边即可），把角色固化成节点标签就要维护两处一致性。通用判断：**易变的、由行为派生的身份放关系，稳定的、本质性的分类放标签**。这和关系型建模里"不要把可推导列物化"是同一直觉。

## 4. 形式化定义：label、property、type、direction

小图画完，把四个要素正式定义一遍：

| 要素 | 属于谁 | 定义 | 本课示例 |
|---|---|---|---|
| **label** | 节点 | 把多个节点归成一组的分组机制 | `Person`、`Course` |
| **property** | 节点 & 关系 | 存在记录内部的 key-value 键值对 | person 的 name；KNOWS 的 `since: 2024` |
| **type** | 关系 | 每条关系必有且只有一个类型 | `KNOWS` / `TEACHES` / `INTRODUCES` |
| **direction** | 关系 | 每条关系必有方向 | Andreas ─KNOWS→ Andrew |

三条关系各自的属性，正好展示"关系是数据记录"：

- `KNOWS {since: 2024}`——认识自 2024 年；
- `TEACHES {year: 2024}`——2024 年教授；
- `INTRODUCES {section: ...}`——介绍的是课程的哪个 section。

**本课的知识图谱定义**（原话复述）：

> A Knowledge Graph is a **database** that stores information in **nodes** and **relationships**. Both nodes and relationships can have **properties**（key-value pairs）, and nodes can be given **labels** to help group them together. Relationships always have a **type** and a **direction**.

注意第一个词：**database**。Neo4j 语境下知识图谱不是内存里的抽象结构，而是一个可持久化、可查询的数据库。

> **对比《Knowledge Graphs for AI Agent API Discovery》的 RDF 模型**：这是两种图谱数据模型的分野点。RDF 里**一切都是三元组**（subject–predicate–object），节点没有"内部属性"——person 的 name 也是一条独立三元组；而且 RDF 的边（predicate）本身**不能直接挂属性**，要表达 "knows since 2024" 得靠 reification 或 RDF-star 绕路。LPG（Labeled Property Graph）则把节点和关系都当成**自带 key-value 属性的数据记录**，`{since: 2024}` 直接挂在关系上，建模直觉更接近对象/文档。代价是：RDF 有 W3C 标准、全局 URI 和跨库互操作（SAP 课的强项），LPG 是产品生态（Neo4j/Cypher），标准化在 GQL 之前长期靠事实标准。选型口诀：**要联邦互操作和本体推理选 RDF，要开发效率和路径查询性能选 LPG**。

## 5. 本课总结

| 要点 | 一句话 |
|---|---|
| 节点是数据记录 | 圆括号 `(Person)` 表示节点，内部可存 key-value 属性 |
| 关系是数据记录 | 不是一根线，是"一对节点 + 关于这对的信息"，故叫 relationship 不叫 edge |
| 文本模式 | `(:Person)-[:TEACHES]->(:Course)<-[:INTRODUCES]-(:Person)`，箭头可双向汇合 |
| 建模原则 | 行为派生的身份用关系表达，不给节点叠冗余标签 |
| 形式化定义 | 知识图谱 = 存节点和关系的数据库；label 分组节点，property 挂两者，关系必有 type + direction |

> **记忆点（引出 L2）**：本课的圆括号、方括号、箭头文本表示法，其实就是 **Cypher** 的模式语法——画在纸上的图怎么写成文本，查询就怎么写。L2（query_with_cypher）正式引入 Cypher 查询语言，用它在真实的 Neo4j 图谱上做增删查改。

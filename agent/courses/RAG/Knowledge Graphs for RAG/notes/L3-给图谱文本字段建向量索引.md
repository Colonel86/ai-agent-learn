# L3 · 给图谱文本字段建向量索引（genai.vector.encode + 库内相似度检索）

> 课程：Knowledge Graphs for RAG（DeepLearning.AI × Neo4j）
> 本课任务：RAG 靠向量表示把 prompt 匹配到相关文本。要让知识图谱也具备这个能力，就得给图里的文本字段（电影 tagline）算 **embedding**、建**向量索引**，然后直接在 Neo4j 里做相似度检索。

## 0. 三步路线 + 环境增量

流程只有三步：**① 建向量索引 → ② 算 embedding 填充索引 → ③ 相似度查询**。

环境与 L2 唯一的增量是 `OPENAI_API_KEY`——因为 embedding 由 OpenAI 模型计算：

```python
OPENAI_API_KEY = os.getenv('OPENAI_API_KEY')
# 下面这行是课程环境特有的代理 endpoint，自己环境不需要
OPENAI_ENDPOINT = os.getenv('OPENAI_BASE_URL') + '/embeddings'

kg = Neo4jGraph(url=NEO4J_URI, ...)   # 连接方式与 L2 完全相同
```

## 1. 第一步：CREATE VECTOR INDEX

向量索引和普通索引一样是 schema 对象，用 Cypher DDL 声明：

```cypher
CREATE VECTOR INDEX movie_tagline_embeddings IF NOT EXISTS
FOR (m:Movie) ON (m.taglineEmbedding)     -- 索引 Movie 节点的 taglineEmbedding 属性
OPTIONS { indexConfig: {
  `vector.dimensions`: 1536,              -- OpenAI embedding 模型默认维度
  `vector.similarity_function`: 'cosine'  -- OpenAI 官方推荐余弦相似度
}}
```

四个要素：索引名、`IF NOT EXISTS` 幂等、作用对象（label + 属性）、两项关键配置（**维度**必须与 embedding 模型一致、**相似度函数**）。建完用 `SHOW VECTOR INDEXES` 验证——看到 state 就绪、type 为 VECTOR 即可。

## 2. 第二步：genai.vector.encode 填充索引

索引建好还是空的，要给每部电影的 tagline 算 embedding 存进节点属性：

```cypher
MATCH (movie:Movie) WHERE movie.tagline IS NOT NULL   -- 没 tagline 的跳过
WITH movie, genai.vector.encode(
    movie.tagline,                     -- 要编码的文本
    "OpenAI",                          -- 用哪家 embedding 模型
    { token: $openAiApiKey,            -- $xxx 是查询参数，key 不硬编码进查询
      endpoint: $openAiEndpoint }
  ) AS vector
CALL db.create.setNodeVectorProperty(movie, "taglineEmbedding", vector)
-- 把算出的向量写入节点的 taglineEmbedding 属性
```

```python
kg.query(上面的查询, params={"openAiApiKey": OPENAI_API_KEY,
                             "openAiEndpoint": OPENAI_ENDPOINT})
# 要跑几秒——每部电影都要调一次 OpenAI API
```

两个关键机制：

- **`genai.vector.encode(文本, 提供商, 配置)`**：Neo4j 内置函数，**由数据库出面调用 OpenAI API** 算 embedding；
- **查询参数（`$` 前缀）**：Python 侧 `params={...}` 字典传入，查询里用 `$openAiApiKey` 引用——密钥、用户输入都走参数而不是字符串拼接。

验证三连（取一条回来肉眼看）：tagline 是 "Welcome to the Real World"（The Matrix）；`taglineEmbedding[:10]` 看前 10 个浮点数长得像正经向量；`len(...) == 1536` 维度对得上。

> **架构师视角**：这是 **"计算下推（in-database embedding）"** 路线——embedding 的计算和存储都发生在数据库内，应用侧一行 Python 向量代码都没有。好处是管道极短、文本和向量天然同处一节点、不会出现"向量库和源数据不同步"这一 RAG 经典事故；代价是被数据库支持的 provider 列表绑死、批量调用的重试/限速控制不如自建管道精细。与之相对的是 3-retrieval.md 的主流架构：应用侧算 embedding → 写独立向量库（还要自己维护 chunk↔源数据的引用一致性）。数据本来就在图里时，库内方案是运维上更省心的默认。

## 3. 第三步：相似度检索（similarity search）

问题本身也要变成向量，然后查索引找最近邻：

```python
question = "What movies are about love?"
```

```cypher
WITH genai.vector.encode(
    $question, "OpenAI",
    { token: $openAiApiKey, endpoint: $openAiEndpoint }
  ) AS question_embedding                 -- ① 问题 → 向量（和填充用同一函数）
CALL db.index.vector.queryNodes(
    'movie_tagline_embeddings',           -- ② 查哪个索引
    $top_k,                               --    要几个最近邻（这里 5）
    question_embedding
  ) YIELD node AS movie, score            -- ③ 产出命中节点 + 相似度分数
RETURN movie.title, movie.tagline, score
```

结果按 score 降序：Joe vs. the Volcano、Snow Falling on Cedars……从 tagline 看确实都是关于 love 的电影。换个问题 `"What movies are about adventure?"` 重跑同一查询：Cast Away、Ninja Assassin、Joe vs. the Volcano——语义匹配生效。

注意此时的检索单元是**节点**（`queryNodes`）：命中的不是一段裸文本，而是图里一个还带着所有关系的 Movie 节点——这是"向量检索落在图上"与"向量检索落在向量库里"最本质的差异，后面课程（L5-L7）会靠这一点从命中节点沿边扩展上下文。

> **对比课程 04/05 的经典 RAG 管道**：LangChain Chat with Your Data 的标准流水线是 Load → Split → **应用侧 Embed → 独立 VectorStore（Chroma）** → Retrieve；本课把 Embed 和 Store 两步整个搬进 Neo4j，一条 Cypher 完成"问题编码 + Top-K 检索"。组件更少，但也意味着检索逻辑写在 Cypher 里而非可插拔的 Retriever 抽象里——L4 会用 LangChain 的 `Neo4jVector` 把它重新包回 Retriever 接口，两边接轨。

## 4. 本课总结

| 要点 | 一句话 |
|---|---|
| 三步流程 | 建向量索引 → encode 填充 → queryNodes 检索 |
| CREATE VECTOR INDEX | 声明式 DDL：label + 属性 + 维度 1536 + cosine |
| genai.vector.encode | 数据库内置函数，由 Neo4j 出面调 OpenAI 算 embedding |
| 查询参数 | `$param` + `params={}`，密钥/用户输入不拼字符串 |
| db.index.vector.queryNodes | 索引名 + top_k + 问题向量 → YIELD node, score |
| 检索单元 | 命中的是带关系的图节点，不是孤立文本块 |

> **记忆点（引出 L4）**：本课是在**别人建好的图**上加向量能力，文本还只是现成的短 tagline。真实 RAG 应用得**从零构建**：拿到成千上万字的原始文档（SEC Form 10-K），自己 chunking、自己建 Chunk 节点、自己建索引算 embedding，最后接上 LLM 组成完整问答链——L4 把这条从文本到知识图谱的构建管道完整走一遍。

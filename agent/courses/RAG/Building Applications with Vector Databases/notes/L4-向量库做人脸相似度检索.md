# L4 · 向量库做人脸相似度检索（DeepFace/FaceNet + Pinecone）

> 课程：Building Applications with Vector Databases（DeepLearning.AI × Pinecone）· Lesson 05
> 本课任务：用**人脸向量嵌入**回答一个古老问题——孩子长得更像爸爸还是妈妈？以英国王室为例，用"科学方法"判定 Prince William 更像 King Charles 还是 Princess Diana。方法可直接套到自己家的照片上。

## 0. 从 L3 衔接：同一套向量库，第五种应用

L3 的 hybrid search 把 dense（CLIP）与 sparse（BM25）两路向量塞进同一个 Pinecone 条目，解决"语义 + 关键词"的时装检索。到本课，**输入模态从文本/图文换成纯人脸图像**，但底座没变：编码成向量 → upsert 进 Pinecone → 用相似度查询。这正是本课的立意——向量数据库远不止 RAG，人脸比对也是它的自然应用。

本课路线四步：**① 人脸 → 向量嵌入 → ② 存入 Pinecone → ③ t-SNE 可视化验证聚类 → ④ 用平均相似分裁决"更像谁"**。

## 1. 技术栈与数据集

| 组件 | 选择 | 说明 |
|---|---|---|
| 人脸嵌入库 | **DeepFace**（开源） | 内置多种人脸模型的统一封装 |
| 嵌入模型 | **FaceNet** | 输出 **128 维**向量 |
| 数据集 | **Families in the Wild** | 公开的家庭人脸数据集（课程附链接） |
| 向量库 | Pinecone | 存嵌入 + 相似度查询 |

数据集解压后是三层目录：顶层 `family/`，下含 `dad/`、`mom/`、`child/` 三个子目录，分别对应 King Charles、Princess Diana、Prince William 的多张照片。用 `wget`（quiet + 进度条）拉取 `family_photos.zip` 再解压——但 notebook 里已经预下载好，下载那行保持注释以免误触发。

一个 `show_image` 辅助函数把图片略微 resize 后本地显示，先肉眼看一眼三个人各自的样子。

## 2. 生成嵌入并落盘为 vectors.vec

思路：每个人的照片用 glob 全部取出，逐张过 DeepFace 生成 128 维嵌入，写进一个中间文件 `vectors.vec`。**为什么先写文件？因为后面要多次遍历这批数据**（可视化一次、upsert 一次），落盘避免重复算嵌入。

```python
# 口播摘录：先清掉旧文件保持干净，再逐人逐图生成嵌入写盘
with open("vectors.vec", "w") as f:
    for person in ["dad", "mom", "child"]:
        images = glob(f"family/{person}/*")   # 取该人全部照片
        for img in images:
            emb = DeepFace.represent(img, ...)  # FaceNet → 128 维
            # 行格式：person:图片名  后跟嵌入本身
            f.write(f"{person}:{img} {emb}\n")
```

文件格式很直白——`person:图片名 [嵌入向量]`，一行一图。`head` 一看：第一行是 mom 的某张 `P11...jpeg` 加它的 128 维向量。共约 **241 张图 → 241 条向量**。

> **架构师视角**：这里的 `vectors.vec` 是一层朴素的**嵌入缓存**。嵌入计算（尤其人脸/图像模型）是整条流水线里最贵的一步，把它与"写入向量库""可视化"解耦，是任何 embedding pipeline 都该有的分层——重算嵌入 vs. 重灌索引应该是两个独立可重跑的阶段。生产里这层缓存会换成对象存储或专门的 feature store，但形态一致。

## 3. t-SNE 可视化：先验证"每个人自己的照片聚成一簇"

灌库之前先画一张 t-SNE 散点图确认嵌入质量。两个降维概念：

- **PCA（主成分分析）**：把高维嵌入压到低维，保留大部分信息。常作 t-SNE 的**预处理**——先降维缓解维度灾难，再喂给 t-SNE，显著加速（t-SNE 本身在大数据上很慢且贵）。
- **t-SNE**：把高维数据映射到 2D/3D 做可视化，专门用来揭示高维空间里不易察觉的**聚类与关系**。
- **perplexity**：t-SNE 的关键超参，控制每个点在降维时考虑的邻居数。课程把它做成了可插拔参数。

流程：`gen_tsne_dataframe(person)` 遍历 `vectors.vec` 取某人的向量 → 对该人做 PCA 降维 → 再做 t-SNE → 返回 DataFrame；`plot_tsne(perplexity)` 调用前者，为 dad/child/mom 各配一种图例颜色后画散点。

```python
plot_tsne(perplexity=27)   # 第一次
plot_tsne(perplexity=44)   # 讲师："这类图通常要多跑几次调 perplexity"
```

**读图的正确姿势**（讲师反复强调）：要看的是**每个人自己的多张照片是否各自紧密聚成一簇**——一个点 = 一张 dad 的照片，dad 的点全挤在一起才说明"dad 的每张照片都像 dad"，child、mom 同理。**不要**去解读"child 和 mom 两簇靠得近"就断言长得像——散点相对位置在这里没有那种含义。

> **对比 Qdrant「Retrieval Optimization」课**：那门课把降维/量化（PQ、二值量化）当作**生产检索的压缩手段**——牺牲一点精度换存储与召回速度。本课的 PCA/t-SNE 是**诊断可视化手段**，只在 2D 平面上"看一眼"嵌入健不健康，从不回灌到索引。同是降维，一个进数据通路、一个只进人眼——别把可视化降维误当成检索优化。

## 4. 灌库：清空重建 + upsert

可视化通过后，清掉索引重建（clean slate），再遍历 `vectors.vec` 逐行 upsert：

```python
with open("vectors.vec") as f:
    for line in f:
        person_file, vec = line.split(" ", 1)   # 切出"person:图名"和向量串
        person, fname = person_file.split(":")
        vector = eval(vec)                        # 把存盘的向量串还原成 list
        index.upsert([(fname, vector, {"person": person, ...})])
```

`describe_index_stats` 确认 **241 条**，与之前 TQDM 的 241 次迭代吻合——灌库无遗漏。

## 5. 裁决"更像谁"：平均 top-K 相似分

核心是一个 `test(parent)` 例程：拿某个 parent（mom 或 dad）的一张随机图，去 Pinecone 查 **top-K** 最相似的 child 图，把返回的这 K 个相似分**取平均**当作该 parent 与 child 的接近度。

```python
def test(parent_vec, k):
    res = index.query(vector=parent_vec, top_k=k, ...)
    scores = [m.score for m in res.matches]   # Pinecone 每条 match 带一个相似分
    return sum(scores) / len(scores)          # 平均分作为"接近度"

# 对两条关系各跑一次，随机取一张 parent 图
dad_score = test(random_dad_image, k)   # → 0.43
mom_score = test(random_mom_image, k)   # → 0.35
```

结果：**dad（King Charles）0.43 > mom（Princess Diana）0.35** → Prince William 更像父亲。

**再深一步**：既然确定更像 dad，就找出 dad 阵营里**具体哪张照片最像 William**。取一张最能代表 William 成年样貌的基准图，生成嵌入，`query` 只在 dad 的图里取 **top 3**。Pinecone 返回的典型 JSON blob 含三件套：**vector `id` + `metadata` + `score`**。取最高分那张展示——即"最像 Prince William 的一张 King Charles 照片"。讲师本人也认同：确实很像。

> **架构师视角**：注意本课**没有训练任何模型**——DeepFace/FaceNet 是现成的通用人脸编码器，所有"智能"都落在**嵌入 + 向量相似度**上。"多张图取平均分"是把单点噪声抹平的朴素但有效的稳健化技巧（单张随机图可能角度/光照失真，平均后更可信）。这类"零训练、纯嵌入检索"的模式，正是向量库能承接远超 RAG 的应用面的原因——分类、去重、比对、推荐都能退化成"最近邻 + 一点聚合逻辑"。

## 本课总结

| 要点 | 一句话 |
|---|---|
| 应用形态 | 人脸相似度检索 = 通用人脸编码器 + 向量最近邻，零模型训练 |
| 嵌入 | DeepFace/FaceNet 输出 128 维，先落盘 `vectors.vec` 做缓存 |
| 可视化 | PCA 预降维 + t-SNE 画散点，只看"每人自己聚簇"，perplexity 需多试 |
| 裁决逻辑 | top-K 相似分取平均比大小，dad 0.43 > mom 0.35 |
| 结论 | King Charles 比 Princess Diana 更像 Prince William |

> **记忆点（引出 L5）**：本课把"**高相似**"当信号——找最像的那张脸。L5 反过来，把"**低相似**"当信号：在一堆规整的 Cisco ASA 日志里，相似度分数最低的那条就是**异常**。同一个 Pinecone 查询接口，取 top 还是取 bottom，就切换出"检索"与"异常检测"两种截然不同的应用。

# L2 · 用向量库做内容推荐（标题 vs 正文两种粒度）

> 课程：Building Applications with Vector Databases（DeepLearning.AI × Pinecone）
> 本课任务：用一份新闻数据集，先按**文章标题**建向量库做推荐，再按**文章正文**建一遍做推荐，对比同一个查询"Obama"在两种粒度下召回的结果差异——直观感受"embedding 的是什么，就决定了推荐的是什么"。

## 0. 本课目标与路线

推荐系统在这里的本质，和 L1 的检索是**同一个动作**：存一批向量，用查询向量取回最相似的若干条。区别只在"取回来干什么"——L1 拿去喂 LLM，本课直接当推荐结果展示。路线两段，刻意做对照实验：

```
第一段（标题粒度）：新闻标题 → embedding → Pinecone → query "Obama" → 推相似标题
第二段（正文粒度）：删库重建 → 文章正文切块 → embedding → query "Obama" → 推相似正文段
              └─ 同一个查询，两种粒度，结果不同
```

数据是 `all-the-news-3.zip`（wget 下载后解压，讲师照例注释掉下载过程）。用 pandas 读 CSV，关注两列：**title** 和 **article**。

## 1. 第一段：按标题建库

流程和 L1 同一套骨架（连接 Pinecone → index 存在则删再建 → 拿 index 指针），讲师直言"这已经是 boilerplate，复制粘贴即可"。默认相似度量是 **cosine**。

按 chunk 读 DataFrame（`chunk_size=400`，最多读 20,000 行），每块取出标题、批量 embedding、攒够 300 条 upsert 一次：

```python
for chunk in pd.read_csv('all-the-news-3.csv', chunksize=400, nrows=20000):
    titles = chunk['title'].tolist()          # 只取标题
    embeddings = get_embeddings(titles)        # 复用 L1 的 OpenAI 封装
    for i in range(len(titles)):
        prepped.append({
            'id': str(chunk_num*400 + i),      # chunk_num 递增保证 id 唯一
            'values': embeddings.data[i].embedding,
            'metadata': {'title': titles[i]},
        })
    chunk_num += 1
    if len(prepped) >= 300:                    # 攒够 300 写一批
        index.upsert(prepped); prepped = []
```

`describe_index_stats()` 核对：**20,000** 条标题向量入库。

## 2. 第一段查询：`get_recommendations` 辅助函数

推荐动作封成一个辅助函数——传入 Pinecone index、搜索词、`top_k`（默认 10），内部把搜索词 embedding 后跑 query：

```python
def get_recommendations(pinecone_index, search_term, top_k=10):
    embed = get_embeddings([search_term])
    res = pinecone_index.query(
        vector=embed.data[0].embedding,
        top_k=top_k, include_metadata=True)
    return res

reco = get_recommendations(index, 'obama')
for r in reco.matches:
    print(round(r.score, 2), r.metadata['title'])  # 相似度分 + 标题
```

结果：召回一批**标题里与 Obama 相关**的文章，如"Obama's been a much more effective communicator than he gives himself credit for""Parting message is a warning for Donald Trump"。注意——这是**标题层面**的相似匹配。

> **架构师视角**：推荐和搜索在向量库里是同一个 query，差别全在"查询向量从哪来"。搜索的查询向量来自用户输入的问句；推荐的查询向量来自"一篇已有物料"（item-to-item）或"用户画像"（user-to-item）。理解这一点，就不会为"搜索"和"推荐"各搭一套基础设施——它们共用同一个向量索引，换的只是查询侧。这正是 L0"一个能力派生六种应用"的又一次印证。

## 3. 第二段：按正文建库（引入切块 + 去重）

删掉旧 index 重建，这次 embedding 的是**文章正文**而非标题。正文很长，必须先切块——用 LangChain 的 `RecursiveCharacterTextSplitter`，块长 400 字符、重叠 20：

```python
from langchain.text_splitter import RecursiveCharacterTextSplitter
splitter = RecursiveCharacterTextSplitter(chunk_size=400, chunk_overlap=20)

for article, title in zip(articles, titles):
    if article is not None:
        chunks = splitter.split_text(article)   # 一篇正文 → 多个块
        embeddings = get_embeddings(chunks)      # 每块各自 embedding
        embed(embeddings, title, prepped, embed_num)  # 攒够 300 上传
```

`embed` 辅助函数负责把每块的向量塞进 `prepped`，满 300 就 upsert 再清空（和前面同一模式）。这次入库 **10,500** 条向量——注意条数变了：**一篇文章被切成多块，每块是一条向量**，所以条数不再等于文章数。

> **对比 3-retrieval 的 Chunking 策略**：本课用的是最朴素的定长切块（`RecursiveCharacterTextSplitter` 400/20）。`3-retrieval.md §四` 的谱系里这只是起点——按语义边界切之外，还有 SentenceWindow（嵌入粒度与喂 LLM 粒度解耦）、Auto-merging（命中子块合并父块）。本课在"正文推荐"里暴露的**同一篇文章多块召回**问题（下节），正是这些进阶策略要解决的痛点之一。

## 4. 正文查询：去重才能让推荐可读

正文切块带来副作用：同一篇文章的多个块都可能命中，推荐列表会**重复同一篇**。用一个 `seen` 字典去重——标题没见过才展示：

```python
seen = {}
reco = get_recommendations(index, 'obama', top_k=100)
for r in reco.matches:
    title = r.metadata['title']
    if title not in seen:
        print(round(r.score, 2), title)   # 首次见到才打印
        seen[title] = '.'                  # 标记已见，后续同篇跳过
```

结果：召回的是一批**与 Obama 相关的正文段落所属文章**，且**与第一段按标题查的结果明显不同**——因为这次匹配的是正文语义，而非标题字面。讲师强调"you'll see the results are different this time"，这正是本课的核心对照点。

```
同一查询 "Obama"：
  标题粒度  → 标题里出现 Obama 主题的文章（题面匹配）
  正文粒度  → 正文段落语义接近 Obama 的文章（内容匹配，需去重）
```

## 本课总结

| 要点 | 一句话 |
|---|---|
| 推荐=搜索 | 同一个向量 query，差别只在"查询向量从哪来" |
| 标题粒度 | embedding 标题 → 题面相似推荐，一文一向量，20k 条 |
| 正文粒度 | 正文切块（400/20）→ 内容相似推荐，一文多向量，10.5k 条 |
| 切块副作用 | 一文多块 → 同篇重复召回，用 `seen` 字典去重 |
| 核心对照 | embedding 的粒度 = 决定推荐语义的粒度，两者结果不同 |
| 相似度量 | 本课默认 cosine（对比 L3 混合搜索改用 dot product） |

> **记忆点（引出 L3）**：到这里所有召回都只用了一种向量——**dense 稠密向量**（语义相似）。但"dark blue French connection jeans"这类查询里既有语义（蓝色牛仔裤）又有需要精确匹配的专有名词（French Connection 品牌）。L3 引入 **hybrid search**：在同一条 Pinecone 记录里同时存 dense（CLIP，语义）和 sparse（BM25，关键词）两种向量，并用一个 **alpha 旋钮**在"语义 vs 关键词"之间连续调权重——相似度量也会因此从 cosine 换成 dot product。

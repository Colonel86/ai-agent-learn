# L0 · 课程介绍：Multi-vector Image Retrieval（多向量图像检索）

> 课程：Multi-vector Image Retrieval（DeepLearning.AI × Qdrant，C2）
> 讲师：Kacper Łukawski（Qdrant developer advocate、资深 AI 工程师）；开场 Andrew Ng
> 定位：Qdrant 与 DeepLearning.AI 合作的第二门课（C1 是《Retrieval Optimization》，讲 dense embedding / HNSW / ANN 基础）。本课把"多向量检索"从文本延伸到图像与复杂文档。

## 这门课解决什么问题

长期以来，把数据喂给 LLM 最省事的方式是只用**文本**——但这样会把大量藏在**图片、扫描件、PDF、幻灯片**里的有用信息挡在门外。而如今大家在用的多数"LLM"其实是 **VLM（Vision Language Model，视觉语言模型）**，它们处理图像的能力和处理文本一样强。瓶颈从来不在"模型能不能看图"，而在**能否准确且高效地把正确的图像检索出来**喂给 VLM。本课要讲的一族技术——**Multi-vector**——正是在补这一环。

## 单向量 vs 多向量：一句话对照

| | 单向量（standard / dense retrieval） | 多向量（multi-vector） |
|---|---|---|
| 表示粒度 | 每个文档/图像压成**一个大向量** | 用**许多个小向量**表示，如图像的每个 patch、文本的每个 token |
| 匹配方式 | query 向量与文档向量整体是否接近 | query 的每个 token 与图像每个 patch 做**细粒度匹配** |
| 擅长 | 快、可扩展到十亿级 | 复杂文档（文字+图表+幻灯片混排）下检索质量高 |
| 代价 | 存储省 | 向量爆炸 → 内存与搜索开销大 |

多向量存下这些细粒度信息，就能在**文本 query 的 token** 与**构成图像/文档的 patch** 之间做精细匹配——这正是它在复杂文档上表现好的原因。代价是存储所有这些向量会带来内存与搜索的挑战，本课后半程会讲专门缓解这些问题的新技术。

## 课程主线（四步）

```
① 文本打底    —— 用 ColBERT 理解多向量检索到底怎么工作（late interaction / MaxSim）
② 迁移到图像  —— ColPali 如何把这套思路搬到图像/文档检索
③ 优化性能    —— 量化 / 池化，压掉 ColPali 的内存开销
④ MUVERA      —— 把多向量与单向量各自的优点合到一起
```

每一步都是**概念 + 动手实现**交替：先讲清楚每种方法背后的基础原理，再把它们落进一个能跑的 **multimodal RAG 系统**。

## 前置知识

本课假设你已熟悉向量检索基础：dense embedding vector、vector similarity、approximate nearest neighbor（ANN）搜索、以及支撑它的 **HNSW 索引**。如果不熟，讲师建议先上 Qdrant 的第一门课（C1《Retrieval Optimization》）。

## 各课速览

| 课 | 主题 | 一句话 |
|---|---|---|
| L1 | ColBERT（文本多向量） | 用最常见的文本多向量技术 ColBERT 上手，理解 late interaction 与 MaxSim |
| L2 | ColPali（图像多向量） | 把多向量思路搬到图像/文档，跳过 OCR 与版面解析 |
| L3 | 内存优化 | 量化（scalar/binary）+ 池化（row/column/hierarchical）压缩 ColPali 向量 |
| L4 | MUVERA | 把变长向量序列转成定长嵌入，重新解锁 HNSW |
| L5 | 综合 multimodal RAG | 把前面的技术拼成能跑的系统 |

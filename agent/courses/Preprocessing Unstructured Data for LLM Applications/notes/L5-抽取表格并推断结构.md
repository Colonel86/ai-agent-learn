# L5 · 抽取表格并推断结构（Table Extraction：三法 + text_as_html + 摘要检索）

> 课程：Preprocessing Unstructured Data for LLM Applications（DeepLearning.AI × Unstructured）
> 本课任务：把文档里的**表格**抽出来并**推断其行列结构**，导出 `text_as_html`，再为表格生成摘要以便 RAG 相似度检索。

## 0. 承上：从整页版面到表格内部

L4 用 DLD/Vision Transformer 把整页拆成 Title、NarrativeText、Table 等 element——但**表格当时只是一个被框住的整体**，框内的行列关系还没还原。表格恰恰是很多文档（财报、论文）承载关键信息的地方：RAG 若读不懂表内数据，就答不了"第 X 项的数值是多少"。本课就补上这一层。

路线：① 为什么表格要单独处理 → ② 三种抽表技术 → ③ API 抽表 + `text_as_html` → ④ 表格摘要用于检索。

## 1. 为什么表格要单独处理

表格能让 RAG 应用取到"藏在表里"的信息。按文档类型分两种情况：

- **HTML / Word**：结构信息**内建**在文档里（如 HTML 的 `<table>` 标签）→ 直接用 **rules-based parser** 读行列；
- **PDF / 图片**：没有标签 → 必须**先用视觉线索定位表格**，再处理它、抽出结构。

本课聚焦后者（PDF/图片），学三种技术。

## 2. 三种抽表技术对照

| 技术 | 怎么做 | 优点 | 缺点 |
|---|---|---|---|
| **Table Transformer** | ① 先用 L4 的 DLD 检测出表格；② 把表路由给 table transformer，识别**每个单元格的 bounding box** 并转成 HTML | 单元格可回溯到原框，有逐格坐标 | 多次昂贵模型调用（多次 DLD + 多次 OCR） |
| **Vision Transformer** | 整表图片→模型，直出**HTML**（注意：L4 目标是 JSON，这里目标是 HTML） | 可 prompt、灵活、**单次**模型调用 | 生成式易幻觉、**不保留任何 bounding box** |
| **OCR + rules** | 对表格区域跑 OCR，再用规则后处理 OCR 结果，拼出 HTML 表 | 快，对"规整表格"够用 | 对复杂/不规整表容易崩 |

三者的产物都收敛到同一个东西：**表格的 HTML 表示**——因为 HTML 能把行列结构保留下来喂给 LLM。

> **对比 3-retrieval.md 的数据摄取**：向量检索的 ingestion 常把表格"拍平"成一行行文本，行列对应关系丢失，LLM 拿到一堆散落数字根本对不上表头。本课坚持**保留 `text_as_html`**，就是为了在 RAG 摄取阶段守住结构语义。这印证了 3-retrieval.md 的一条原则：**检索质量的上限在摄取阶段就被决定了**——摄取时丢掉的结构，检索/生成阶段再也补不回来。表格是这条原则最尖锐的体现。

## 3. 代码实操：API 抽表 + text_as_html

示例是一份**含嵌入图片和表格的复杂 PDF**，目标抽出其中 Table 1。抽表是 model-driven，走 Unstructured **API**。关键在两个参数：

```python
from unstructured_client.models import shared

with open("example_files/embedded-images-tables.pdf", "rb") as f:
    files = shared.Files(content=f.read(), file_name="embedded-images-tables.pdf")

req = shared.PartitionParameters(
    files=files,
    strategy="hi_res",
    hi_res_model_name="yolox",
    skip_infer_table_types=[],        # 空列表 = 不跳过任何类型的表格抽取（都要）
    pdf_infer_table_structure=True,   # 关键开关：要推断表格结构
)
resp = s.general.partition(req)        # 多次模型调用，可能几分钟
elements = dict_to_elements(resp.elements)
```

**筛出表格并看两种表示**：

```python
tables = [el for el in elements if el.category == "Table"]

tables[0].text                        # ① 纯文本表示（行列拍平，人看勉强、LLM 难对齐）
table_html = tables[0].metadata.text_as_html   # ② HTML 表示（保留行列结构）—— 藏在 metadata 里
```

`text_as_html` 存放在 **element 的 metadata 字段**里，是表格专属的关键产物。可以格式化打印或直接渲染：

```python
from io import StringIO
from lxml import etree
parser = etree.XMLParser(remove_blank_text=True)
tree = etree.parse(StringIO(table_html), parser)
print(etree.tostring(tree, pretty_print=True).decode())   # 缩进美化，肉眼核对行列

from IPython.core.display import HTML
HTML(table_html)                                           # Notebook 里直接渲染成表格
```

要点：**给 LLM 的应该是 `text_as_html` 而不是 `.text`**——HTML 里 `<tr>/<td>` 保住了"哪个数值属于哪行哪列"，LLM 才能正确回答表内问题。

## 4. 表格摘要：为相似度检索铺路

抽出 HTML 表后，还有一步：**为表格生成自然语言摘要**。原因是 RAG 靠 similarity search 找相关内容，而一张 HTML 表格的向量未必能和用户的自然语言问题对齐；一段摘要则更容易被检索命中。用 LangChain 的 summarize chain：

```python
from langchain_openai import ChatOpenAI
from langchain_core.documents import Document
from langchain.chains.summarize import load_summarize_chain

llm = ChatOpenAI(temperature=0, model_name="gpt-3.5-turbo-1106")
chain = load_summarize_chain(llm, chain_type="stuff")   # stuff：把整表塞进一个 prompt
chain.invoke([Document(page_content=table_html)])       # 输入是 HTML 表，输出是摘要
```

于是同一张表有了两件东西：**① HTML 表示（喂给 LLM 保结构）+ ② 摘要（喂进向量库供检索）**。检索时用摘要命中，回答时把 HTML 交给 LLM——这就是"多表示"（multi-representation）索引的雏形。

> **架构师视角**：这里出现了 RAG 里一个通用模式——**"检索用的表示"与"回答用的表示"可以不是同一个**。摘要负责"被找到"（recall），HTML 负责"被读懂"（fidelity）。同理可推广到长文档、代码、图片：为难检索的内容单独生成一个"检索代理文本"（proxy），把 embedding 的语义对齐和内容保真解耦。这是比"整块内容直接 embed"更高级的索引设计。

## 5. 本课总结

| 要点 | 一句话 |
|---|---|
| 分流 | HTML/Word 内建表结构走规则；PDF/图片需视觉先定位再抽 |
| 三法 | Table Transformer（有格坐标、贵）/ Vision Transformer（灵活、无坐标）/ OCR+rules（快、脆） |
| 关键参数 | `pdf_infer_table_structure=True` + `skip_infer_table_types=[]` |
| 核心产物 | `metadata.text_as_html`——保住行列结构喂 LLM，别用拍平的 `.text` |
| 多表示索引 | 表格 HTML（保真）+ 摘要（供 similarity search）分工 |

> **记忆点（引出 L6）**：至此 L2–L5 的技能齐了——规范化多格式（L2）、元数据与 chunking（L3）、PDF/图片视觉抽取（L4）、表格结构（L5）。L6 把它们**全部拼起来**，对一批异构文档（PDF/PPTX/Markdown）建一个能问答、能按来源过滤的 RAG bot。

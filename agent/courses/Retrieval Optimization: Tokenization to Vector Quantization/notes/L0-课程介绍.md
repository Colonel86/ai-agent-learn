# L0 · 课程介绍：从 Tokenization 到 Vector Quantization 的检索优化

> 课程：Retrieval Optimization: Tokenization to Vector Quantization（DeepLearning.AI × Qdrant，C1）
> 讲师：Kacper Łukawski（Qdrant Developer Relations Lead）；出品：Andrew Ng 开场 + David Myriel / Esmaeil Gargari / Geoff Ladwig。

## 这门课解决什么

RAG 有两步：**retriever**（从大语料里找相关信息）+ **generator**（用这些信息生成回答）。这门课**只优化第一步——retrieval**，因为它是最常被忽视、却决定上限的一环。讲师的核心信条贯穿全程：

> **"你无法优化你没有度量的东西"**（You can't improve what you don't measure）。优化的第一步永远是先建立质量度量，否则改完不知道是变好还是变坏。

## 全课路线（6 课 + 结语）

课程从"文本进模型之前"一路讲到"向量存下来之后"，是一条完整的检索链路：

| 课 | 主题 | 一句话 |
|---|---|---|
| L1 | Embedding Models | 文本如何经多层 transformer 变成向量，tokenizer 在其中的角色 |
| L2 | Role of the Tokenizers | 亲手训练 BPE / WordPiece / Unigram / SentencePiece 四类 tokenizer |
| L3 | Practical Implications | tokenization 如何坑到 emoji / 错字 / 型号 / 数字 / 日期，以及 payload filter 救场 |
| L4 | Measuring Search Relevance | information retrieval 的质量指标（precision / recall / MRR / NDCG 等） |
| L5 | HNSW | 近似最近邻的多层图结构，建图/查询参数如何平衡速度与召回 |
| L6 | Vector Quantization | product / scalar / binary 三种量化，内存最多省 64× |

本笔记覆盖**前半部分 L0–L3**（tokenization 主线）。

## 三条技术主线（Andrew 开场概览）

**① Tokenization（L1–L3）**
Tokenizer 把文本切成 token id 序列，token 通常对应词或子词。切法不止一种：
- word-level：`"I enjoy learning"` → `I` / `enjoy` / `learning`
- subword-level：`I` / `en` / `joy` / `learn` / `ing`

Tokenizer 是语言模型里**可训练**的关键组件。课程讲 WordPiece、byte-pair encoding、unigram 三种算法，以及 token 词表如何影响搜索结果——尤其是 emoji、错字、数字这些特殊字符。

**② HNSW（L5）**
向量库用专门数据结构做近似最近邻搜索，最常用的是 **HNSW（Hierarchical Navigable Small Worlds）**，建在多层图上。讲师的比喻：**像寄快递**——顶层把你送到大致的州，下一层定位到城市，越往下层越接近目标地址。它有一组参数控制"近似有多准"，要在速度和相关性之间平衡。

**③ Quantization（L6）**
百万级向量时存储/索引/搜索都变得又慢又贵。例：500 万条向量 × OpenAI Ada（1500+ 维）≈ **30 GB 内存**，且每月还在涨。量化最多可把内存降到 **1/64**：

| 量化 | 做法 | 代价 |
|---|---|---|
| Product Quantization | 子向量映射到最近 centroid | 省内存，但增加索引时间 |
| Scalar Quantization | 每个 float → 1-byte 整数 | 省内存 + 加速索引与搜索，精度略降 |
| Binary Quantization | float → Boolean（极端形态） | 内存/速度收益最大，精度损失也最大 |

> **架构师视角**：这门课的价值不在"教你调 HNSW 的 ef 参数"，而在把检索栈拆成**三个可独立度量、独立优化的层**——输入层（tokenizer 决定模型能看见什么）、索引层（HNSW 决定近似质量）、存储层（quantization 决定成本）。选型时这三层各有取舍旋钮，且**先度量后优化**是唯一正确顺序。挂到我的 `3-retrieval.md`：它此前聚焦"选哪个向量库 / embedding / reranker"，这门课补齐了"选定之后如何**在同一套组件内部**压成本、提召回"的下钻能力。

> **对比 Qdrant C2《Multi-vector Image Retrieval》**：C2 是同厂商姊妹课，把这里的 HNSW / quantization 用到**多向量图像检索**（ColPali 类 late-interaction）场景。C1 打的是单向量文本检索的地基，C2 是它在多模态、多向量上的延伸——两课的量化与 HNSW 知识可直接迁移。

> **记忆点（引出 L1）**：一切从 embedding 开始，而 embedding 又从 tokenization 开始。讲师说 tokenization 是"模型里极其关键、却常被忽视和低估"的一环。L1 就拆开一个真实的 sentence-transformer，看文本如何逐层变成向量、tokenizer 卡在最前面那道门。

在上节课中，我们介绍了语义搜索的基础知识，并看到它在大量使用场景中都能很好地工作。但我们也看到了一些边缘情况，看到了事情可能会出一点小问题。在这节课中，我们将深入探讨检索（retrieval），并介绍一些更高级的方法来克服这些边缘情况。

我对此非常兴奋，因为我认为检索是一个全新的领域，而且我们要讨论的很多技术都是过去几个月左右才出现的。这是一个前沿话题，所以你们将会站在最前沿。让我们享受其中吧。

在这节课中，我们将讨论检索。这在查询时非常重要——当你接收到一个查询时，你想要检索出最相关的文本片段。我们在上一节课中讨论了语义相似性搜索，但这里我们将讨论一些不同的、更高级的方法。

我们要介绍的第一个是最大边际相关性（Maximum Marginal Relevance，简称 MMR）。其背后的思想是：如果你总是选取在嵌入空间中与查询最相似的文档，你实际上可能会错过多样化的信息，正如我们在前面的某个边缘情况中看到的那样。在那个例子中，有一位厨师在询问关于全白色蘑菇的信息。如果我们只看最相似的结果，那将是前两个文档——它们包含大量与查询相似的信息，比如子实体和全白色的描述。但我们真正想要确保的是，我们也能获取其他信息，比如它其实有剧毒这一事实。这就是 MMR 的用武之地，因为它会选取一组多样化的文档。

MMR 的核心思想是：我们发送一个查询进去，最初会得到一组响应，其中 "fetch_k" 是一个我们可以控制的参数，用来决定我们获取多少个响应。这一步完全基于语义相似性。然后我们再处理这个较小的文档集合，不仅优化基于语义相似性的最相关文档，还要优化具有多样性的文档。最后从这组文档中，我们选择最终的 "k" 个返回给用户。

我们能做的另一种检索类型叫做 self-query（自查询）。当你遇到的问题不仅仅是关于你想要进行语义查询的内容，还包含一些关于元数据的提及（你想据此进行筛选）时，这就很有用。让我们看一下这个问题：1980 年制作的关于外星人的电影有哪些？这其实有两个组成部分。一是语义部分，即"外星人"这部分，我们想要在电影数据库中查找外星人。二是真正涉及到每部电影元数据的部分，即年份应为 1980 年这个事实。我们能做的是：使用语言模型本身将原始问题分成两个独立的部分——一个过滤器和一个搜索词。大多数向量库都支持元数据过滤器，所以你可以轻松地基于元数据筛选记录，比如年份是 1980 年。

最后，我们将讨论压缩（compression）。这对于真正只提取检索到的段落中最相关的部分非常有用。例如，当问一个问题时，你会得到存储的整个文档，即使只有前一两句话是相关的部分。通过压缩，你可以将所有这些文档传给一个语言模型，提取出最相关的段落，然后只将最相关的段落传给最终的语言模型调用。这会以增加对语言模型的调用次数为代价，但它对于将最终答案聚焦于最重要的内容也非常有用。所以这是一种权衡。

让我们来看看这些不同的技术实际运行的效果。我们将像往常一样，先加载环境变量。然后让我们像之前一样导入 Chroma 和 OpenAI。我们可以通过查看 collection 数量看到，它有之前加载的 209 个文档。

现在让我们来看 max marginal relevance（最大边际相关性）的例子。我们将加载之前那个示例中关于蘑菇信息的文本。对于这个例子，我们将创建一个小数据库，作为一个简单的玩具示例使用。我们有了问题，现在可以运行相似性搜索。我们设置 "k=2" 只返回两个最相关的文档，可以看到其中没有提到它有毒这一事实。

现在让我们用 MMR 来运行。虽然传入 "k=2"，我们仍然希望返回两个文档，但让我们设置 "fetch_k=3"，即最初获取所有三个文档。我们现在可以看到，关于"有毒"的信息出现在我们检索到的文档中。

让我们回到上一节课中的一个例子——当时我们询问关于 MATLAB 的问题，得到的文档中包含重复信息。为了帮你回忆，我们可以看一下前两个文档（只看前几个字符，因为它们否则会非常长），可以看到它们是相同的。当我们对这些结果运行 MMR 时，可以看到第一个和之前一样，因为那是最相似的。但当我们看第二个时，可以看到它不一样了——它在响应中带来了一些多样性。

现在让我们继续看 self-query 的例子。这是我们之前提的那个问题：他们在第三讲中说了什么关于回归的内容？它返回的结果不仅仅来自第三讲，还来自第一讲和第二讲。如果我们手动修复这个问题，我们要做的就是指定一个元数据过滤器——传入这个信息，即我们想要 source 等于第三讲的 PDF。然后如果我们看检索到的文档，它们都将正好来自那一讲。

我们可以使用语言模型来为我们做这件事，这样就不必手动指定了。为此，我们将导入一个语言模型 OpenAI，导入一个名为 self-query retriever 的检索器，然后导入 attribute info——我们可以在其中指定元数据中的不同字段以及它们对应的内容。

我们的元数据中只有两个字段：source 和 page。我们为每个属性填写名称、描述和类型的描述。这些信息实际上将被传递给语言模型，所以让它尽可能具有描述性是很重要的。然后我们将指定一些关于这个文档库中实际内容的信息。我们将初始化语言模型，然后使用 "from_llm" 方法初始化 self-query retriever，传入语言模型、底层向量数据库（我们要查询的）、关于描述和元数据的信息，最后还会传入 "verbose=True"。

设置 "verbose=True" 让我们能看到 LLM 推断"应该传递的查询以及任何元数据过滤器"时，底层发生了什么。当我们用这个问题运行 self-query retriever 时，多亏了 "verbose=True"，我们可以看到正在打印出底层发生的事情。我们得到一个查询 "regression"——这是语义部分；然后我们得到一个过滤器，其中有一个 equals（等于）的比较器，在 source 属性和 docs 路径这个值之间，这是第三讲机器学习课程的路径。所以这基本上是告诉我们：在语义空间中对 regression 进行查找，然后做一个过滤，只查看 source 值为这个值的文档。这样如果我们循环遍历这些文档并打印出元数据，我们应该看到它们都来自第三讲。确实如此。这就是一个 self-query retriever 可以用来精确按元数据过滤的例子。

我们可以讨论的最后一种检索技术是上下文压缩（contextual compression）。让我们加载一些相关模块：contextual compression retriever 和一个 LLM chain extractor。它要做的是：从每个文档中仅提取相关的部分，然后将这些作为最终的返回响应。

我们将定义一个漂亮的小函数来美观打印文档，因为它们通常很长很难懂，这将使我们更容易看清发生了什么。然后我们可以用 LLM chain extractor 创建一个 compressor，再创建 contextual compression retriever，传入 compressor 和向量库的 base retriever。

当我们现在传入问题"他们关于 MATLAB 说了什么"，并查看压缩后的文档时，我们可以看到两件事。一是它们比普通文档要短得多。二是我们仍然有一些重复的内容——这是因为底层我们使用的是语义搜索算法。这正是我们之前在这节课中通过 MMR 解决的问题。

这是一个很好的例子，说明你可以结合各种技术来获得最佳的结果。为了做到这一点，当我们从向量数据库创建检索器时，可以将搜索类型设置为 MMR。我们重新运行后可以看到：得到一个经过过滤的结果集，不包含任何重复信息。

到目前为止，我们提到的所有附加检索技术都建立在向量数据库之上。值得一提的是，还有其他类型的检索完全不使用向量数据库，而是使用其他更传统的 NLP 技术。

在这里，我们将用两种不同类型的检索器重建一个检索流水线：SVM 检索器和 TF-IDF 检索器。如果你能从传统 NLP 或传统机器学习中认出这些术语，那很好；如果你不认识，也没关系。这只是其他现存技术的一个示例。除了这些还有很多其他的，我鼓励你去看看其中一些。

我们可以快速地跑一遍通常的加载和分割流水线。这两个检索器都暴露了一个 from_text 方法：一个接收 embedding 模块（那就是 SVM 检索器），而 TF-IDF 检索器则直接接收分割好的片段。现在我们可以使用这些其他的检索器了。让我们传入"他们关于 MATLAB 说了什么"给 SVM 检索器，看一下返回的最顶部的文档，可以看到它提到了很多关于 MATLAB 的内容，所以它得到了一些不错的结果。我们也可以在 TF-IDF 检索器上试试，可以看到结果看起来稍微差一些。

# L0 · 课程介绍：把 Prompt Engineering 变成可自动优化的程序

> 课程：DSPy: Build and Optimize Agentic Apps（DeepLearning.AI × Databricks）
> 讲师：Chen Qian（Databricks 软件工程师、DSPy 开发 co-lead）；Andrew Ng 开场对谈。致谢名单：Omar Khattab、Cathy Yin、Krista Opsahl-Ong、Tomu Hirata（Databricks），Esmaeil Gargari、Brendan Brown（DeepLearning.AI）。

## 一句话定位

**核心问题**：构建复杂 AI 应用时，最大的痛点之一是给 LLM 写好 prompt——Andrew 自述常常试几十个 prompt、改措辞、换格式，耗时巨大；更糟的是**换一个底层 LLM，prompt 经常直接失效**。

**本课答案**：DSPy 把这个过程流水线化——你只声明**模型需要什么输入、返回什么输出**（signature），再提供一个"输入 + 期望输出"的数据集，DSPy 的 optimizer 就能自动搜索更好的 prompt，用远少于手工的工作量拿到更好的效果。Andrew 的评价：optimizer 有时能从数据里构造出**质量远超人类手写水平的 few-shot prompt**。

DSPy 有两大 building block：

- **Signature**：告诉系统这个 LLM 组件期望什么输入输出——例如情感分析程序，输入是一段文本，输出是一个表示情感的整数；
- **Module**：拿着 signature 去实际调用语言模型并取回结果。

此外课程还覆盖 **MLflow tracing**——应用不工作但不知道为什么时，一行代码开启追踪，看清每一步用了什么数据、调了什么工具、模型返回了什么、哪里断掉了。

> **架构师视角**：Andrew 那句"prompt 在换模型时会 break"点中了手工 prompt 的本质缺陷——它是**对某个特定模型的过拟合**。DSPy 的思路是把"意图"（signature + 数据集 + metric）和"实现"（具体 prompt 字符串）分离，prompt 降级为可再生成的编译产物。这与"配置即代码 → 代码即可编译"的工程演化是同一个方向。

## 核心概念/类比

| 概念 | 类比 | 一句话 |
|---|---|---|
| Signature | 函数签名 / API 契约 | 声明 LLM 组件的输入字段与输出字段 |
| Module | 拿着契约干活的执行体 | 用 signature 实际调用 LM 并解析结果 |
| Optimizer | 自动化的 prompt 工程师 | 给定 agent + 评估数据集 + metric，自动为工作流各步骤搜索更好的 prompt |
| MLflow tracing | 应用的 X 光机 | 一行代码，看清每步的数据、工具调用、模型返回与断点 |
| Agentic workflow | 多步流水线 | 输入经多个步骤处理产出输出，多步都可能调 LLM——每一步的 prompt 都可被 optimizer 优化 |

## 课程路线

| 课 | 一句话预告 |
|---|---|
| L1 | DSPy 是什么、特别在哪、为什么不是重复造轮子——出人意料的是它只需极少代码，本质上自动化了 prompt engineering |
| L2 | 用 signature + module 构建 DSPy 程序（情感分类器 + 自定义 agent 游戏） |
| L3 | 用 MLflow tracing 调试 DSPy 程序 |
| L4 | 用 DSPy optimizer 自动优化一个回答 Wikipedia 问题的 RAG 应用的 prompt |

> **对比课程 12《Long-Term Agentic Memory》的 create_multi_prompt_optimizer**：LangMem 的 prompt optimizer 和 DSPy optimizer 是**同一个问题的两种解法**——"prompt 不该由人手工维护，该由系统根据反馈数据自动改进"。区别在切入点：LangMem 把优化后的 prompt 当作 Procedural Memory 存进 store，在**运行时**随反馈演化；DSPy 把优化当作**开发/编译期**步骤，靠评估数据集 + metric 离线搜索。前者是在线学习，后者是离线编译，生产系统里两者可叠加。

> **记忆点（引出 L1）**：Andrew 收尾点题——DSPy 令人惊讶之处在于**代码量极少，却把 prompt engineering 这个过程本身自动化了**。但"我们已经有那么多框架，DSPy 是不是重复造轮子？"L1 正面回答这个问题：从 compound AI system 的两大痛点讲起，给出 DSPy 的三个特别之处。

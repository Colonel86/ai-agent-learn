## 一、课程背景

### 1. 过去一年 AI Agent 的进展

大约一年前做第一门 LLM 框架课程时，agent 示例还很"古老"、很难跑通。这一年间，Andrew 看到许多团队已成功构建出 AI agents。

Harrison 总结了这一年中的两个关键进展：

1. **Function Calling LLMs（函数调用）** — 让工具使用变得更可预测、更稳定；
2. **为 Agent 优化的工具（如搜索）** — 专门针对 agentic 使用方式做了适配。

### 2. 为什么普通搜索不够？Agentic Search 的由来

Rotem 的观察：
- 普通搜索引擎返回**多个链接**，需要人点进去找答案；
- Agent 真正需要的是 **可以直接引用到链接的答案**；
- Agent 还需要 **可预测的结果格式**。

这正是 **Agentic Search** 所提供的能力。

## 二、什么是 Agent 和 Agentic Workflow

Andrew 用"三人合写论文"为例解释：

| 步骤 | 谁做 | 角色 |
|---|---|---|
| 1. 规划（Planning） | Andrew | 起草大纲 |
| 2. 研究（Research） | Rotem | 做调研、查询、整理相关文档 |
| 3. 写初稿（Draft） | Harrison | 基于大纲和资料写第一版 |
| 4. 审查（Review） | Andrew | 给出建设性意见 |
| 5. 迭代（Iterate） | 回到 Harrison / Rotem | 修改 / 补研究 |

这个**迭代过程**就是 agent / agentic workflow 的典型形态，和今天人们"一个 prompt 一次性让 LLM 生成文章"的方式形成鲜明对比。

> Andrew：如果强迫我从第一个字写到最后一个字、不准退格，我自己也写不好。迭代式工作流能得到远更好的产出。

对应到 LLM：
- 用一个 LLM 写大纲；
- 用一个 LLM 写草稿 / 修订；
- 用一个 LLM 做研究；
- ……

## 三、Agentic Workflow 的五大核心设计模式

| # | 模式 | 含义 |
|---|---|---|
| 1 | **Planning（规划）** | 规划要走的步骤，比如先写大纲，再接下来做什么 |
| 2 | **Tool Use（工具使用）** | 知道哪些工具可用、如何使用（例如搜索工具） |
| 3 | **Reflection（反思）** | 通过多次迭代改进结果；可由多个 LLM 互相批评、提建议来驱动编辑循环 |
| 4 | **Multi-Agent Communication（多智能体协作）** | 每个 LLM 被赋予独特的 prompt 扮演特定角色，协作完成任务 |
| 5 | **Memory（记忆）** | 跨多个步骤跟踪进度和中间结果 |

### 关键观察
- **有些能力在 LLM 内部实现**（如 Function Calling 支撑 Tool Use）；
- **许多能力实际由外部框架实现**（如记忆、多步编排等）。

## 四、LangChain 的现状与 LangGraph 的由来

LangChain 早已支持：
- 多种形式的 **Memory**；
- **Function-calling LLMs 与 Tool Execution**（先前的 *Functions, Tools, and Agents* 课程涉及过）。

最近 LangChain 强化了对 agentic 工作流的支持，能更好地处理这些经典 agent 范式：

| Agent 范式 | 说明 |
|---|---|
| **ReAct Agents** | 早期范式，ReAct = Reasoning + Action（推理 + 行动） |
| **Self-Refine 论文方法** | 实现迭代式修正（reflection 式） |
| **AlphaCodium / alpha coding 示例** | 用 **flow engineering** 构建的代码智能体 |

这些 agent 的共同结构：
> **由一个循环图（cyclical graph）定义其行为。**

为了**直接支持这种循环图式的构建**，LangChain 推出了 **LangGraph**。

## 五、本课程学习路径

1. **从零开始构建 Agent**
   - 只用 LLM + Python 手写一个 agent。

2. **学习 LangGraph 组件**
   - 用 LangGraph 组件重建同一个 agent，对比原理。

3. **Agentic Search 能力**
   - 搜索是许多 agent 应用的核心；
   - 学习它的能力与使用方式。

4. **两个额外的关键能力**
   - **人类输入（Human Input）** —— 在关键节点引导 agent；
   - **持久化（Persistence）** —— 存储当前状态，便于：
     - **调试 agent**
     - **生产化部署 agent**

5. **综合项目**
   - 用 LangGraph 做一个项目；
   - 具体做什么到最后一课才揭晓。

6. **展望**
   - 结尾讨论该技术的酷炫应用和未来方向。

## 七、本节要点速记

- Agent 的关键进步来自 **Function Calling** 和 **Agentic 专用工具（如 agentic search）**。
- Agentic workflow 的本质是 **迭代** —— 比一次性生成效果好得多。
- 五大设计模式：**Planning / Tool Use / Reflection / Multi-Agent / Memory**。
- Agent 的行为本质是 **循环图**，这是 LangGraph 出现的直接原因。
- 课程会从手写 agent → LangGraph 组件 → Agentic Search → 人类输入 + 持久化 → 项目实战。

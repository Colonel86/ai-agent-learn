# L0 · 课程介绍：Build Interactive Agents with Generative UI

> 课程：Build Interactive Agents with Generative UI（DeepLearning.AI × CopilotKit）
> 讲师：**Atai Barkai**，CopilotKit 联合创始人兼 CEO——也就是本课所依赖的 **AG-UI 协议**背后的团队。开场由 Andrew Ng 引入。
> 一句话定位：**把"已经建好的 agent"变成"用户愿意用的产品"**——这一步远不止再套一个 chatbot 界面。

## 1. 课程要解决的问题

Andrew 的开场点题：**造出一个能干活的 AI agent 很难，但那只是第一关**。第二关是——怎么以用户喜欢的方式把它交付到用户手里。

一个好的 agent 界面长什么样？不该是**大段大段的纯文本**：

- 用户要审批 → 给他一张**表单**；
- 用户要探索数据 → 给他一张能交互的**图表**；
- agent 不只是"用文字回答"，而是给用户**能看、能操作的东西**（something to see or act on）。

Atai 把现状类比成计算机史：今天大多数 agent 还停留在 **MS-DOS 命令行时代**——对早期极客够用，但撑不起大众普及。AI 正在经历从 MS-DOS 到 **Windows/Mac 时代**的同一次跃迁，一句主张贯穿全课：**"all UI is becoming AI"**（未来一切人机交互都会被 agent 中介）。

## 2. 什么是 Generative UI（生成式 UI）

**Generative UI = 由 LLM/agent 使能、且服务于 LLM/agent 的 UI 范式**。所有 generative UI 方案排在**一条光谱**上，光谱的轴是"**控制权从开发者流向 agent 的程度**"。三支柱：

| 支柱 | 一句话 | 谁定 UI |
|---|---|---|
| **Controlled**（受控） | 开发者手写全定制组件，agent 按需调用并填数据 | 开发者定外观，agent 定意图 |
| **Declarative**（声明式） | 开发者声明一套乐高式 building-block 目录，agent 从 schema 拼装布局 | agent 组装，用 A2UI 开放规范 |
| **Open-ended**（开放式） | agent 按需生成完整交互体验（白板、审批流…），经 MCP apps 嵌入你的产品 | agent 端到端生成 |

> **架构师视角**：这三支柱不是"选一个用"，而是**同一个应用里按 surface 分层用**。最高频界面用 controlled 求稳、长尾界面用 declarative 求灵活、第三方系统/极长尾用 open-ended 求惊喜。这正是 `10-agent-ux.md` 呈现层选型的核心命题——**先想清楚 agent 的"中间态"要不要给人看、以什么颗粒度看**，再倒推后端 emit 什么流。

## 3. 你将构建什么

课程主线：**先搭地基，再沿光谱逐支柱加码**。

```
LangChain Deep Agent  ──AG-UI──▶  CopilotKit  ──▶  React 前端
      (后端)                     (runtime+组件)      (用户界面)

           沿 generative UI 光谱推进：
  Controlled ──▶ Declarative(A2UI) ──▶ Open-ended(MCP apps → app sandbox)
```

结课交付物是一个 **full-stack agentic app**，它能：

1. 按需渲染 charts 和 cards（controlled）；
2. 通过自定义 apps 呈现一块**实时白板**（open-ended / MCP apps）；
3. 在 agent 与 UI 之间**双向同步一份共享 to-do 列表**（state synchronization）。

**技术栈**：CopilotKit（开源，一个框架同时支持三大 generative UI 范式）+ AG-UI 协议。CopilotKit 有对 LangGraph、Google Cloud、AWS、Azure 等的一方集成；AG-UI 已被 Google / Microsoft / Amazon / LangChain / Oracle 等主流 agentic 生态采纳——**本课学到的东西可迁移到几乎任何 agentic 后端**。本课聚焦 **Web + React**（主流 Web 框架）。

## 4. 前置知识与边界

- **假设你已会造 agent**：课程提供预置 agent，不教从零造 agent（DeepLearning.AI 另有课程）。
- **只讲"用 AG-UI 连接用户"这一侧**，不讲"为自研 agent 系统写 AG-UI connector"那一侧。
- 焦点是 Web/React，但同一套思路可延伸到 mobile / Slack / 短信等前端。

## 5. 课程地图（Lesson 概览）

| Lesson | 主题 | 支柱 |
|---|---|---|
| L1 | Generative UI 光谱：三支柱的差异与适用场景（心智模型） | — |
| L2 | 用 CopilotKit + AG-UI 搭第一个 agent chat（生产级地基） | 地基 |
| L3 | **Controlled** Generative UI：`useComponent` 注册组件 | 受控 |
| L4 | **Declarative** Generative UI：A2UI 组件目录 | 声明式 |
| L5–L6 | **Open-ended**（MCP apps / app sandbox）+ 前端工具调用、state 同步 | 开放式 + 收尾 |

> **对比 A2A 课的 client 端**：A2A 解决 **agent↔agent**（一个 agent 作为另一个的 client 去发现/调用）；本课的 AG-UI 是 **agent↔user**（把 agent 接到人面前的界面）。加上 MCP 的 **agent↔tools**，三者构成同一张图的三条腿——L1 会把这个三角讲透。

> **记忆点（引出 L1）**：本课把 generative UI 拆成 **controlled / declarative / open-ended** 三支柱，并断言"all UI is becoming AI"。L1 会正式建立这个**光谱心智模型**——每支柱的 pros/cons 与适用 surface，以及 AG-UI 在 MCP / A2A / AG-UI 三角中的定位——为后面每一课的动手实现打底。

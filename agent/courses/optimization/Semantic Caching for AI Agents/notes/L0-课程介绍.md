# L0 · 课程介绍

> 课程：Semantic Caching for AI Agents（DeepLearning.AI × Redis）
> 讲师：Tyler Hutcherson（Redis Applied AI Engineering Lead）、Iliya Zhechev（Redis Senior Research Engineer）
> 一句话：给 AI Agent 加一层**语义缓存（Semantic Cache）**，让它更快、更省钱。

## 这门课解决什么问题

很多项目里，**推理成本（inference cost）和延迟（latency）直接限制了应用能不能规模化**。传统的 input-output 缓存只在输入文本**完全一致**时生效，某些场景有用；但一个用户问 "How can I get a refund?"、另一个用户问 "I want my money back."——exact match 缓存会把它们看作完全不同的两个问题。

**Semantic Caching 看的是"意思"**：用 embedding 度量两个问题在语义空间（meaning space）里有多相似；足够相似，就直接复用模型对旧问题的回答，不再调用模型。

## 课程路线（5 课 + 结语）

| 阶段 | 内容 |
|---|---|
| 从零手搓 | 亲手造 embedding、算距离、设阈值（threshold），逐块看懂语义缓存的内部构造 |
| Redis 生产化 | 换用 Redis 开源 SDK 实现，更接近生产部署：TTL（time to live）保持缓存新鲜且小巧、按用户/团队/租户隔离的独立缓存、以及一个**为缓存精度微调过的开源开放权重 embedding 模型** |
| 度量效果 | Hit Rate / Precision / Recall，用混淆矩阵可视化；观察调整相似度阈值如何在 precision 和 recall 之间移动平衡点；再看延迟——少量 cache hit 很快累积成可观的时间节省 |
| 四种增强 | ① 优化阈值；② cross-encoder 做更好的重排（re-ranking）；③ 小 LLM 复核两个问题是否同义；④ fuzzy matching 处理用户提问里高频出现的拼写错误 |
| 接入 Agent | Agent 把大问题拆成小问题，逐个查缓存，**只在必要时才调 LLM**——每个新用户、每种略有不同的措辞都能受益于系统已有的知识；随着缓存"预热（warm up）"，模型调用下降，响应质量不变但快得多 |

> **架构师视角**：这门课的定位是"LLM 成本优化"里**语义层缓存**的完整落地：从算法内核（embedding + 距离 + 阈值）到工程外壳（TTL、多租户、指标、Agent 集成）。阈值是贯穿全课的**唯一核心旋钮**——它同时决定省钱多少（hit rate）和答错风险（false positive），后面每一课都是围绕这个 trade-off 展开。

> **对比 memory 课程 12a**：12a 的记忆分类里 Semantic Cache 被归入**短期记忆**——"命中相似 query 直接返回，省一次 LLM 调用"，一句话带过；本课是同一概念的另一出处，从"记忆系统的一个组件"换到"成本/延迟优化基础设施"的视角，把那一句话展开成一整门课。两个视角互补：对 Agent 而言它是记忆，对账单而言它是缓存。

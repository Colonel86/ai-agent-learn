MCP 基于客户端-服务器架构。本节深入介绍其架构原理、核心原语以及通信机制。

---

**三层架构：Host、Client、Server**

- **Host（宿主）**：承载所有 MCP 客户端的 LLM 应用，如 Claude Desktop、Cursor、Windsurf 等，负责维护与各 MCP 服务端的连接
- **Client（客户端）**：嵌入在 Host 内部，与 MCP 服务端保持一对一连接，负责发现并调用服务端暴露的资源和工具
- **Server（服务端）**：轻量级程序，向客户端暴露特定能力（工具、资源、提示词模板）

---

**三大核心原语**

**工具（Tools）**：客户端可调用的函数，类似于一般的工具使用（Tool Use）。适用于需要写操作或修改的场景，如检索、搜索、发送消息、更新数据库记录等。

**资源（Resources）**：服务端暴露的只读数据或上下文，类似于 GET 请求。包括数据库记录、API 响应、文件、PDF 等。应用可以选择是否将其纳入上下文，且资源可以随数据变化动态更新。

**提示词模板（Prompt Templates）**：服务端预定义的提示词模板，用户只需传入动态参数，无需自己从头编写提示词。这些模板是经过充分测试和优化的，能让用户直接享受最佳提示词实践的成果。

---

**实际演示（SQLite MCP 服务端）**

在 Claude Desktop 中连接 SQLite MCP 服务端后：

- **工具使用**：用自然语言查询数据库（如"有哪些表，各有多少条记录？"），系统自动调用 `List Tables` 等工具，结合 Artifacts 功能还能生成数据可视化图表
- **提示词模板**：选择服务端提供的 `MCP Demo Prompt`，只需填入动态参数（如"行星"主题），服务端会自动生成完整的操作提示词，驱动数据库建表、填充数据等操作
- **资源**：演示中出现的"业务洞察备忘录"会随新数据的加入动态更新，无需额外的工具调用

---

**Python MCP SDK 代码结构**

- **工具**：用装饰器标注函数，声明参数和返回值类型，SDK 自动生成工具 Schema
- **资源**：指定 URI 和数据格式，装饰函数返回所需数据；支持静态资源和带参数的动态模板资源
- **提示词模板**：同样用装饰器定义，指定名称、描述，以及要返回的消息内容

---

**通信机制与传输层**

客户端与服务端的通信流程：初始化握手（请求→响应→确认通知）→ 消息交换（双向请求和通知）→ 连接终止。

**传输层（Transport）**决定消息的具体传递方式：

- **标准 IO（Stdio）**：本地运行时使用，客户端将服务端作为子进程启动，通过标准输入/输出通信
- **HTTP + 服务端推送事件（SSE）**：远程部署时使用，维持有状态的持久连接
- **Streamable HTTP**：更新版协议，同时支持有状态和无状态连接，是未来推荐的方向；无状态部署更利于应用扩展

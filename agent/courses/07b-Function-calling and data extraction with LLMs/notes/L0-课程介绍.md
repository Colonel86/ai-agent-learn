# L0 课程介绍

## 一句话

大模型训练在非结构化文本上,但我们的软件基础设施(API、数据库)是结构化的、有固定接口的——**function calling 就是架在这两个世界之间的桥**:把自然语言意图转成一个能调用函数的结构化调用。

## 课程背景与讲师

- 合作方 Nexusflow,讲师 Jiantao Jiao(Nexusflow CEO / UC Berkeley 助理教授)、Venkat Srinivasan(创始工程师)。
- 全程用的模型是 **NexusRavenV2-13B**——一个**专门为 function calling 微调**的开源模型(HuggingFace 可下载)。课程强调:它只有 13B,却能在部分 function-calling 基准上打平 GPT-4,而且小到可以本地部署,省掉延迟和成本。

## function calling 的核心机制(全课的地基,务必记牢)

1. 在发给模型的 prompt 里,附上**可用函数的描述**(函数名、参数、以及"这个函数是干嘛的"的自然语言说明,让模型判断何时该用它)。
2. 模型判断某个查询适合调某函数时,**从查询里抽出参数,生成一个"可以用来调用该函数的字符串"**。
3. **关键:模型不亲自执行函数,它只吐出一个调用字符串。真正的执行是你(调用方)来做的。**

这第 3 点是整门课、也是面试的命门——**模型只产出"调用意图",执行发生在你的代码/网关层**。对应你面试包 `02-tool-gateway-auth-and-contract`:工具网关存在的意义,正是因为模型只会说"我要调这个",真正带鉴权地执行、拦截越权,是网关的事。

## 课程会覆盖的路径

单函数调用 → 多函数 / 并行 / 嵌套调用 → 把 OpenAPI 规范的 Web 服务转成可调用工具 → 用 function calling 做结构化抽取 → 最终项目:把客服对话转录抽取成结构化数据、生成 SQL 存进数据库。

## ⚠️ 时效提醒(架构师视角)

这门课 2024 年出的,用 NexusRaven 的"Pythonic prompt 格式"、GPT-3.5-turbo。**具体实现已过时**——今天所有主流模型(GPT、Claude、Gemini)都原生支持 tool calling,不用手搓 Raven 那套 prompt 格式。但**概念全部通用且是当前主流**:工具契约、并行/嵌套调用、结构化抽取、受控的数据库访问——这些直接映射到 MCP 工具设计和你已学的 `10-MCP` / `09-Functions,Tools and Agents`。学这门课要抓概念,别记 Raven 的具体语法。

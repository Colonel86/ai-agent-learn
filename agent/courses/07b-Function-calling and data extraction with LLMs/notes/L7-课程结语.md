# L7 课程结语

## 这门课学到的能力

- 写 prompt 让 LLM 做 function calling
- 多函数调用、嵌套函数调用
- 用 function calling 接入 Web 服务(外部 API)
- 用 function calling 从非结构化文本抽结构化数据

## 三条可迁移、到今天仍然通用的核心思想

1. **模型只产出"调用意图",执行归你。** function calling 的本质是把自然语言意图翻译成结构化调用串,真正的执行、鉴权、拦截发生在你的代码/网关层。这是理解工具网关、MCP、Agent 安全的地基。

2. **工具描述(docstring)是模型推理的输入,不是给人看的文档。** 调用失败先查工具描述够不够清楚(L2 的教训)。工具契约写得好不好,直接决定调用准确率。

3. **让模型有多大权限,是核心安全取舍。** raw SQL(万能钥匙,危险)vs 白名单工具函数(受限,可控)——agent 的写操作应走预定义的、带校验的 action,而不是让它生成任意可执行代码(L5)。

## 与你其他资产的连接

- **和 07a(结构化输出)交汇**:L4 展示了 function calling 的参数抽取 = 结构化抽取,和 07a 的约束解码/JSON schema 是同一目标的两条路。
- **和已学 09(Functions, Tools and Agents)、10(MCP)递进**:这门课手工做的"适配器 + OpenAPI 转工具",今天被 MCP 标准化了。理解这门课的痛点 = 理解 MCP 为什么值钱。
- **映射面试包**:`01`(Run Loop 的执行环)、`02`(工具网关与契约)、`03`(MCP)、`07`(安全护栏,尤其 raw SQL vs 白名单)。
- **可做作品集**:L6 的"对话→结构化→SQL"端到端管道,换成现代栈(原生 tool calling + Pydantic + 白名单 DB 函数)就是一个能讲出取舍的 demo。

## ⚠️ 全课时效总结

这门课 2024 年、基于 NexusRaven 的"Pythonic prompt 格式"——**具体实现已过时**(今天用主流模型的原生 tool calling,不手搓 prompt 格式;JSON 生成用约束解码;数据库访问用更安全的白名单)。**但概念全部通用**。学它抓思想:工具契约、并行/嵌套调用、结构化抽取、grounding、权限取舍。

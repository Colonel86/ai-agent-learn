# L1：为什么评估智能体与传统软件测试不一样

AI 智能体（AI Agent）本质上是**由 LLM 驱动的软件应用**。本节先厘清"评估 LLM 系统"与"传统软件测试"的本质区别，再看智能体相比普通 LLM 应用多出来的复杂度。

## 评估的两个层次

讨论评估通常分成两层：

- **左侧：LLM 模型评估（Model Evaluation）**——衡量一个基础模型本身在某个任务上的表现。典型基准（Benchmark）有覆盖数学、哲学、医学等的 **MMLU**，以及代码生成的 **HumanEval**。模型厂商常用这些榜单展示自己模型的相对实力。
- **右侧：LLM 系统/应用评估（System / Application Evaluation）**——衡量"整个应用"做得好不好，LLM 只是其中一部分。这里的评估数据集可以**手工构造、自动构造或合成**，也常来自真实世界数据。

当你把 LLM 嵌进一个更大的产品里，需要关心的就不止模型本身了——**Prompt、工具、记忆、路由组件**协同工作的整体效果才是重点。

## 传统软件测试 vs LLM 系统测试

- 传统软件大多是**确定性（Deterministic）**的——像火车在轨道上跑，起点终点清晰，每个零件能否正常工作很容易验证。**单元测试 + 集成测试**这一套就够用。
- LLM 系统更像**在堵车的城市里开车**：环境多变、系统非确定。同一个 Prompt 多次调用会得到略有差异的回答，质量指标也常常是**相关性、连贯性**这类定性维度，难以用 pass/fail 一刀切。

## LLM 系统常见的评估类型

- **幻觉（Hallucination）**：是否在乱编内容
- **检索相关性（Retrieval Relevance）**：检索到的文档是否真的与问题相关
- **问答准确性（QA Accuracy）**：是否给出符合用户需要的正确答案
- **毒性（Toxicity）**：是否产出有害/不当语言
- **整体性能（Overall Performance）**：系统整体是否完成目标

社区有大量开源工具和数据集可以辅助这些评估，课程后面也会用到。

## 从 LLM 应用到智能体：复杂度跃迁

一旦把 LLM 应用升级为 **智能体（Agent）** ，复杂度立刻上一个台阶。

> 智能体 = 一个能基于推理、代表用户 **采取行动（Take Actions）** 的软件系统。

它通常由三部分组成：

1. **推理（Reasoning）**：由 LLM 完成
2. **路由（Routing）**：决定使用哪个工具/技能
3. **行动（Action）**：实际调用工具、API 或代码

常见用例：个人助理（笔记/转录）、桌面或浏览器自动化、数据抓取与摘要、搜索研究汇编等。

## 例子：订机票去旧金山

让智能体"帮我订一张去旧金山的机票"，幕后涉及：

1. 理解用户意图，挑选合适的工具/API
2. 调用机票/酒店搜索 API，可能需要追问澄清
3. 用正确语气、正确细节回复

那么评估时要逐步审视：

- 路由器选对工具了吗？
- 构造请求时是否用正确的参数调用了正确的函数？
- 是否准确使用了**上下文（日期、偏好、地点）**？
- 最终回复语气是否合适、事实是否正确？

如果它把"San Francisco"理解成"San Diego"并返回了圣地亚哥的航班，对希望去旧金山的用户来说就是失败——这说明**不能只评估 LLM 原始输出，还要评估它沿途的每一个决策**。

## 智能体的典型失败模式

- 工具选错（Wrong tool selection）
- 上下文误用（Misusing context）
- 出现讽刺/不当语气
- 用户尝试越狱（Jailbreak）导致异常输出

对这些问题，可以用 **人工反馈（Human-in-the-loop）** 或 **LLM 作评审（LLM-as-a-judge）** 来评估最终回复是否真正满足需求。LLM-as-a-judge 在智能体评估中的细节会在后续章节展开。

## Prompt 改一行，可能引发回归

哪怕只是给 Prompt 加一句"请礼貌回复"，都可能在某些场景下意外引发回归。所以你需要一组**有代表性的测试用例（Test Cases / Datasets）**，每次改动后跑一遍，捕捉回归并持续扩展能力。

## 评估驱动的迭代闭环

像传统软件那样迭代，但**不能只靠确定性检查**：智能体是非确定的，可能在 A 场景改进的同时在 B 场景退化。所以要有：

- 一组覆盖不同用户场景的**一致测试集**
- 从**生产数据**回流的真实查询和真实用户交互
- 一条把生产数据带回开发、用来调 Prompt/工具/逻辑的闭环

## 课程后续会用到的工具

- **轨迹埋点（Trace Instrumentation）**：观察智能体内部到底在做什么
- **评估运行器（Eval Runner）**：内含 LLM-as-a-judge
- **数据集（Datasets）**：用于重复跑实验
- **人工反馈（Human Feedback）**：在生产中抓取人工标注
- **Prompt Playground**：在数据上快速迭代 Prompt

## 小结

本课你了解了：模型评估 vs 系统评估、LLM 应用相比传统软件需要不同测试范式、智能体多出来的推理/路由/行动复杂度、常见失败模式（工具选错、上下文误用），以及从开发到生产用同一套工具持续迭代的重要性。下一课，我们开始动手搭智能体并细看每一步评估。

# L0 · 课程介绍（Building and Evaluating Data Agents）

> 课程：Building and Evaluating Data Agents（DeepLearning.AI × Snowflake）
> 讲师：Anupam（Snowflake AI research lead）与 Josh Reini（Snowflake developer advocate，前 CMU 教授、可观测性创业公司 TruEra 创始人——被 Snowflake 收购，至今维护开源库 **TruLens**）。开场由 Andrew Ng 引入。

## 这门课教什么

这门课带你**从零手写一个 data agent**，并把"评测"作为一等公民贯穿整个开发迭代：

- **构建**：agent 会做 web search 收集数据源、分析数据、可视化结果、给出洞见（例如把结果整理成一封邮件报告发出去）。
- **离线评测（offline evals）**：用评测指标驱动 agent 设计的改进与迭代——改逻辑、改 prompt、换模型。
- **实时评测（inline / runtime evals）**：让 agent 在**运行过程中**就拿到反馈，边跑边调整检索与分析策略。

这是本课与只讲"怎么搭 agent"的课程最大的区别：**评测不是事后打分，而是开发回路和运行回路里的控制信号**。

## 两条评测回路

```
                   ┌─────────── 离线回路（开发者迭代）───────────┐
   user query ──▶  data agent ──▶ 最终答案 + 中间检索        │
                        │              │                        │
                        │              ▼                        │
                        │        LLM-as-judge 打分              │
                        │   · answer relevance（答案是否切题）  │
                        │   · context relevance（检索是否切题） │
                        │   · groundedness（答案是否有据可依）  │
                        │              │                        │
                        │              ▼                        │
                        │   改逻辑 / 改 prompt / 换模型 ────────┘
                        │
                   ┌────┴──── 实时回路（agent 自我修正）────────┐
                   │  每步检索后 → inline eval 给出 context     │
                   │  relevance 分 → 若不足，plan executer 要求 │
                   │  planner 重新规划（replan）                │
                   └───────────────────────────────────────────┘
```

**离线**衡量端到端表现：答案是否 relevant、检索数据是否 relevant、答案是否 grounded 在检索结果里。**实时**则把 context relevance 分数在每个检索步之后立刻反馈给 plan executer，一旦某步检索"缺乏上下文相关性"，plan executer 就回头让 planner 调整计划。两条回路都依赖对 agent 的 **tracing（追踪/埋点）**——本课也会讲。

> **架构师视角**：大多数团队把 eval 当作发布前的一次性验收（跑个测试集、看个准确率）。这门课的立场是——**同一套 judge 指标既是离线的迭代罗盘，又是运行时的反馈信号**。当你把 context relevance 从"报告里的一个数字"变成"plan executer 的一个输入"，评测就从度量变成了控制。这正是 data agent 可信度工程的核心姿态。

## Agent 的形态：多 agent 工作流

本课的 data agent 不是单体，而是一个**多 agent 工作流**：

| 角色 | 职责 |
|---|---|
| **Planner** | 接用户 query，拆成计划（有编号的子目标/子查询） |
| **Plan Executer** | 按计划推进，决定下一步该调哪个专职 agent；每个检索步后**反思**计划、决定是否更新（replan） |
| 专职 agents | web / data researcher（检索）、data visualizer（画图）、response synthesizer（合成回答） |

各 agent 通过共享的 **agent state** 传递执行结果与计划状态。要评的不只是最终答案，还有：

- **检索质量**：每步取回的数据对不对；
- **计划质量**：计划是否对齐用户请求？行动是否对齐计划？执行是否高效、有逻辑？

这套"计划—行动"的评测维度，下一课会正式命名为 **GPA（Goal / Plan / Action）三维度评测**。

> **对比《Evaluating AI Agents》（已学课程 21）**：课程 21 教的是通用 agent 的评测方法论（trajectory、tool-call 正确性、LLM-as-judge 的搭建）。本课是它在 **data agent** 场景的落地专精——评测对象具体化为"NL→SQL 检索质量、跨数据源的计划质量、可视化答案的 groundedness"，并且把 judge 从离线搬进了 runtime。学完 21 再看本课，是"评测总论 → data 场景专论 + 实时化"的递进。

## 课程路线（L2–L6）

| 课 | 主题 |
|---|---|
| L1 | data agent 定义、如何工作、GPA 三维度评测框架、可信度 |
| L2 | 用 **LangGraph** 搭多 agent 工作流：planner + executor + web researcher + 画图 + synthesizer |
| L3 | 扩展检索能力：接入 **Snowflake Cortex**（text-to-SQL + 文档搜索），跨内外部数据源 |
| L4 | 加 **tracing**（OpenTelemetry 兼容）+ 用 **TruLens** 做首批 goal-completion 评测（RAG triad） |
| L5 | 扩到 GPA 全维度：plan quality / plan adherence / logical consistency / execution efficiency；展示失败模式 |
| L6 | 依据评测结果改进 agent；Conclusion 收尾 |

> **记忆点（引出 L1）**：本课的关键词是"**边建边评**"——agent 的形态是 planner/executer/专职 agent 的多 agent 工作流，而衡量它"可信"的标尺是 GPA。L1 先把 data agent 讲清楚：它是什么、怎么规划与行动、以及"可信 = 高 GPA（Goal/Plan/Action 三者对齐）"这个贯穿全课的评测框架。

## 一、Claude Code 用得好的几个准则

> "You can make the best out of Claude Code when you give it clear instructions, clarify the context, and point it to the relevant files in your codebase."

三个底层心法：
1. **清晰的指令**（明确说要什么、不要什么）
2. **明确的 context**（不靠 Claude 猜，主动给）
3. **指向正确的文件**（`@file` / `@folder` 是最直接的工具）

记忆系统：
- 把项目规则 + 你希望 Claude 记住的信息写进 **CLAUDE.md**
- 三层（项目 / 项目-local / 用户全局）按归属分清

扩展能力：
- 通过 **MCP server**（如 Playwright、Figma）把 Claude Code 接到外部系统

## 三、架构师视角的总结

- **Claude Code = 模型 + 小工具集 + 本地环境 + 记忆 + MCP 扩展点**。它的设计哲学是"少而精的原语 + 强模型的智能调度"。
- **HITL 是分级的**：每次询问 → auto-accept → 完全自治。按对任务的信任度移动这个滑块。
- **Plan 模式 + Extended Thinking 是高质量起手**，复杂任务从不"裸跑"。
- **并行 ≠ 简单复制 Claude 实例**——靠 Git worktrees 做物理隔离 + 测试做合并安全网。
- **MCP 让 Claude Code 不止是"代码助手"**：接 Figma 就能做设计实现、接 Playwright 就能做视觉验证、接 GitHub 就能进 PR/Issue 循环。这是它长期生命力的根。

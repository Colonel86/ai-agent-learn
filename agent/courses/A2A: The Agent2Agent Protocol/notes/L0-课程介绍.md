# L0 · 课程介绍（A2A: The Agent2Agent Protocol）

> 课程：A2A: The Agent2Agent Protocol（DeepLearning.AI × Google Cloud × IBM Research）
> 讲师：Holt Skinner、Ivan Nardini（Google Cloud）+ Sandi Besen（IBM）
> 一句话定位：学会用 **A2A 协议**把任意框架构建的 agent 包装成可互相发现、互相委派任务的标准化服务，最终搭出一个**跨框架的医疗多 agent 系统**并部署运维。

## 0. 为什么是 A2A

agent 间通信曾有多个相互竞争的协议；自 **IBM 与 Google 合流**（IBM 的 Agent Communication Protocol 在 Google 2025 年 4 月发布 A2A 后不久并入）之后，A2A 正在成为行业主导标准。A2A 开源、由 **Linux Foundation** 社区治理。

它与 MCP **解耦但互补**——这是全课反复出现的一对关系：

| 协议 | 标准化的是 | 一句话 |
|---|---|---|
| MCP | agent ↔ 工具 / API / 资源 | agent 怎么**拿信息、干活** |
| A2A | agent ↔ 对等 agent（peer agents） | agent 怎么**找同伴、派任务** |

> **对比 06-protocols.md**：我的选型矩阵早已写下同一结论——"**MCP 接工具/数据（锚 L1）+ A2A 接 agent（锚 L4）**"的 2026 两层参考架构。这门课等于官方视角把 A2A 那一层展开成 12 课。矩阵里的冷水判据同样带着听：**同进程多角色用框架内 handoff 就够，跨进程/跨团队/跨组织才是 A2A 的回本点**。

## 1. 核心概念表（L0 提到的全部要素）

| 概念 | 是什么 |
|---|---|
| A2A Server | 把任意框架构建的 agent **包装**成对外服务的一层 |
| Agent Card | JSON 文档，描述 agent 的 **capabilities、endpoint、authentication requirements**——server 对外公布的"合同" |
| A2A Client | 发现 A2A server、读 Agent Card、按合同构造请求的一方；它本身可以是**另一个 AI agent，也可以是任何软件应用** |
| Orchestrator agent | 处理用户请求、经 A2A 把任务**路由**给专家 agent 的编排者 |
| 解耦效应 | 通信走标准化 client-server 接口 → 各团队**独立更新自己的 agent，其他人不用改代码**；存量 agent 也容易接入多 agent 工作流 |
| 内建 A2A 支持的框架 | Google ADK、Microsoft Agent Framework、BeeAI 等 |

课程开场的示例：客服多 agent 系统——一个团队建 logistics agent（订单状态），另一个团队建 RAG agent（产品通用问答），**各用不同框架**、各自暴露成 A2A server，由 orchestrator 统一路由。

```
                 用户咨询
                    │
            ┌───────▼────────┐
            │ Orchestrator    │ ← A2A Client
            └──┬─────────┬───┘
        A2A    │         │    A2A
     ┌─────────▼──┐  ┌───▼──────────┐
     │ Logistics   │  │ RAG Agent    │   各自是 A2A Server
     │ (框架 X)    │  │ (框架 Y)     │   各自发布 Agent Card
     └────────────┘  └──────────────┘
```

## 2. 贯穿全课的动手项目：医疗多 agent 系统

三个 remote agent，**故意用三种不同技术栈**，验证 A2A 的跨框架互操作：

| Remote Agent | 职责 | 技术栈 |
|---|---|---|
| Insurance agent | 回答保险覆盖问题 | **Claude on Vertex AI** |
| Health research agent | 搜索健康相关信息 | **Google ADK** |
| Doctor matching agent | 匹配医生（挂 MCP server 取医生数据） | **LangGraph** |

## 3. 课程路线（L1–L12）

| 课 | 内容 | 性质 |
|---|---|---|
| L1 | 开放标准的重要性、A2A 填补的空白、使用场景 | 概念 |
| L2 | A2A 在技术栈中的位置、整体架构、agent 生命周期 | 概念 |
| L3 | 构建 QA（insurance）agent：Claude on Vertex AI | lab |
| L4 | 把 agent 包装成 A2A Server | lab |
| L5 | 构建通用 A2A Client（可与任何 A2A server 通信） | lab |
| L6 | 用 Google ADK 构建 research agent | lab |
| L7 | ADK Sequential Chain：把 insurance + research agent 串行编排 | lab |
| L8 | LangGraph + MCP 构建 doctor matching（provider）agent | lab |
| L9 | 用 Microsoft Agent Framework 的 client 连接 A2A server | lab |
| L10 | BeeAI 多 agent 系统：不再硬编码串链，用 **requirement agent 动态 handoff** | lab |
| L11 | 生产部署：Agent Stack（开源、可自托管的 agent 基础设施——快速部署、框架灵活、数据可控） | lab |
| L12 | day-two 运维 | lab |

> **架构师视角**：这个课程设计本身就是 A2A 的最佳论证——L3-L8 三个 agent 分别用 Claude 裸调、ADK、LangGraph 三套栈构建，L9 再换 Microsoft Agent Framework 当 client，L10 用 BeeAI 编排。**任何一层都可独立替换**，因为边界是协议而不是框架 API。Andrew 收尾点题：A2A 标准化的通信可以发生在**同一开发者、同组织不同团队、甚至不同组织之间**——协议的价值随组织边界的跨越而放大。

> **记忆点（引出 L1）**：A2A = 让"各自为政的 agent 框架"获得一门共同语言的开放标准。但为什么必须是**开放标准**而不是某家的 SDK？L1 用 HTTP 战胜 FTP/Gopher 的历史回答这个问题。

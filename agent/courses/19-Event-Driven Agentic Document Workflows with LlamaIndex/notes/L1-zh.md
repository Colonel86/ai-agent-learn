# L1：智能文档工作流的基础概念

本节课不写代码，先把后面要用到的几个核心概念串起来：**RAG**、**Agent（智能体）**、**Workflow（工作流）**，以及它们如何组合成 **ADW（Agentic Document Workflows）**。

## RAG：让模型用上你自己的数据

LLM 训练时见过海量公开数据，但**没见过你的数据**。要让它回答关于你私有数据的问题，就必须把数据喂给它。但 LLM 还有一个天然限制——**上下文窗口（Context Window）**。即使是当今最强的 LLM，一次也只能处理约 100 万 token，而企业内部的数据往往是几千万、上亿 token 级别。所以必须**有选择地**只把最相关的部分喂给它。

**RAG（Retrieval Augmented Generation，检索增强生成）** 就是为这个问题而生：

1. **嵌入（Embedding）**：用嵌入模型把文本编码成"向量（vector）"，所有可能向量的集合称为向量空间（vector space）；向量编码的是"含义"。
2. **入库**：把这些向量存进向量数据库。
3. **检索（Retrieval）**：把用户提问也用同一个嵌入模型编码成向量，在向量空间里找**几何上邻近**的向量——它们对应的就是和问题"意思相近"的文本片段。
4. **生成（Generation）**：把问题与检索到的上下文（context）一起交给另一个 LLM，让它**基于上下文**回答问题。

"检索"加"生成"，合起来就是 RAG。

## RAG 的局限

RAG 强大但并非万能。一个典型短板是**复杂或多部分问题**：

- RAG 本质上是搜索，多部分问题会同时去匹配很多东西，结果就不聚焦；
- 拿到一堆相关性平庸的片段，反而拼不出完整答案。

解法是：让 LLM 把复杂问题**拆分成一堆简单问题**，每个简单问题分别去检索，最后再让 LLM 把多个小答案**合成（synthesize）** 为连贯的最终回答。LLM 既擅长"拆"，也擅长"合"——这正是 Agent 要替我们干的事。

## Agent 是什么

Agent 这个词比较模糊。在 LlamaIndex 的语境里，Agent 指的是一种**半自主的软件**：你给它工具（tools）和目标（goal），它能自己想办法解决问题，**不需要你手把手地给一步步的指令**。这和传统编程截然不同——传统程序里每一步都精确写死。

## Workflow：搭建 Agent 的积木

在 LlamaIndex 里，构建 Agent 的方式是使用 **Workflow（工作流）**。

- Workflow 是**事件驱动（event-based）**的系统；
- 你定义一连串**步骤（steps）**，步骤之间通过**事件（events）** 连接，数据随事件在步骤间流动；
- 可以构造**分支（branches）**、**循环（loops）**、**并发执行（parallel execution）**，足以表达任意复杂任务。

Laurie 给出了一个对比：

- 一些 Agent 框架**完全没有结构**，结果容易混乱；
- 另一些采用**图（graph-based）** 方式建模，循环和复杂控制就比较别扭；
- **Workflow 介于两者之间**，既灵活又结构化。

## 什么是 ADW

把 RAG、Agent、Workflow 三个东西组合起来，就是 **ADW（Agentic Document Workflows，智能文档工作流）**：

- 把 Agent 化的工作流嵌入到更大的软件中，解决真实业务问题；
- 在 RAG 的基础上向前一步——RAG 主要回答简单问题，**ADW 处理复杂问题并产出结构化的特定输出**，而不仅仅是一段自然语言。

# L4 组件级评测（Component-Level Evals）

## 为什么不只靠端到端 eval

研究 agent 的"漏关键点"被定位到 web search 组件。如果每改一次搜索引擎就**重跑整条端到端流水线**：

1. **慢且贵**：一次跑要走完多个 LLM 调用。
2. **信噪比差**：其它组件本身的随机性会**掩盖**掉 web search 的小幅提升。

→ 给被锁定的组件**单独建一个 eval**，更高效。

## 怎么给 web search 建组件级 eval

1. **挑一批 query**。
2. 对每个 query，让专家列出"**理想的高权威 web 资源**"作为 gold standard（哪些 URL 是真该被搜出来的）。
3. 跑 web search 拿到结果列表。
4. 用信息检索的标准指标（如 **F1 score**）衡量：返回结果和 gold standard 列表的重合度。

> F1 等指标的细节不懂没关系，重点是**有了一个能量化"这次搜索好不好"的数字**。

## 有了组件 eval 能做什么

可以快速做**超参 / 配置实验**：

- 换搜索引擎：Google / Bing / DuckDuckGo / Tavily / You.com……
- 调返回结果数量。
- 调时间范围。

每改一个，几秒到几十秒就能看到组件分数变化，**不用重跑整条流水线**。

## 最后别忘了端到端复测

组件级分数涨了 ≠ 整体一定涨。组件调到满意后，**再跑一次端到端 eval** 确认整体确实在变好。这一步是闭环。

## 组件级 eval 的额外好处

1. **信号更干净**：把组件从整个系统的噪声里隔离出来。
2. **团队分工友好**：负责 web search 的人盯自己的指标干活，不用每次都协调全链路联调。

## 实务建议

不是每个组件都值得建组件级 eval。**决定要重点改这个组件了**，再考虑建不建。建了能加速迭代，就建；如果改 1–2 次就完事，端到端 eval 也够。

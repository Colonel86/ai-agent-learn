# L0 · 课程介绍：给 AI Agent 装上数据治理

> 课程：Governing AI Agents（DeepLearning.AI × Databricks）
> 讲师：Amber Roberts（Databricks Staff Technical Marketing Manager）；Andrew Ng 参与开场对谈。致谢名单：Nicolas Pelaez、Ben Wilson（Databricks），Hawraa Salami（DeepLearning.AI）。

## 一句话定位

**核心问题**：假设你要造一个客户分析 Agent，给它一组工具去读客户人口统计、交易、网站互动、问卷数据。如果直接给 Agent 对所有数据的**宽泛权限**（broad permissions），它就有可能泄露不该被全体员工看到的私密信息——信用卡、住址、个人购买行为。

**本课答案**：把 **data governance（数据治理）**集成进 Agent 的工作流。数据治理是一组策略与实践，保证三件事：① Agent 只能访问**任务所需**的数据；② 个人信息受保护、免于未授权访问；③ 你和团队能**持续监控** Agent 的表现。落到手段上：在部署环境里指定 Agent 可访问的表/列、加密客户 ID、mask 信用卡信息；给输入输出加数据质量检查点；用 evals 度量输出质量；启用 observability 记录 Agent 的每个处理步骤——这些共同支撑持续监控与故障调试。

> **架构师视角**：这门课站的位置和大多数 Agent 课不同——不是"怎么把 Agent 做得更聪明"，而是"怎么让 Agent **有权做的事**被系统性约束"。护栏（guardrails）拦的是**运行时的一次请求**，治理管的是**部署环境本身的权限与可见性**：就算 prompt 注入骗过了模型，Agent 的凭证也拿不到视图之外的数据。两层互补，不可互替。

## 核心概念/类比

| 概念 | 类比 | 一句话 |
|---|---|---|
| Data Governance | 公司的财务制度（而非某次报销审批） | 策略+实践的框架：只给所需数据、保护 PII、可监控 |
| Least Privilege Access | 只给保洁员工具间钥匙，不给全楼万能钥匙 | Agent 得到的是"特定、有意图"的最小访问权 |
| View（视图） | 给外人看的"脱敏版报表" | 行为像表的 SQL 查询，只含 Agent 任务所需的数据 |
| Unity Catalog | 数据界的"权限中枢+资产台账" | 开源数据目录，保证只有获授权的 Agent/用户能用数据和工具 |
| MLflow Tracing | 行车记录仪 | 记录 Agent 每一步处理，供评估与调试 |

## 课程路线（也是动手实验的主线）

在 Databricks 上构建并部署一个受治理的 Agent，全程贯穿治理实践：

| 步骤 | 内容 |
|---|---|
| ① 视图 | 用 view（行为像表的 SQL 查询）给 Agent 特定、有意图的最小访问权 |
| ② 权限 | 学会为 Agent 指定 permissions，让它能访问这些视图 |
| ③ 工具 | 构建数据访问工具，并注册为 **Unity Catalog 里的 function** |
| ④ Agent 逻辑 | 用 OpenAI SDK 实现 Agent，做 evaluate，用 MLflow 开 tracing |
| ⑤ 部署 | 部署 Agent（可用 Databricks Free Edition 免费跟练全部 lab） |

> **对比 CrewAI 生产课 L12 的中心化 enablement 治理**：那门课的"治理"是组织维度的——中心团队管模板、管上线流程、管谁能建 Agent；本课的治理是**数据平面**维度的——管 Agent 的凭证能碰到哪张表、哪一列。前者治"人与流程"，后者治"数据与权限"，企业级落地两者都要。

> **记忆点（引出 L1）**：Andrew 收尾点题——下一课 Amber 会讲 **AI Agent 数据治理的四大支柱**：**Lifecycle Management、Risk Management、Security、Observability**。这四根柱子概括了"治理一个 Agent 到底要管哪些事"，是全课的总纲。

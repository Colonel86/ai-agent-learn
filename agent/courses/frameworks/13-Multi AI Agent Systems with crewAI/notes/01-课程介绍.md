## 二、什么是多智能体工作流？

**多智能体工作流（Multi-agent workflows）** 允许我们把一个复杂任务拆解为多个子任务，再由各自扮演特定角色的 Agent 分别执行。

### 示例一：撰写研究报告

若目标是"写一份研究报告"，可以设计以下角色：

- **Researcher**（研究员）
- **Writer**（撰稿人）
- **Fact Checker**（事实核查员）

### 示例二：搭建网站

若目标是"搭建一个网站"，角色可以是：

- **Web Designer**（网页设计师）
- **Software Engineer**（软件工程师）
- **Testing Engineer**（测试工程师）

## 五、如何组织 Agent 之间的协作

在组装 Agentic 工作流时，你还需要定义：

- **协作方式**：Agent 之间如何合作
- **委派能力（Delegation）**：哪些 Agent 可以把特定任务（如研究）委派给其他 Agent
- **执行模式**：
  - **并行（Parallel）**
  - **串行（Series）**
  - **层级式（Hierarchical）**——由一个 **Manager Agent** 向多个 **Worker Agent** 分派任务

João 将通过开源库 **crewAI** 来讲解这些概念。

João 特别强调了一个重要的心智模型转变：

> **优秀的多智能体系统设计，就像是在当一位管理者。**

1. 识别**目标（Goals）**

## 面试速答总结

**一句话**：多智能体系统 = 把复杂任务拆成子任务、由各自扮演角色的 Agent 分工完成；构建块是 **Role-playing / Tool use / Memory / Guardrails / Collaboration** 五件套，协作有**并行 / 串行 / 层级（Manager-Worker）**三种模式；设计它的心智模型不是写代码而是**当管理者**——识别目标、定义角色、给"成功"设清晰预期。

### 面试回答骨架（问"多 agent 系统由哪些构建块组成 / 怎么开始设计一个多 agent 系统"）

> 1. **先给分解逻辑**：多 agent 的本质是**任务分解 + 角色专精**——写研究报告拆成 Researcher/Writer/Fact Checker，搭网站拆成 Designer/Engineer/Tester。拆的依据是"角色天然分工"，不是为拆而拆。
> 2. **报五大构建块**（这是所有多 agent 框架的通用清单，crewAI 只是载体）：**Role-playing**（角色扮演提升表现）、**Tool use**（与外部世界交互）、**Memory**（跨任务共享上下文）、**Guardrails**（行为边界）、**Collaboration**（协作与委派）。
> 3. **协作模式三型**：**串行**（前一个的输出是后一个的输入）、**并行**（子任务独立）、**层级**（Manager Agent 向 Worker 分派）——外加**委派能力（delegation）**这个横向自由度：哪些 agent 能把活转给别人。
> 4. **收在心智转变**：设计多 agent 系统 = 被"晋升"为 Agent 的管理者——①识别目标 ②定义角色 ③给"成功"设**清晰预期**。第三条最关键，它直接对应后面 Task 的 `expected_output`。

### 关键判断（加分点）

- **五大构建块可横向迁移**：对到通用架构就是 工具层 / 记忆层 / 护栏层 / 编排层——面试时能把 crewAI 的清单映射到任意框架（LangGraph/AutoGen）或分层选型矩阵，体现的是抽象而不是框架背诵。
- **"管理者心智"不是修辞**：它意味着质量来自**角色定义和预期清晰度**，而不是来自改代码——多 agent 系统调优的第一杠杆是 prompt 里的角色与验收预期，第二才是结构。
- **层级模式有成本**：Manager-Worker 最强也最贵（多一层模型调用与协调开销），串行够用就别上层级——呼应"最轻起步"。

**一句话收尾**：多 agent 系统 = 管理者视角下的"目标→角色→清晰预期"，用 Role-playing/Tools/Memory/Guardrails/Collaboration 五件套组装，协作模式从串行起步、复杂度到了再升层级。

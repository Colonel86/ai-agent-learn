## 一、自定义 Component 的契约

Haystack 对自定义组件只有两条硬要求：

1. **用 `@component` 装饰类**。
2. **实现 `run(self, ...)` 方法，并用 `@component.output_types(...)` 声明输出端口的类型**。

```python
from haystack import component

@component
class Greeter:
    @component.output_types(greeting=str)
    def run(self, user_name: str):
        return {"greeting": f"Hello {user_name}"}
```

- 输入端口 = `run()` 的形参名。
- 输出端口 = `output_types` 声明的键名，必须与 `run()` 返回 dict 的键一致。
- 这两套"端口名"就是 `pipeline.connect("greeter.greeting", "prompt.dialogue")` 里能引用的标识。

> **架构意义**：Haystack 不要求继承基类、不要求注册中心，只要装饰器 + 端口声明，**任何 Python 函数都能 5 行内变成可编排组件**。这是它扩展性强的关键。

## 二、组合进 Pipeline

```python
dialogue_builder = Pipeline()
dialogue_builder.add_component("greeter", Greeter())
dialogue_builder.add_component("prompt",  PromptBuilder(template=template))
dialogue_builder.add_component("llm",     OpenAIGenerator())

dialogue_builder.connect("greeter.greeting", "prompt.dialogue")
dialogue_builder.connect("prompt", "llm")
```

`template` 里的 `{{ dialogue }}` 与 `Greeter` 的输出 `greeting` 通过 `connect` 显式接线——名字可以不同，端口才是契约。

## 三、实战：Hacker News 摘要器

需求：抓 Hacker News 当前 Top-K 帖子 → 抽正文 → 让 LLM 写摘要。

### 3.1 Component 封装一个子 Pipeline

`HackernewsNewestFetcher` 内部**自己持有一个 sub-pipeline**（fetcher + converter），用于把 URL 转成 Document：

```python
@component
class HackernewsNewestFetcher:
    def __init__(self):
        html_conversion_pipeline = Pipeline()
        html_conversion_pipeline.add_component("fetcher",   LinkContentFetcher())
        html_conversion_pipeline.add_component("converter", HTMLToDocument())
        html_conversion_pipeline.connect("fetcher", "converter")
        self.html_pipeline = html_conversion_pipeline

    @component.output_types(articles=List[Document])
    def run(self, top_k: int):
        articles = []
        trending = requests.get(
            "https://hacker-news.firebaseio.com/v0/topstories.json?print=pretty"
        ).json()
        for hid in trending[:top_k]:
            post = requests.get(
                f"https://hacker-news.firebaseio.com/v0/item/{hid}.json?print=pretty"
            ).json()
            if "url" in post:
                article = self.html_pipeline.run({"fetcher": {"urls": [post["url"]]}})
                articles.append(article["converter"]["documents"][0])
            elif "text" in post:   # Ask HN 这类无 URL 帖子
                articles.append(Document(content=post["text"], meta={"title": post["title"]}))
        return {"articles": articles}
```

> **设计要点**：Pipeline 可以嵌套——外层 Pipeline 的一个 Component 内部又跑一个 Pipeline。复用现成组件（`LinkContentFetcher` + `HTMLToDocument`）而不是手写 requests + BeautifulSoup。

### 3.2 顶层摘要 Pipeline

```mermaid
flowchart LR
    A["fetcher(top_k)"] --> B["prompt(articles=…)"] --> C["llm"]
```

```python
summarizer = Pipeline()
summarizer.add_component("fetcher", HackernewsNewestFetcher())
summarizer.add_component("prompt",  PromptBuilder(template=prompt_template))
summarizer.add_component("llm",     OpenAIGenerator())

summarizer.connect("fetcher.articles", "prompt.articles")
summarizer.connect("prompt", "llm")

summarizer.run({"fetcher": {"top_k": 3}})
```

模板里直接遍历 articles 并引用 `article.meta["url"]`：

```jinja

  {{ article.content }}
  URL: {{ article.meta["url"] }}
{% endfor %}
```

## 四、架构取舍

- **何时写自定义 Component？** —— 当逻辑是"业务专属 I/O"（特定 API、内部数据库、私有协议）时；通用能力（fetch HTML、split、embed、retrieve）优先用现成组件。
- **要不要在 Component 里嵌 sub-pipeline？** —— 当你想**复用一组组件 + 但希望把它们当成一个原子单元暴露给外层**时，嵌套是最干净的方式。比起把所有节点摊在外层，调用方只看到 `articles=…` 一个端口。
- **错误处理放哪里？** —— 例子里 `try/except` 跳过下载失败的帖子并 `print`，是典型的"在 Component 内做局部容错"。Pipeline 层不感知。

---

## 五、本节要点

- `@component` + `@component.output_types` 是把任意 Python 类变成 Haystack 组件的全部门槛。
- `run()` 的形参 = 输入端口，返回 dict 的键 = 输出端口。
- Component 内部可以再持有一个 Pipeline——天然支持"模块化封装"。
- `meta` 在自定义 fetcher 里就要写好，下游模板才能直接消费。

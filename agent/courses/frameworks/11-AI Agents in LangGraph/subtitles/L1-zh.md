**智能体工作流的直觉**

三人合写论文的比喻很好地诠释了 Agentic 工作流：Andrew 负责规划和撰写大纲，Rotem 负责搜索相关资料，Harrison 负责撰写初稿，Andrew 再进行审阅提出修改建议，根据需要循环迭代——这比"从第一个词写到最后一个词、中间不许退格"的一次性生成方式，能产出质量高得多的成果。

---

**智能体工作流的五大设计模式**

- **规划**：思考需要执行哪些步骤，如先列大纲再执行
- **工具使用**：了解有哪些工具可用及如何使用，如搜索工具
- **反思**：迭代改进结果，可由多个 LLM 相互批评和提供建议
- **多智能体通信**：每个智能体被赋予独特的角色和提示词
- **记忆**：跨多个步骤追踪进度和中间结果

其中部分能力（如函数调用）依赖 LLM 本身，但许多能力实际上由 LLM 运行所在的**框架**来实现。

---

**为什么是 LangGraph？**

LangChain 已支持记忆、函数调用、工具执行等能力，但观察 ReAct 智能体、Self-Refine（迭代精炼）、AlphaCode 等各类智能体的行为图，可以发现它们都由**有向循环图**定义。为了直接支持这类图结构智能体的构建，LangChain 推出了 **LangGraph**。

- 从零开始用 Python 和 LLM 构建一个智能体

- 最终构建一个完整的 LangGraph 项目

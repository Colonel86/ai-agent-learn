# L4 结构化抽取:用 function calling 从非结构化文本里抽数据

## 一个视角转换

前面 function calling 是"调工具"。这课发现:**"从查询里抽参数填进函数"这个动作本身,就可以当成数据抽取用。** 你不是真的要执行这个函数,你只是借它的"参数抽取"能力,把非结构化文本里的信息抽成结构化字段。

例:文本 "Mary had a little lamb",定义一个函数参数为 `(person_name, owned_object)`,模型就把 `person_name="Mary", owned_object="lamb"` 抽出来。函数根本不用真跑,你要的就是这组抽出来的参数。

**这和 07a 那门课(结构化输出)是同一个目标的两条路**:07a 用约束解码/JSON schema 强制输出结构;这里用 function calling 的参数抽取能力达成结构化。殊途同归。

## 简单情形 vs 复杂情形

- **简单**:名字→地址一一对应,直接函数参数 `names: list[str]`、`addresses: list[str]` 就行。
- **复杂(不平衡映射)**:一个人对应多个地址(John Tech → 三个地址)。这时候两个平行 list 对不齐了,改用 **dataclass**:定义 `Record(name: str, addresses: list[str])`,函数参数是 `list[Record]`。模型能理解 dataclass(它在 Python 上训练过),把每个人和其多个地址正确打包成一个个 Record 实例。

> 要点:**dataclass 的字段名要起得有意义**——模型是靠字段名理解你的意图的(和 docstring 一个道理)。这也和你已学的 `07-Pydantic` 相通:类型化的字段定义就是给模型的契约。

## 一个巧妙技巧:用嵌套调用生成合法的嵌套 JSON

小模型(7B/13B)有时很难稳定吐出合法的嵌套 JSON。课程的解法很妙:**把 JSON 的层级结构,映射成嵌套函数调用的层级。**

想要 `{city: {country: {continent: ...}}}` 这种三层 JSON,就定义三个函数,层层嵌套(city_info 需要 location dict,location dict 需要 continent dict)。模型为了填最外层函数的参数,必须先嵌套调用内层函数——**嵌套调用的层级天然就构成了你要的 JSON 层级**。配合 Python 的 `locals()`(把当前作用域变量当 dict 返回),就把嵌套调用的结果拼成合法嵌套 JSON。

> ⚠️ 时效:这个"用嵌套函数凑合法 JSON"的技巧,是当年小模型 JSON 能力弱时的变通。今天有了 07a 讲的**约束解码**(Outlines)和主流模型的原生 structured output,直接就能保证合法嵌套 JSON,不需要这么绕。**但这个例子很好地展示了 function calling 和结构化输出本质是相通的**——两门课(07a / 07b)在这里交汇。

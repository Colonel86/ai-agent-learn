# L5 实战应用:联网搜索 + 数据库对话(附一个关键的安全取舍)

## 主题:用 function calling 给 LLM 补上"实时数据"和"私有数据"

LLM 训练在静态数据上,天然有两个盲区:训练截止后的新信息、锁在企业内部数据库里的信息。Function calling 是给这两个盲区补数据的手段——这本质就是 **grounding(接地)**。

## 应用一:联网搜索(补实时信息)

例:问一个训练截止后才发布的产品,模型直接说"我不知道"。解法:
1. 写个 `do_web_search(query, num_results)` 工具,内部调搜索 API,把结果拼成字符串返回。
2. 给模型这个工具 + 用户问题 → 模型生成搜索调用 → 执行 → 拿到搜索结果。
3. **把搜索结果连同原问题再喂回模型** → 得到有依据(grounded)的回答。

这个"检索→把结果塞回上下文→再生成"的循环,就是 RAG 的骨架。对应你已学的 RAG 系列课。课程还提到用 **one-shot 示例**帮模型理解怎么用这个搜索工具。

## 应用二:和 SQL 数据库对话(补私有数据)

例:"我们公司卖的最贵的东西是什么?" 答案在内部数据库里。做法:
1. 建个 toys 表(name, price)。
2. **把数据库 schema 提供给模型**(告诉它有个 toys 表、有哪些列)——不给 schema 模型没法生成正确 SQL。
3. 模型生成 SQL(`SELECT ... ORDER BY price DESC LIMIT 1`)→ 执行 → 结果喂回模型 → 自然语言回答。

## 本课最有价值的点:两种数据库访问模式的安全取舍 ⭐

课程明确对比了两种让 LLM 访问数据库的方式:

| 模式 | 做法 | 风险 |
|---|---|---|
| **原生 SQL** | 让模型直接生成 raw SQL 去执行 | 强大但危险——模型能生成任意 SQL,可能 DROP 表、越权读取、SQL 注入 |
| **受控/模板化(gated)** | 预先定义一组安全函数(`list_toys` / `find_by_price_range` / `get_most_expensive` …),模型只能调这些**白名单函数**,SQL 藏在函数内部 | 更安全——模型碰不到 raw SQL,只能在你允许的操作范围内活动;也不用把 schema 暴露给模型 |

**这是整门课最重要的架构/面试点。** 它是"让模型有多大权限"的经典权衡:

- 原生 SQL = 给模型一把万能钥匙(灵活但危险)
- 模板化函数 = 给模型一串预配好的、每把只能开一扇门的钥匙(受限但可控)

直接对应你面试包 `07-safety-guardrails`(越权工具拦截)和 `02-tool-gateway`(工具契约、最小权限)。面试里被问"你怎么让 Agent 安全地访问数据库",这个"raw SQL vs 白名单工具函数"的对比就是标准答案骨架——而且能延伸到:**agent 的写操作永远应该走预定义的、带权限校验的 action,而不是让它生成任意可执行代码/SQL**(这也正是 Palantir Ontology 的 action type 设计、以及你 FDE 笔记里那条"agent 只能调预定义 action"的思想)。

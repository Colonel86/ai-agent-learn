# L0 · 课程介绍：用 Guardrails 构建安全可靠的 AI 应用

> 课程：Safe and Reliable AI via Guardrails（DeepLearning.AI × GuardrailsAI）
> 讲师：Shreya Rajpal（GuardrailsAI CEO & Co-Founder，职业生涯长期做 AI reliability，包括自动驾驶系统；Predibase 创始工程师）；Andrew Ng 开场对谈。致谢：Zayd Simjee（GuardrailsAI）、Tommy Nelson（DeepLearning.AI）。

## 一句话定位

**核心问题**：GPT-4、Claude、Gemini 等 API 让搭 prototype 变得极快，但要从 POC 走向生产，团队都会撞上同一堵墙——**LLM 的输出无法提前预测**。prompting、fine-tuning、RLHF、RAG 这些技术都有帮助，但**都不能完全消除输出的变异性与不可预测性**。对有严格监管要求的行业（GuardrailsAI 的客户集中在 healthcare、government、finance）或要求高一致性的客户，LLM 单独使用**不够可信（not trustworthy enough）**，这直接卡住了落地。

**本课答案**：Guardrails——内建于 AI 应用的**安全机制与验证工具**，在**运行时（runtime）**确保应用遵循特定规则、运行在预定义边界内。它作为保护性框架，拦截 LLM 的非预期输出，让行为对齐开发者的预期，为应用提供一层关键的控制与监督（control and oversight）。

**实现核心是 validator**：一个函数，输入是用户 prompt 和/或 LLM 响应，检查其是否符合某条预定义规则——

- **简单形态**：一个 regex 检查文本里有没有电话/邮箱等 PII，命中就抛异常、阻止信息泄露给用户；
- **进阶形态**：用 ML 模型（Transformers）甚至另一个 LLM 做更复杂的文本分析——让 chatbot 按允许话题清单**保持在主题内**、阻止特定词出现在回复里（避免商标词/竞品名）；
- **降幻觉形态**：课程后段会用 **NLI（natural language inference）模型**构建幻觉 validator，检查 RAG 系统的回答**是否真正 grounded 在检索出的原文上**（即源文本能确认 LLM 生成内容的真实性）。

一个反直觉的要点：guardrails 大量使用**更小的 ML 模型**做验证任务——既保持应用性能，又在某些 failure mode 上**比单用 LLM 可靠性更高**。

> **架构师视角**：Andrew 收尾点出的商业逻辑值得记住——很多公司因为担心 LLM 系统的安全与可靠性而**放缓投资**，护栏是解锁投资的钥匙，不只是技术合规件。Shreya 的履历也暗合这门课的方法论：自动驾驶的安全思路（不信任概率模型、用确定性验证兜底）平移到了 LLM 应用——"explicitly verify, don't blindly trust"。

## 核心概念/类比

| 概念 | 类比 | 一句话 |
|---|---|---|
| Guardrail | 高速公路护栏 | 不改变车（模型）怎么开，只保证冲不出预定义边界 |
| Validator | 质检工位上的一条检查规则 | 函数：输入 prompt/响应 → 检查是否符合一条预定义规则 |
| 简单 validator | 用尺子量 | regex 查电话/邮箱等 PII，命中即抛异常 |
| ML validator | 请专家目检 | 小模型/二次 LLM 做主题、竞品词、复杂语义分析 |
| 幻觉 validator | 对账 | NLI 模型验证 RAG 回答是否被检索原文支持（grounded） |
| Guardrails Hub | 现成的质检规则库 | 大量 pre-built guardrails 可直接取用再改造 |

## 课程路线

| 阶段 | 一句话预告 |
|---|---|
| L1 | 实地看一个 RAG 披萨店客服 chatbot 的基础 failure modes（幻觉、偏离用途、信息泄漏……） |
| L2 | AI validation 是什么、为什么护栏有效——它是护栏起效的核心 |
| L3 起 | 按 GuardrailsAI 公司内部的 coding pattern，从零实现一个个针对具体 failure mode 的 guardrail |
| 后段 | 用 NLI 模型构建幻觉 validator（验证 RAG 回答 grounded）；学会取用 Guardrails Hub 上的 pre-built guardrails |
| 完课后 | 能改造这套 pattern，为自己的产品/用例定制专属 guardrails |

> **对比 agent/skills/agent-selection/7-safety-guardrails.md**：选型文件里 Guardrails AI 只是候选表的一行——"Pydantic 风格 validator 组合，偏输出校验，失败可 reask/fix，validator 质量参差"。这门课的**增量**是打开这一行的黑盒：validator 的编写模式（函数签名、规则从 regex 到 NLI 的梯度）、"小模型比 LLM 更可靠"的工程依据，以及 Hub 生态怎么用。选型文件回答"选不选它"，本课回答"选了之后怎么写"——两者拼起来才是完整决策链。

> **记忆点（引出 L1）**：护栏的一切设计都始于"要防什么"。L1 不讲任何护栏，而是先把一个搭好的 RAG 披萨店 chatbot **打坏给你看**——幻觉、被挪作他用、PII 泄漏、提竞品，四种 failure mode 逐一复现，护栏的需求清单由此而来。

# L0 · 课程介绍：红队 LLM 应用（Red Teaming LLM Applications）

> 课程：Red Teaming LLM Applications（DeepLearning.AI × Giskard）
> 讲师：Matteo Dora（Giskard，Lead LLM Safety Researcher）、Luca Martial（Giskard，Product Lead）；主持人 Andrew Ng。
> 一句话定位：**站在攻击者视角，在上线前主动攻击自己的 LLM 应用，把漏洞找出来并修掉。**

## 这门课解决什么问题

越来越多 LLM 被放进真实产品（聊天机器人、问答系统），但很多在部署前**没有被严格检验风险与表现**就交给了成百上千万用户。媒体上那些"翻车"报道就是后果——LLM 说了不该说的话，比如：

- 被诱导**答应 1 美元卖一辆车**；
- **泄露有价值的知识产权**，比如把自己的 system prompt 吐出来。

这些误触发（misfire）会给业务带来真实损失。这门课教你用**红队（Red Teaming）**手段在事故发生前把它们挖出来。

## 什么是 Red Teaming

Red Teaming 源自**网络安全与军事演习**：一支被称为 **Red Team（红队）**的队伍扮演对手（adversary），主动攻击一个系统，目的是**发现并修复漏洞**。它和渗透测试（Penetration Testing / Pen Testing）都是安全领域被广泛接受的成熟实践。

```
        军事/网络安全演习              →            LLM 应用
   ┌──────────┐   ┌──────────┐            ┌──────────┐   ┌──────────┐
   │ Red Team │攻→│ Blue Team│            │ Red Team │攻→│ LLM App  │
   │ (对手)   │   │ (防守)   │            │ (你/攻方)│   │ (防守方) │
   └──────────┘   └──────────┘            └──────────┘   └──────────┘
   模拟对抗、暴露弱点                      探测并暴露 LLM 应用的漏洞
```

把红队能力用在 AI 上，就能减少 AI 系统的漏洞。课程反复强调：这些技能必须**符合伦理、负责任地**使用——用来攻击**你自己的**应用、在进生产前发现并修复漏洞。

## 为什么现在学

生成式 AI **刚刚被列入网络安全从业者要应对的主要威胁类别**。它的特殊之处在于：底层技术来自一个全新领域，从 ML 工程师到安全架构师，**每一个参与开发和部署的人**都在与全新且复杂的风险概念搏斗。Giskard 观察到各类组织对红队 LLM 应用的兴趣正在爆发。正因为这个领域又新又重要，**现在是学这套技术的绝佳时机**——它处在 LLM 应用安全与安全性的最前沿。

> **架构师视角**：红队是**攻方视角**的质量保证。它和我资产里 `7-safety-guardrails.md` 的护栏是同一枚硬币的两面——护栏是**守方**（运行时同步拦截，把不该发生的挡在发生之前），红队是**攻方**（上线前主动把防线打穿，暴露护栏的盲区）。二者必须配对：只做护栏不做红队，你不知道护栏漏在哪；只做红队不做护栏，你有发现却没有拦截。这门课补的正是攻方这一课，与 GuardrailsAI（守方）课互为镜像。

> **对比 benchmark（下一课展开）**：大众印象里"评估 LLM"= 跑 MMLU / ARC / HellaSwag 这类基准。但基准测的是**知识和常识**，不是**安全（safety）与安全性（security）**；而且它评的是**基础模型**，不是**你部署的那个应用**。红队补的正是这两个缺口，这是 L1 的主线。

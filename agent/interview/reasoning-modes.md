# Agent 思考模式:CoT / ToT / ReAct / Plan-and-Execute / Reflection / MCTS / LATS

面试常被问"Agent 有哪些推理范式、各自取舍"。一条主线串起来:**从「线性想」到「树状搜索」,从「只在脑子里」到「真去动手」,从「一次成」到「复盘重试」**。

## 模式总览

| 模式 | 核心 | 与环境交互 | 能否回溯 | 短板 |
|---|---|---|---|---|
| CoT(思维链) | 线性一条路想到底 | 否 | 否 | 错了没法回头,无搜索 |
| ToT(思维树) | 展开多分支再选 | 否 | 是(在"想"的层面) | 只推演不动手 |
| ReAct | 想一步→做一步(调工具/观察) | 是 | 否(贪心单线) | 一条道走到黑,难纠偏 |
| Plan-and-Execute | 先规划完整步骤,再逐步执行(可 replan) | 是 | 有限(靠 replan) | 初始计划易脱离实际,长链误差累积 |
| Reflection / Reflexion | 执行→自我批判→带教训重试 | 是(Reflexion 用环境反馈) | 是(线性重试) | 自评不准就原地打转,多轮加延迟成本 |
| MCTS(搜索算法,LATS 内核) | 树上选择/扩展/模拟/回传找最优路径 | 取决于实现 | 是(统计回溯) | 需可模拟可评估,调用量大 |
| **LATS** | **树搜索 + 真实行动 + 反思** | 是 | 是 | 慢、贵(大量 LLM 调用) |

记忆锚点:**LATS = ReAct(会动手)+ ToT(会分叉)+ MCTS(会回溯打分)+ Reflection(会复盘)**,用算力换成功率。

主线排序(由简到繁):CoT 线性 → ToT 脑内分叉 → ReAct 动手单线 → Plan-and-Execute 先谋后动 → Reflection 复盘重试 → MCTS 统计搜索 → LATS 集大成。

---

## Plan-and-Execute(先谋后动)

**核心**:把"边想边做"换成两段式——**Planner** 先一次性产出完整步骤计划,**Executor** 再按计划逐步执行;执行中发现偏差可触发 **replan**(重新规划剩余步骤)。

**解决什么问题**:ReAct 每步都让大模型现想下一步,**长任务里容易走偏、也贵**(每步全量推理)。Plan-and-Execute 把"规划"和"执行"解耦——规划用强模型想一次,执行可用便宜模型/工具批量推进,**全局更连贯、单步更省**。

**取舍(面试点)**:
- 优点:适合**步骤明确、可提前拆解**的多步任务(订机票、跑数据流程);全局视野强,减少"走一步看一步"的漂移。
- 短板:**初始计划可能脱离现实**(环境和预想不符),所以 replan 是关键;计划过死则不灵活,replan 过频则退化回 ReAct。
- 对比 ReAct:ReAct 是**隐式、增量**规划;Plan-and-Execute 是**显式、前置**规划。

---

## Reflection / Reflexion(复盘重试)

**核心**:在执行之外加一个**自我批判**回路——产出结果后,让 LLM(或一个独立 critic)评判哪里不对、为什么,把这条"教训"写进上下文,然后**带着教训重试**。Reflexion 论文进一步用**环境反馈(成败信号)**驱动反思,把语言化的反思当作一种"记忆"累积。

**解决什么问题**:一次生成往往不够好;Reflection 用"生成→批判→再生成"的闭环逼近正确答案,**不改模型权重就提升成功率**(等于把试错搬到推理时)。

**取舍(面试点)**:
- 优点:实现简单、即插即用;在代码(跑测试拿报错再改)、写作润色、数学校验上提升明显。
- 短板:**强依赖评判质量**——自评不准就会"自我说服"原地打转;每轮重试**叠加延迟和成本**;要设**最大重试轮数**兜底。
- 关键前提:批判信号越**客观可验证**越好(单测、编译报错、规则校验 > 纯 LLM 自评)。
- 与 LATS 的关系:LATS 把 Reflection 当作其中一个组件——失败节点的反思会作为上下文喂回树搜索(见下文 LATS 小节)。

---

## MCTS(蒙特卡洛树搜索 —— LATS 的内核)

**核心**:这不是 LLM 原生的"思考模式",而是一种**搜索算法**。把决策过程建成树,反复跑四步:**Selection(用 UCT 挑最有希望节点)→ Expansion(展开子节点)→ Simulation/Evaluation(模拟/评估该路径)→ Backpropagation(把得分回传更新祖先)**,用统计采样在巨大空间里逼近最优路径,核心是**平衡探索(explore)与利用(exploit)**。

**为什么放进这张表**:LATS 就是"**MCTS + LLM**"——用 LLM 充当其中的动作生成器(Expansion)和价值函数(Evaluation)。理解 MCTS 才能理解 LATS;面试问 LATS 几乎必然连着问 MCTS。

**取舍**:能系统性回溯、找全局更优解;但**调用量随树宽×深爆炸**,且必须有**可模拟或可评估**的环境/信号,否则搜索是在放大噪声。

---

## LATS(Language Agent Tree Search)

2023 年论文提出,把**蒙特卡洛树搜索(MCTS)搬到 LLM Agent** 上,是目前把「推理 + 行动 + 规划」结合得最完整的一种范式。

### 解决什么问题

- CoT/ToT 只在脑子里推演,不与环境交互;
- ReAct 能动手但走单线、容易一条道走到黑、错了难纠偏。

LATS 把两者合一:既能像 ToT 那样**展开多条候选路径搜索**,又能像 ReAct 那样**每步真去执行、看环境反馈**,还加**反思**把失败经验喂回搜索。

### 怎么运转(MCTS 四步循环)

把每个「状态」当成树节点,反复跑:

1. **Selection 选择** — 用 UCT 之类的打分从根往下挑最有希望的节点(平衡「利用已知好路径」与「探索新路径」)。
2. **Expansion 扩展** — 让 LLM 在该节点采样出多个候选动作,生成子节点。
3. **Evaluation / Simulation 评估** — 执行动作拿到环境观察,再用 LLM 当「价值函数」给这条路打分(成功希望多大)。
4. **Backpropagation 回传** — 把得分沿树回传更新祖先节点价值,影响下一轮选择。

外加 **Reflection**:失败时让 LLM 总结「为什么错」,把教训作为上下文注入后续节点,让搜索越走越准。

### 取舍(面试追问点)

- **优点**:在需要试错、可回溯、有明确成败信号的任务上(代码生成 + 跑测试、网页操作、数学解题、工具密集任务),成功率明显高于 ReAct/ToT——能「走错了退回来换条路」。
- **代价**:**LLM 调用量爆炸**,一次任务几十上百次调用,延迟高、成本高 → 不适合实时/低延迟场景。
- **前提**:必须有**靠谱的评估信号**(单测通过、环境 reward、可验证的中间状态)。评估器不准,树搜索就是在放大噪声。
- **何时选**:任务复杂、容错低、可离线慢慢算、且每步结果可验证 → LATS;简单/实时/线性任务 → ReAct 甚至 CoT 就够,别上 LATS。

## 速记卡

- 问"ReAct 的局限" → 贪心单线、不可回溯;引出 ToT(会分叉)和 LATS(分叉+回溯+动手)。
- 问"ReAct vs Plan-and-Execute" → ReAct 隐式增量规划(边走边想),Plan-and-Execute 显式前置规划(先谋后动 + replan);长任务后者更连贯更省。
- 问"Reflection 怎么提升效果" → 生成→批判→带教训重试的推理时试错;成败看批判信号是否客观可验证,要设最大重试轮数。
- 问"MCTS 四步" → Selection / Expansion / Simulation / Backpropagation,UCT 平衡探索与利用。
- 问"LATS 是什么" → MCTS + LLM:LLM 当动作生成器和价值函数,= ReAct + ToT + MCTS + Reflection。
- 问"LATS 为什么贵" → MCTS 每轮 Selection/Expansion/Evaluation 都要调 LLM,调用量随树宽×深爆炸。
- 问"LATS / MCTS 落地前提" → 必须有可验证的评估信号(测试/reward),否则价值函数不可信。
- 选型一句话:**简单线性 → CoT;要动手 → ReAct;步骤可预拆 → Plan-and-Execute;结果可验证想自纠 → Reflection;容错低、可离线、可验证的硬任务 → LATS,用算力换成功率**。

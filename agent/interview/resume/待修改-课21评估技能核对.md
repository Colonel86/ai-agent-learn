## 一、建议补充（课程覆盖、简历缺失）

### 1. 人工反馈 / 标注回流（缺失度最高）

- **现状**：技能行只有「规则评估 + 模型评分」两条腿；课程 L6 明确评估器是**三类**——Code-based / LLM-as-a-Judge / **Human Annotation**（标注队列 + 用户 👍/👎 反馈）。L13 进一步强调「评估指标与真实用户反馈不一致」是关键报警信号。
- **风险**：面试官问「LLM Judge 不准怎么办」「生产反馈怎么进评估」时，简历没有钩子。
- **建议改法**（技能行第 20 行追加）：
  - `人工标注与用户反馈回流（annotation queue / 👍👎 反馈 → 数据集扩充）`

### 2. 评审器元评估（evaluate your evaluators）

- **现状**：简历写了 LLM-as-a-Judge，但没写**Judge 本身也被校准过**。课程 L12 整节讲：用同一套 Experiment 机制测 Judge 与 ground truth 的对齐度，靠改 Judge Prompt / 加 few-shot 提升。
- **价值**：这是资深与初级用 LLM-as-a-Judge 的分水岭，一句话就能体现。
- **建议改法**（二选一）：
  - 技能行：`LLM-as-a-Judge（含评审器对齐度校准 / meta-eval）`
  - 或宜信第 32 行末尾加：`；LLM Judge 先在人工标注对齐集上校准（few-shot 调优对齐度）再投产`

### 3. 生产在线评估与监控（简历只写了「离线评测」）

- **现状**：技能行和链图段都只出现「离线评测」；课程 L13 核心是**同一套评估资产延伸到生产**——线上 Trace 持续评估、成本/延迟/收敛度监控、新失败模式回流数据集的自我改进飞轮。
- **建议改法**（技能行）：
  - `离线评测` → `离线评测 + 生产在线评估（线上 trace 采样评估、成本/延迟/收敛度监控、失败案例回流数据集）`

### 4. Golden Dataset 作为发布门禁

- **现状**：简历写「CI 评测门禁」，但没点出门禁跑的是什么。课程 L13 的术语是 **Golden Dataset**（关键用例 + 已知失败模式固化）+ Experiment 作为发布 Gate，分数不达标即 roll back。
- **建议改法**：`CI 评测门禁（规则评估 + 模型评分）` → `CI 评测门禁（Golden Dataset 回归 + 规则评估 + 模型评分，不达标阻断发布）`
- 注：若嫌长，至少把 Golden Dataset 一词放进去——是行业通用信号词。

### 5. Router 评估的两个维度可更精确（宜信第 32 行，小改）

- **现状**：「工具选择 / 参数抽取用 LLM-as-a-Judge 评估」。课程 L6/L10 的标准做法是**两条腿**：有 ground truth 时用 Code-based 精确比对（100% 准），无 ground truth 的生产流量用 LLM-as-a-Judge 横扫。简历现在只写了 Judge 一条腿，反而显得没做过 code-based 比对。
- **建议改法**：`工具选择 / 参数抽取用 ground truth 精确比对 + LLM-as-a-Judge 双轨评估`

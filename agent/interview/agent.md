这四个是多 Agent 系统的**拓扑结构**——本质区别在于一个问题:**控制权(谁来决定下一步干活的是谁)是怎么流转的。** 从"高度集中"到"完全去中心化"排成一条谱系来理解最清楚。

## 先给一句话区分

| 模式 | 控制权 | 一句话 |
|---|---|---|
| **Supervisor** | 集中在协调者 | 所有专家都听一个老板调度,干完回老板那 |
| **Hierarchical** | 多层集中 | 老板下面还有小老板,Supervisor 的递归版 |
| **Network** | 完全分散 | 任意 agent 都能直接调任意 agent |
| **Swarm** | 接力传递 | 谁接手谁就一直干,直到主动交棒给别人 |

## 逐个拆

**1. Supervisor(协调者 / 星形)**

一个中央 supervisor 节点连着 N 个专家 agent,呈**星形**。流程永远是:supervisor 决定派给谁 → 专家干活 → **结果回到 supervisor** → supervisor 再决定下一步派给谁,或者结束。

专家之间**不直接通信**,全靠中间这个老板转发。

- 优点:控制流清晰、可控、好调试好审计(所有决策都过 supervisor 一个点)。
- 缺点:supervisor 是瓶颈也是单点;每次流转多绕一跳。
- 适合:任务能清晰拆成"分诊→分发"的场景(客服路由、研究任务分派)。

```
        ┌─────────────┐
   ┌────┤ Supervisor  ├────┐
   ↓    └──────┬──────┘    ↓
 专家A         专家B       专家C
   └─────回到 supervisor────┘
```

**2. Hierarchical(层级)**

就是 **Supervisor 的递归套娃**。当专家太多、一个 supervisor 管不过来,就分组,每组配一个 sub-supervisor,上面再有个 top-supervisor 管这些 sub-supervisor。形成树状多层。

- 和 Supervisor 的关系:Supervisor 是单层,Hierarchical 是多层。
- 适合:大型系统,团队/部门式划分(比如"研究团队 supervisor" + "写作团队 supervisor",上面一个总协调)。
- 这也是 `Command(graph=Command.PARENT)` 的用武之地——子图里的 agent 要把控制权交回父图。

```
            Top-Supervisor
            ┌──────┴──────┐
       Sub-Sup-1      Sub-Sup-2
        ┌──┴──┐        ┌──┴──┐
        A     B        C     D
```

**3. Network(网状 / 全连接)**

**没有中央协调者**,每个 agent 都可以直接决定把控制权交给**任意**其他 agent。呈多对多的全连接网。

- 优点:最灵活,适合那种"下一步该谁干没有固定顺序、要 agent 自己临场判断"的问题。
- 缺点:难预测、难调试、容易绕圈或上下文衰减;agent 多了连接数爆炸(N×N)。
- 适合:问题结构不规则、协作路径无法预先设计的开放场景。

```
   A ←───→ B
   ↑ ╲   ╱ ↑
   │   ╳   │
   ↓ ╱   ╲ ↓
   C ←───→ D     (任意两两可互相 handoff)
```

**4. Swarm(蜂群 / 接力)**

关键区别在"**控制权交接的持续性**"。Network 里 A 调 B,B 干完通常**还回到某种调度逻辑**;Swarm 里更像**接力棒**——A 把控制权 handoff 给 B 之后,**B 就成为当前活跃 agent 一直接着干**,直到 B 觉得该换人,再把棒交给 C。系统**记住当前是谁在掌控**,用户的后续输入直接进到当前活跃 agent。

- 和 Network 的细微差别:Network 强调"谁能调谁"(连接拓扑),Swarm 强调"控制权像接力棒一样转移并停留"(谁是当前 active agent)。LangGraph 专门有个 `langgraph-swarm` 库实现这个模式。
- 适合:专长明确、按需在专家间转手的对话(比如订机票 agent 处理着,涉及退款就把整个对话交给退款 agent 接管)。

```
  用户 → [Agent A 掌控] ──handoff──→ [Agent B 掌控] ──handoff──→ [Agent C 掌控]
              ↑ 后续输入直接进当前掌控者
```

## 面试怎么讲(把谱系串起来)

> "这四个的本质区别是控制权怎么流转,可以排成集中到分散的谱系:**Supervisor** 是中央老板星形调度,所有结果回到老板;**Hierarchical** 是它的多层递归版,适合大规模分组;**Network** 去掉中央协调者,任意 agent 互相 handoff,最灵活但最难控;**Swarm** 介于其间,控制权像接力棒一样转移并**停留**在当前 active agent。选型上我默认从 Supervisor 起步——可控、好审计,只有当中央协调真的成为瓶颈、或协作路径无法预先设计时,才往 Network/Swarm 这种去中心化方向走。"

最后那句"默认从最可控的起步、复杂度要证明它值得",正好呼应你之前那条反馈——**有取舍判断**,而不是罗列名词。

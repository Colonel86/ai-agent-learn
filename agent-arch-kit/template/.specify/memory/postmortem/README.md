# Postmortem · 事故复盘

postmortem 是回写闭环（constitution §4）的**执行载体**：生产事故是最高价值的知识来源，
本目录把"出事"变成体系升级的输入——每份复盘必须产出矩阵回写条目、门禁检讨、或两者。

## 规则

- **无责文化（blameless）**：复盘对象是系统与流程，不是人。根因写"缺少 X 机制"，
  不写"某人失误"——写人名的复盘会让下次没人说真话
- **何时必写**：T2 系统的线上事故（可用性/正确性/安全/成本超支）必写；
  T1 的重复性问题（同类第 2 次出现）必写；评测门禁被绕过后出的问题必写
- **时限**：事故关闭后 3 个工作日内出稿——拖过一周细节就没了
- **核心追问**（本模板区别于通用 postmortem 的地方）：
  **"哪个门禁本应拦住它？为什么没拦住？"**——这个字段持续检验七门禁本身的有效性，
  答案只有三种：门禁缺失（→ W3 提议）/ 门禁存在但被 N/A 跳过（→ 检讨 tier 判定）/
  门禁通过了但没测到（→ golden set 回流 + 门禁强化）
- 命名：`PM-YYYYMMDD-<kebab-title>.md`，从 `_TEMPLATE.md` 复制起步
- 行动项必须有 owner 和检查日期；没有行动项的复盘等于没开

# Constitution · AI Agent 项目宪法（agent-arch-kit 合并点）

> 本文件是项目**始终生效**的治理核心，由 agent-arch-kit 投影生成。
> 它合并了四个资产的"常驻部分"：选型红线（来自选型矩阵）、NFR 门禁摘要（来自 nfr-standard）、
> ADR 升格规则（来自 adr-writer 规范）、回写义务（闭环收口）。
> 细节知识不常驻——选型矩阵全文、NFR playbooks、ADR 模板都按需加载（见各节指针）。
>
> **AI 执行者注意**：`/speckit.plan` 的 Constitution Check 必须逐节核对本文件；
> 任何与本文件冲突的产出视为未通过计划评审。

---

## §1 核心原则（不可妥协）

1. **闭环原则**：知识指导决策、决策变成约束、约束驱动执行、执行结果反哺知识。
   任何环节的产出必须被下一环节消费——写了没人读的文档等于没写。
2. **证据原则**：架构结论必须可追溯到证据（实测数据 / 矩阵条目 / ADR 编号 / 评测结果），
   "我觉得"不构成架构理由。
3. **显式取舍原则**：可以跳过标准动作，但必须显式留痕（N/A + 理由）；隐式跳过视为违规。
4. **确定性安全原则**：安全边界必须是确定性机制（权限 / 沙箱 / HITL / 凭证 scope），
   prompt 里写"请不要"不算安全措施。

## §2 选型治理（来自分层选型矩阵）

### 2.1 选型红线（一票否决，违反即计划不通过）

- **R1 数据不出域**：涉及敏感数据 / 合规约束的场景，禁止选用数据出域的 SaaS
  （观测、评测、记忆服务均含在内）；必须选可自托管方案。
- **R2 简单场景禁引框架**：单轮工具调用 / 简单流水线，禁止引入编排框架——
  裸 SDK + function calling 即可。引框架必须能回答"框架解决了裸 SDK 的什么问题"。
- **R3 编排默认 LangGraph**：需要编排时默认 LangGraph；偏离（CrewAI / harness 类 / 自研）
  属于 ADR 升格事项（见 §2.3）。
- **R4 密钥零硬编码**：任何凭证不进代码与 prompt；统一走密钥管理 + 短时效 token。
- **R5 高危操作必须 HITL**：写操作 / 资金类 / 不可逆操作，必须有确定性的
  Human-in-the-Loop 闸门，不得仅靠模型判断。
- **R6 埋点选标准**：可观测埋点跟 OTel（GenAI 语义约定）走，禁止绑定私有 SDK 独占格式。

### 2.2 矩阵咨询义务

`/speckit.plan` 的「技术选型」小节，**每个选型决策必须逐层对照选型矩阵**
（模型 / 框架 / 检索 / 工具 / 观测·评估 / 记忆 六层），逐项标注：

- **一致**：引用矩阵条目即可，不必复述理由；
- **偏离**：必须写明偏离理由；命中 §2.3 条件的升格为 ADR。

矩阵入口（按需加载，不常驻）：`.claude/skills/selection-matrix/`（见 `memory/selection/README.md`）。

### 2.3 ADR 升格规则（何时必须落 ADR）

满足**任一**条件的决策，必须产出 `memory/adr/ADR-NNN-*.md`（模板见 `memory/adr/_TEMPLATE.md`，
编号规则见 `memory/adr/README.md`）：

- **A1** 影响 ≥ 2 个模块，或替换成本预估 > 1 人周；
- **A2** 偏离选型矩阵的默认结论（含 §2.1 红线的豁免申请）；
- **A3** 引入新的重大外部依赖（新框架 / 新存储 / 新 SaaS / 新协议）；
- **A4** 决策在团队内有实质分歧，需要留下"为什么不选 X"。

不满足以上条件的 feature 级小选型，写进 `plan.md`「技术选型」小节即可，**不要**升格为 ADR
（防 ADR 通胀）。

## §3 NFR 门禁（摘要；本体见 nfr-standard）

七门禁按 tier 适用。**source of truth 是 `memory/nfr/` 下的 playbooks（由 nfr-standard 安装）**，
本节仅为常驻摘要：

| 门禁 | 关注点 | 一句话 |
| --- | --- | --- |
| G1 | 性能与扩展 | 延迟 SLO（TTFT, p99）+ 吞吐定了吗 |
| G2 | 可用性与韧性 | fallback / 重试熔断 / 断点恢复 / 幂等有吗 |
| G3 | 可观测 | tracing + 成本指标 + 在线质量评估 + SLO 告警配了吗 |
| G4 | 安全 | 注入防御 / 工具权限边界 / 密钥 / 数据出域管了吗 |
| G5 | 成本 | 单请求 token 预算 / 缓存 / 模型路由定了吗 |
| G6 | 评估质量 | golden set + CI 回归门禁有吗（禁止前视偏差） |
| G7 | 可维护 | 新能力配置驱动吗，prompt/工具/模型有版本吗 |

| Tier | 适用范围 | 必过门禁 |
| --- | --- | --- |
| T0 原型 | 一次性、不面向用户 | G4（密钥；接不可信输入则含注入） |
| T1 内部 | 内部用户、爆炸半径有限 | G3 G4 G6 G7（G1/G2/G5 建议） |
| T2 生产 | 面向用户或业务关键 | G1–G7 全部 |

## §4 回写义务（闭环收口，最易腐化的一环）

- **W1 项目收尾 retrospective**：每个 feature / 项目收尾时，将实施中的踩坑结论与评测数据
  **按层回写选型矩阵**（矩阵条目注明来源项目与日期）；无可回写内容需显式记"无新增结论"。
- **W2 ADR 复审**：收尾时逐条检查存量 ADR 的 Revisit Triggers 是否被触发；
  触发的 ADR 标记"待复审"并开任务。
- **W3 门禁进化**：同一类 NFR 问题在 ≥ 2 个项目中出现，应提议升级 nfr-standard
  的对应 playbook（走其仓库的 PR 流程）。

## §5 治理

- 本文件的修改走 PR 评审，理由写进 commit message；红线（§2.1）的增删属于 ADR 升格事项。
- 版本随 agent-arch-kit 的 VERSION 演进；目标仓可在 `<!-- local-additions -->` 标记后追加
  项目私有条款，install 更新时不覆盖。
